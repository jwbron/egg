Background for the implementing agent: issue #2970 tracks that sandboxed agents could not read Confluence — every /api/v1/confluence/* call failed (first upstream 302, then 401) because the gateway targeted the khanacademy.atlassian.net tenant host, which rejects Basic auth. A config workaround set CONFLUENCE_BASE_URL=https://api.atlassian.com/ex/confluence/<cloudId> and populated the space allowlist (ENG, INFRA, BACKEND, FRONTEND, WFG, SI, SEC). That workaround is confirmed present in the live gateway secrets, and direct curl with the same creds returns 200 from api.atlassian.com. The ONLY thing not yet proven is an authenticated read THROUGH the gateway route from inside a sandboxed agent (needs EGG_SESSION_TOKEN, which only exists in an agent run). This probe supplies that proof. Expected success: space_list and search return HTTP 200; expected failure to watch for: 401 (auth) or 403 (empty/wrong allowlist).
