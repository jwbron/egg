# Plan: Role-scope-aware task assignment in plan generation

## Summary

Add a `role` field to the yaml-tasks schema and contract Task model so that plan generation can assign tasks to the correct execution agent (coder, tester, documenter). Inject role file restriction information into the task_planner prompt so it makes correct assignments. Filter tasks by role when building implement-phase agent prompts so each agent only works on files within its boundary.

**Risks / edge cases**: The `role` field must be optional — existing plans without role assignments must parse correctly and default to showing all tasks to all agents (preserving current behavior). Cross-role tasks should be split into separate tasks per role by the planner rather than multi-assigned.

## Implementation

### Phase 1: Implement

Add role-aware task assignment across schema, model, parser, and prompt layers.

**Tasks**:
1. **[task-1-1]** In `.egg/schemas/yaml-tasks.schema.json`, add optional `role` enum property to the task `$defs`. Acceptance: Schema validates tasks with and without `role` field; invalid role values are rejected.
2. **[task-1-2]** In `shared/egg_contracts/models.py:Task`, add `role: str | None = Field(default=None)`. Acceptance: Existing contracts without `role` field deserialize correctly; new contracts with `role` round-trip through serialization.
3. **[task-1-3]** In `shared/egg_contracts/plan_parser.py`, add `role` to `ParsedTask` dataclass and propagate in `to_contract_task()` and `parse_phases_from_yaml()`. Acceptance: Parsing yaml-tasks with `role: tester` produces `Task` with `role="tester"`; omitting `role` produces `role=None`.
4. **[task-1-4]** In `orchestrator/routes/pipelines.py`, create `_build_role_restrictions_section()` that formats coder/tester/documenter file boundaries using `get_file_patterns()`, and append its output to the task_planner prompt after the yaml-tasks example block. Acceptance: task_planner prompt includes file restriction info for all three execution roles.
5. **[task-1-5]** In `orchestrator/routes/pipelines.py:_build_role_context()`, filter `phase_obj.tasks` by `task.role` matching `role_value` for implement phase — unassigned tasks (`role=None`) default to coder. Acceptance: Tester sees only tester tasks; documenter sees only documenter tasks; coder sees coder + unassigned tasks.
