# Plan: Improve overseer escalation/issue opening behavior (advisor-strategy framing)

> Issue: #1962 | Phase: plan | Branch: `egg/issue-1962`

## Approach

This pipeline lands **all three threads of #1962 in a single PR** per
`decision-1` (Option A — single pipeline, all threads) and
`decision-22` (Option A — one PR for everything):

1. **Escalation tuning** — calibrate the deployed agent-side overseer
   so its `OVERSEER_ALERT` triggers cover the false-positive classes
   the human flagged in `feedback-1.Q1` (mainly `agent-heartbeat-stall`
   during legitimate file-reading work, `stuck-phase-transition` reading
   stale contract state). The Tier-1 intersection gate from
   `decision-18` is the load-bearing change: heavy-tier (advisor)
   reasoning is only invoked when Haiku flags an anomaly **AND** an
   orchestrator-side health alert has tripped — same precedent shipped
   in #2012.
2. **Auto-issue filing (advisor-gated)** — wire a new agent-side
   `egg-orch overseer file-issue` CLI verb (`decision-9` opt-1) that
   composes a GitHub issue using the dead-code template at
   `orchestrator/overseer/issue_filer.py:86-107` extended with explicit
   pipeline links (`decision-8` opt-2). The advisor (Opus 4.6, called
   by Haiku on Tier-1 intersection) returns
   `recommendation=file_issue` inside an `OVERSEER_ALERT`; the human
   gates the actual filing through the existing
   `pending_decisions` HITL flow (`decision-21` opt-2 + `decision-10`
   opt-1, shadow-mode rollout). Dedup uses a per-repo
   `gh issue list --label agent:overseer --state open` query plus a
   local `.egg-state/oversight/filed-issues.json` cache (`decision-6`
   opt-2, `decision-15` opt-1).
3. **Host → overseer migration** — move stall / silent-agent / NACK /
   long-running-phase / stuck-pipeline-rescue detection out of
   `skills/sdlc/SKILL.md:489-639` into the overseer. The
   `{role: {phase, phase_entered_at, …}}` in-memory state map
   (`SKILL.md:568-570`) becomes
   `.egg-state/oversight/agent-timing.json` (`decision-16` opt-3);
   `OVERSEER_PATTERNS` already permits this prefix so no
   file-boundary work is needed (`decision-15`). Thresholds become
   per-pipeline configurable via `PipelineConfig` (`decision-12`
   opt-2) defaulting to current values, with the one human-flagged
   tweak: `stuck-phase-transition` default goes from ~60 s to ~180 s
   (`feedback-1.Q2`). `/sdlc` keeps surfacing alerts (passive
   dashboard), HITL handling, and the Phase-5 final-handoff rescue —
   the `AskUserQuestion` side-flows ("Check agent logs" / "Nudge
   agent" / "Restart pipeline") become overseer-initiated and arrive
   wrapped in `OVERSEER_ALERT.detail` per `feedback-1.Q5`.

### Single-PR shape & phasing

One PR; phases organise commits **inside** that PR. Within each phase
the tasks are mostly parallel-safe across role boundaries (coder /
tester / documenter), with a few inter-phase serial dependencies
called out in *Dependencies*.

### Test strategy

- **Automated** — orchestrator tests for the revived `issue_filer`
  template + dedup; gateway tests for the new `gh issue create`
  allow-rule, label-injection and size-limit enforcement; sandbox
  tests for the new `egg-orch overseer file-issue` verb; advisor
  unit tests (mocked `run_agent_async`) for the executor → advisor
  handoff contract; integration test for the
  *anomaly → advisor recommendation → HITL → human-approves → file → dedup-on-next-cycle*
  path; `/sdlc` skill regression tests for the migrated detection
  logic so behavior parity is preserved.
- **Manual** — run a full `/sdlc` triage on a synthetic issue,
  inject an anomaly the advisor will flag, verify the
  `OVERSEER_ALERT` carries `recommendation=file_issue`, approve via
  the surfaced HITL decision, verify the issue lands with
  `agent:overseer` + priority labels, then re-trigger the same
  anomaly to confirm dedup skips the second filing. Plus: smoke-test
  the `/sdlc` migration by intentionally stalling a fake agent and
  verifying the overseer (not `/sdlc`) emits the stall alert.

### Manual pre-merge / post-merge steps

- **Pre-merge** — none. All gateway / file-boundary changes ship in
  this PR.
- **Post-merge** — bump the `claude-agent-sdk` version pin in a
  follow-up PR (out of scope here) if/when Anthropic ships the
  advisor tool in a release that fits inside `>=0.1.65,<0.2`. This
  unlocks Option A as a pure swap of the advisor invocation site.

### Dependencies between phases

- Phase 1 (foundation) gates everything else: config knobs and
  data-class definitions are pre-requisites for Phases 2 / 4 / 6.
- Phase 2 (gateway + CLI verb) and Phase 3 (issue template + dedup)
  can land in either order, but the integration test in Phase 7
  needs both.
- Phase 4 (advisor wiring) depends on Phase 1's config additions and
  Phase 3's `file_diagnostic_issue` template.
- Phase 5 (rule-doc rewrite) depends on Phases 1-4 settling so the
  rule doc can reference real config knob names + new
  CLI/MCP surface. Serialize against Phase 6 if both touch
  `overseer.md`; Phase 6 only edits `skills/sdlc/SKILL.md` so they
  do not collide in practice.
- Phase 6 (host migration) depends on Phase 1's
  `agent-timing.json` schema and Phase 5's documented overseer
  triggers.
- Phase 7 (tests + integration) and Phase 8 (docs) depend on every
  prior phase being functionally complete.

## Risks & mitigations (preview — full risk matrix lives in the risk_analyst's output)

- **Auto-issue noise** — advisor mis-recommends `file_issue`
  during legitimate slow work. *Mitigation*: Tier-1 intersection
  gate + shadow-mode rollout + HITL approval per `decision-10`
  opt-1 + per-repo dedup.
- **Cost regression** — advisor adds Opus calls. *Mitigation*: gate
  is `Haiku-flag ∧ Tier-1-alert`, an empirically rare intersection;
  no per-pipeline cap (per `feedback-1.Q3` resolution) but the
  existing `max_llm_cost_per_hour=$5` envelope still applies; a
  follow-up issue tracks dedicated advisor budgeting.
- **Host-migration regression** — moving `/sdlc` detection logic
  changes alert latency or surfacing fidelity. *Mitigation*: keep
  thresholds identical at first (`decision-12` opt-2 with current
  values as defaults), preserve the `OVERSEER_ALERT` payload
  schema, regression-test side-by-side using the existing
  `/sdlc` test fixtures.
- **SDK pin drift** — Anthropic ships the advisor tool inside the
  `>=0.1.65,<0.2` window mid-implementation. *Mitigation*: the
  plan ships Option B; Option A becomes a clean follow-up swap.
