# Plan: Improve overseer escalation/issue opening behavior (advisor-strategy framing)

> Issue: #1962 | Phase: plan | Branch: `egg/issue-1962`

## Approach

This pipeline lands **all three threads of #1962 in a single PR** per
`decision-1` (Option A — single pipeline, all threads) and
`decision-22` (Option A — one PR for everything):

1. **Escalation tuning** — calibrate the deployed agent-side overseer
   so its `OVERSEER_ALERT` triggers cover the false-positive classes
   the human flagged in `feedback-1.Q1` (mainly `agent-heartbeat-stall`
   during legitimate file-reading work, `stuck-phase-transition` reading
   stale contract state). The Tier-1 intersection gate from
   `decision-18` is the load-bearing change: heavy-tier (advisor)
   reasoning is only invoked when Haiku flags an anomaly **AND** an
   orchestrator-side health alert has tripped — same precedent shipped
   in #2012.
2. **Auto-issue filing (advisor-gated, agent-side)** — wire a new
   agent-side `egg-orch overseer file-issue` CLI verb (`decision-9`
   opt-1) that **runs `gh issue create` itself inside the sandbox**,
   mediated by the gateway. The body is composed entirely sandbox-side
   by the new `sandbox/egg_lib/overseer_issue_body.py` helper, which
   freezes the canonical template literal currently dead-coded in
   `orchestrator/overseer/issue_filer.py:86-107` (the orchestrator
   module is kept only as the *canonical literal source* and marked
   DEAD; no orchestrator-side endpoint invokes `gh`). The advisor
   (Opus 4.6, called by Haiku on Tier-1 intersection) returns
   `recommendation=file_issue` with a fully composed `issue_title` +
   `issue_body` inside an `OVERSEER_ALERT`; the human gates the actual
   filing through the existing `pending_decisions` HITL flow
   (`decision-21` opt-2 + `decision-10` opt-1, shadow-mode rollout).
   Dedup uses a per-repo `gh issue list --label agent:overseer
   --state open` query plus a local
   `.egg-state/oversight/filed-issues.jsonl` append-only cache
   (`decision-6` opt-2, `decision-15` opt-1).
3. **Host → overseer migration (with side-by-side calibration window)**
   — move stall / silent-agent / NACK / long-running-phase /
   stuck-pipeline-rescue detection out of `skills/sdlc/SKILL.md:489-639`
   into the overseer. The `{role: {phase, phase_entered_at, …}}`
   in-memory state map (`SKILL.md:568-570`) becomes
   `.egg-state/oversight/agent-timing.json` (`decision-16` opt-3);
   `OVERSEER_PATTERNS` already permits this prefix so no
   file-boundary work is needed (`decision-15`). Thresholds become
   per-pipeline configurable via `PipelineConfig` (`decision-12`
   opt-2) defaulting to current values, with the one human-flagged
   tweak: `stuck-phase-transition` default goes from ~60 s to 180 s
   (`feedback-1.Q2`). A new `overseer_owns_host_detection` feature
   flag (default **False**) gates the deletion in `/sdlc` so the
   host's detection logic stays available for side-by-side
   calibration with the overseer's new detectors during the first
   release; the cleanup-PR follow-up flips the default after
   validation (mitigates `R-COMPAT-03` / `HR-03` from risk_analyst).
   `/sdlc` keeps surfacing alerts (passive dashboard), HITL handling,
   and the Phase-5 final-handoff rescue — the `AskUserQuestion`
   side-flows ("Check agent logs" / "Nudge agent" / "Restart
   pipeline") become overseer-initiated and arrive wrapped in
   `OVERSEER_ALERT.detail` per `feedback-1.Q5`.

### Single-PR shape & phasing

One PR; phases organise commits **inside** that PR. Within each phase
the tasks are mostly parallel-safe across role boundaries (coder /
tester / documenter), with a few inter-phase serial dependencies
called out in *Dependencies*.

**Implementation order:** `Phase 1 → Phase 3 → Phase 2 → Phase 4 →
Phase 5 → Phase 6 → Phase 7 → Phase 8`. Phase 3 lands first because
Phase 2's CLI verb imports from `sandbox/egg_lib/overseer_issue_body.py`
(TASK-3-1) and the `OVERSEER_ALERT` schema extension (TASK-3-3) is
needed before Phase 4 can emit `recommendation=file_issue`. The YAML
phase IDs reflect *grouping*, not strictly sequential numbering;
implementer should follow the order above.

### Dedup persistence scope (cross-phase)

The `.egg-state/oversight/filed-issues.jsonl` cache is **intra-phase
only** — each phase spawns a fresh overseer container and the local
filesystem under `.egg-state/oversight/` is not preserved across phase
boundaries (per `sandbox/agent-config/rules/overseer.md:5`). For
cross-phase dedup the overseer relies on the **GitHub-side fallback**
in `find_existing_issue`: `gh issue list --label agent:overseer
--state open --search "{anomaly_signature[:8]}" --json number,title`
returns the prior phase's filed issue because the 8-char signature
prefix is embedded in the title. This satisfies `decision-6` opt-2's
"persist across respawns/new phases" intent through *content
addressability* rather than file persistence — the local JSONL acts
as a same-phase fast path; the title-embedded signature acts as the
source of truth across phase boundaries. The plan does **not** wire
orchestrator-side persistence of the JSONL across phase containers
(that would require a worktree-scoped state mount which is out of
scope here); a follow-up issue can revisit if `gh issue list`
latency proves problematic.

  shared-package tests for `shared/overseer/scrubbing.py`

  `OVERSEER_ALERT` callers (without the new `recommendation`
  field) still serialize/deserialize and render in `/sdlc`;
  `/sdlc` skill regression tests for the migrated detection
  logic so behavior parity is preserved while
  `overseer_owns_host_detection=False` (the default).
- **Manual** — run a full `/sdlc` triage on a synthetic issue,
  inject an anomaly the advisor will flag, verify the
  `OVERSEER_ALERT` carries `recommendation=file_issue`, approve via
  the surfaced HITL decision, verify the issue lands with
  `agent:overseer` + priority labels and the title contains the

  confirm dedup skips the second filing. Plus: smoke-test the
  `/sdlc` migration by intentionally stalling a fake agent under
  `overseer_owns_host_detection=True` and verifying the overseer

### Dependencies between phases

- **Phase 1 (foundation)** gates everything else: config knobs,
  data-class definitions, JSONL schema, the `compute_anomaly_signature`
  primitive, and the shared helpers (`shared/overseer/advisor.py`
  stub, `shared/overseer/scrubbing.py`,
  `shared/overseer/infra_error.py`) are pre-requisites
  for Phases 2 / 3 / 4 / 6.
- **Phase 3 (issue body template + dedup primitives)** precedes
  **Phase 2 (gateway + CLI verb)**: TASK-2-1's CLI body-construction
  call uses `compose_issue_body` from
  `sandbox/egg_lib/overseer_issue_body.py` (Phase 3) and the dedup
  read uses `find_existing_issue` (Phase 3). So implement Phase 3
  first, Phase 2 second; the integration test in Phase 7 needs both.
- **Phase 4 (advisor wiring)** depends on Phase 1's config additions
  + shared-package stubs and Phase 3's `OVERSEER_ALERT` schema
  extension (TASK-3-3): the advisor's `decision="file_issue"`
  outcome emits `OVERSEER_ALERT.recommendation=file_issue`, which
  requires the schema change to be in place first.
- **Phase 5 (rule-doc rewrite)** depends on Phases 1–4 settling so
  the rule doc can reference real config knob names + the new
  CLI/MCP surface. Serialize against Phase 6 if both touch
  `overseer.md`; Phase 6 only edits `skills/sdlc/SKILL.md` so they
  do not collide in practice.
- **Phase 6 (host migration)** depends on Phase 1's
  `agent-timing.json` schema and Phase 5's documented overseer
  triggers. Phase 6 lands the new detectors in the overseer AND
  gates the host-side deletions on `overseer_owns_host_detection`.
- **Phase 7 (tests + integration)** and **Phase 8 (docs)** depend on
  every prior phase being functionally complete.

## Risks & mitigations (preview — full risk matrix lives in the risk_analyst's output)

- **Auto-issue noise** — advisor mis-recommends `file_issue`
  during legitimate slow work. *Mitigation*: Tier-1 intersection
  gate + shadow-mode rollout + HITL approval per `decision-10`
  opt-1 + per-repo dedup keyed on `(anomaly_type, agent_role, repo)`.
- **Cost regression** — advisor adds Opus calls. *Mitigation*: gate
  is `Haiku-flag ∧ Tier-1-alert`, an empirically rare intersection;
  no per-pipeline cap (per `feedback-1.Q3` resolution) but the
  existing `max_llm_cost_per_hour=$5` envelope still applies; a
  follow-up issue tracks dedicated advisor budgeting.
- **Public-disclosure regression (R-SEC-01)** — issue body could
  carry container-log lines that leak `ghp_*` PATs / `AKIA*` AWS
  keys / Slack webhooks / `GITHUB_TOKEN=*` exports. *Mitigation*:
  TASK-3-2 (NEW) adds `shared/overseer/scrubbing.py`,
  the advisor must call `scrub_secrets(body)` before returning the
  verdict, and the gateway in TASK-2-3 does a defense-in-depth
  reject when secret patterns slip through.
- **Host-migration regression (R-COMPAT-03 / HR-03)** — moving
  `/sdlc` detection logic changes alert latency or surfacing
  fidelity. *Mitigation*: `overseer_owns_host_detection=False`
  default keeps the host's detectors live for a calibration window;
  thresholds stay identical at first (`decision-12` opt-2 with
  current values as defaults); preserve the `OVERSEER_ALERT`
  payload schema; backwards-compat regression test asserts old
  alerts still render in `/sdlc`.
- **SDK pin drift** — Anthropic ships the advisor tool inside the
  `>=0.1.65,<0.2` window mid-implementation. *Mitigation*: the
  plan ships Option B; Option A becomes a clean follow-up swap.
