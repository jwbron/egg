# Plan: Fix overseer alerts leaking to wrong pipeline (#1523)

## Summary

Fix all four CLI-calling methods in `OverseerMonitor` to explicitly pass `self.pipeline_id` as a positional argument and `--role overseer` where applicable, instead of relying on environment variables. This prevents alerts from leaking to the wrong pipeline and ensures correct `from_role` attribution. Also mock `_broadcast_alert` in test classes that currently let it call through to `_run_cli`.

**Risks / edge cases**: `_send_message()` is also missing the required `--type` flag, so it silently fails today. Adding it means messages will start being delivered — this is correct behavior. No existing production behavior changes negatively since messages are already being sent to the real pipeline via env vars; this just makes routing explicit.

## Implementation

### Phase 1: Implement

**Tasks**:
1. **[task-1-1]** In `orchestrator/overseer/monitor.py:_broadcast_alert()` (line 1286), add `self.pipeline_id` as positional arg and `"--role", "overseer"` to the `_run_cli` call. Acceptance: CLI receives explicit pipeline_id and role.
2. **[task-1-2]** In `orchestrator/overseer/monitor.py:_send_message()` (line 1305), add `self.pipeline_id` as positional arg, `"--role", "overseer"`, and `"--type", "STATUS"` to the `_run_cli` call. Acceptance: CLI receives explicit pipeline_id, role, and message type.
3. **[task-1-3]** In `orchestrator/overseer/monitor.py:_resolve_alert()` (line 1322), add `self.pipeline_id` as positional arg to the `_run_cli` call. Acceptance: CLI receives explicit pipeline_id.
4. **[task-1-4]** In `orchestrator/overseer/monitor.py:_create_hitl_decision()` (line 1337), add `self.pipeline_id` as positional arg to the `_run_cli` call. Acceptance: CLI receives explicit pipeline_id.
5. **[task-1-5]** In `orchestrator/tests/test_overseer_monitor.py`, mock `_broadcast_alert` as `AsyncMock()` in test classes that call health check methods without mocking it: `TestPostConsensusStall`, `TestStatusConsistency`, `TestHitlResolutionPropagation`, `TestPrPhaseOutcomeCheck`, `TestOrchestratorReachability`, `TestCrossPhaseConsistency`, `TestRerunAnomaly`. Acceptance: All existing tests pass.
