# Plan: Gateway auto-filter + commit-authorship registry for cross-role pushes

> Issue: #1882 | Phase: plan | Branch: `egg/issue-1882`

## Approach

Refine-phase HITL locked in four axes (see
`.egg-state/drafts/1882-analysis.md` "HITL Resolution"):

- **decision-1**: Option **B3** — *gateway-side commit-SHA registry*.
  The gateway maintains a durable `commit_sha → (role, session_id,
  timestamp)` mapping, populated by a sandbox `post-commit` git hook
  that POSTs to the gateway. The gateway attributes each commit to
  whichever role owns the **session token** that called the hook — it
  does not trust `commit.author_email` or any sandbox-reported
  authorship data. Session tokens are minted by the gateway, so this
  is deterministic gateway-observed authorship.
- **decision-6**: Option **C1** — single-release cutover. Auto-filter
  + registry + scope-filter removal all ship in this PR. Kill switch
  `EGG_AGENT_RESTRICTIONS_ENFORCE=false` preserved.
- **decision-8**: Remove `egg-orch push --scope-filter` entirely in
  this PR.
- **decision-9**: **Fail closed**. Any commit whose authorship cannot
  be resolved via the registry is treated as own-authored for
  restriction-check purposes. Suppressing the post-commit hook
  (`--no-verify`, `core.hooksPath=/dev/null`, commits before the hook
  is installed) cannot be used to bypass file restrictions.

Refine-phase recommendations were adopted for the remaining decisions:
squash own-authored commits (decision-2 / -11), `nothing_to_push=true`
for the all-blocked case (decision-3 / -10), `[auto-filtered]` commit
suffix (decision-4 / -12), `pulled_commits` response field (decision-5
/ -13), place the partition helper in
`shared/egg_restrictions/checker.py` (decision-7 / -15), fail-closed
for unknown-role authorship (decision-17).

The change decomposes into five phases. They ship as a **single PR**
on `egg/issue-1882`; phases exist only to organise commits and make
review incremental. Phases 1 and 2 are independent (infra vs auto-
filter port) and can land in either order; phase 3 depends on both;
phase 4 depends on 3 being wired; phase 5 (tests) depends on 1-4.

### Phase 1 — Commit authorship registry (durable store + endpoint + hook)

Build the registry that replaces B1's "trust `git log %ae`" approach.

- Extend `orchestrator/state_store.py` with a `commit_authorship`
  table stored as `.egg-state/pipeline-worktree/commit_authorship/<sha-prefix>.json`
  (sharded by first 2 hex chars of SHA so the directory stays
  O(N/256)). Methods: `record_commit_authorship(sha, role,
  session_id)`, `get_commit_authorship(sha) -> Authorship | None`,
  `get_commit_authorship_many(shas) -> dict[sha, Authorship]`. Reuse
  the existing per-pipeline RLock / fcntl.flock pattern; authorship
  shards are keyed by SHA prefix with their own lock to avoid
  serialising all commit writes behind a single pipeline lock.
- Add `gateway/commit_registry.py` — thin façade the gateway calls
  into. `register(sha, role, session_id)` persists via the orchestrator
  state store. `lookup_many(shas) -> dict[sha, Authorship]` does a
  single batched read. Keeps StateStore as an implementation detail
  behind a stable API.
- Expose `POST /api/v1/git/register_commit` in `gateway/gateway.py`.
  Body: `{ "sha": "...", "repo": "owner/name" }`. Authoritative role
  comes from `g.session.agent_role` (not the body), same for
  session_id. Request body's `author_email` / `author_name` are
  ignored — the endpoint does not trust them. Audit log each
  registration with the attributed role and session.
- Install `.git/hooks/post-commit` at sandbox entrypoint time, before
  any agent code runs. Hook: (1) resolves the freshly-created SHA via
  `git rev-parse HEAD`; (2) reads `EGG_SESSION_TOKEN` from env and the
  gateway URL from `EGG_GATEWAY_URL`; (3) POSTs to
  `/api/v1/git/register_commit`; (4) on any failure (network error,
  5xx, missing env), logs to stderr and exits 0. Commit must land
  locally whether or not the hook succeeds; unregistered commits fall
  through to decision-9 fail-closed at push time.
- Update `sandbox/entrypoint.py::setup_git` to write this hook into
  `.git/hooks/post-commit` and chmod +x it. The hook body lives in a
  versioned sandbox file (e.g. `sandbox/hooks/post-commit.sh`) and is
  copied into place, not generated inline, so it is reviewable in
  source.

### Phase 2 — Port #1470 auto-filter building blocks

Revive the three pieces from commit `6f0877f50` (never merged), lightly
refactored so they sit in stable locations.

- Add `partition_files_by_role(role, files) -> (allowed: list[str],
  blocked: list[str])` in `shared/egg_restrictions/checker.py` so both
  gateway and any future client can reuse it (decision-7 /
  decision-15 default). The existing `AgentFilePattern.can_write()`
  is the single source of truth for matching; the new helper is a
  partition over that.
- Add a thin `filter_agent_files(agent_role, files)` wrapper in
  `gateway/phase_filter.py` that delegates to the checker helper.
  Matches the `#1470` import path the rest of the gateway expects.
- Port `_execute_filtered_push(exec_path, blocked_files, cmd, branch,
  old_ref_sha, env, original_msg)` into `gateway/gateway.py`. Behavior
  matches `6f0877f50`: save `HEAD`, soft-reset to `old_ref_sha` (or
  `merge-base HEAD origin/main` for new-branch pushes), unstage
  blocked files, recommit with original message + `[auto-filtered]`
  suffix (decision-4 / -12 default), push, restore `HEAD` via `git
  reset --hard`. On any failure along the way, restore `HEAD` before
  returning an error. The function is atomic from the agent's
  perspective: either the push succeeds and the worktree contains the
  blocked files as *unstaged* changes, or the push fails and the
  worktree state is unchanged. Write the restore logic inside a
  `try/finally` so an uncaught exception anywhere in between still
  restores `HEAD`.

No wiring into the push handler yet — the building blocks land first
so they are unit-testable in isolation.

### Phase 3 — Attribute each commit, route pushes accordingly

Wire the registry and the auto-filter into the push endpoint.

- Change `get_changed_files_in_push()` in `gateway/git_client.py` to
  return per-commit attribution alongside the file list. New return
  type: `tuple[list[AttributedFile], str | None]` where
  `AttributedFile = {"path": str, "commit_sha": str}`. (Add a sibling
  function `get_attributed_changed_files_in_push` and make the
  existing `get_changed_files_in_push` a thin wrapper that drops the
  SHA — safer than changing a widely-called function's return shape.
  Callers that need attribution opt in.) The per-commit `diff-tree`
  loop already iterates every commit — this change records the SHA it
  is iterating and tags each returned path with it. On
  `diff-tree` failure, the existing fail-closed path in
  `git_client.py:1492-1502` is preserved.
- In `gateway/gateway.py`'s push handler, after
  `get_attributed_changed_files_in_push`, call
  `commit_registry.lookup_many(set(af.commit_sha for af in
  attributed_files))`. Partition every attributed file into one of
  three buckets:
  1. **Own-authored** — registry says this commit is the pushing role,
     *or* the commit is unregistered (fail-closed per decision-9).
  2. **Pulled from a known role** — registry says this commit is a
     different known role. Files are exempt from the pushing role's
     restrictions; commits pass through untouched.
  3. **Unknown role** — registry entry exists but role is not in the
     known-role table. Treated the same as own-authored (fail-closed,
     decision-17 default).
- Apply `check_agent_restrictions(role, own_authored_files)` — *only*
  own-authored files feed the check. If all own-authored files pass,
  run the normal `git push` (handles the mixed-author happy path).
- If `check_agent_restrictions` returns a blocked set:
  - All own-authored files blocked, nothing allowed → return **200**
    with `{ filtered: true, nothing_to_push: true, excluded_files:
    [...], pulled_commits: [...] }` and leave the own-authored commit
    intact in the worktree (decision-3 / -10 default).
  - Mixed own-authored allowed/blocked → call
    `_execute_filtered_push`. On success return **200** with `{
    filtered: true, excluded_files: [...], pushed_files: [...],
    pulled_commits: [...] }`.
- Remove the current 403 path entirely when `EGG_AGENT_RESTRICTIONS_
  ENFORCE=true` (the default). Keep the 403 only for
  `check_file_restrictions` (phase-level blocklist, e.g. `.egg-state/
  contracts/` is blocked for every role — not the role-specific file
  pattern check).
- When `EGG_AGENT_RESTRICTIONS_ENFORCE=false`, log the attribution
  result + the would-be filter action to the warn-only path; do not
  rewrite.
- Audit-log emits three distinct events so operators can tell the
  paths apart: `push_auto_filtered`, `push_pulled_commits_exempt`,
  `push_denied_fail_closed_unregistered`. Each includes attributed-
  role mapping per commit SHA.

### Phase 4 — Remove `--scope-filter`

The gateway now handles every case `--scope-filter` was designed for.

- Delete the `--scope-filter` argparse flag from `sandbox/egg_lib/cli_push.py`
  and the associated `_filter_files` + rewrite logic. Keep the simple
  passthrough branch so `egg-orch push` continues to shell out to
  `git push`.
- Search-and-replace across docs and agent-config rules to remove
  every reference to `--scope-filter` and the client-side recovery
  workflow. Concretely: `docs/guides/agent-development.md`,
  `docs/reference/orchestrator-cli.md`, any `sandbox/agent-config/
  rules/*.md` that mention it. Replace with a short paragraph noting
  the gateway now auto-filters.

### Phase 5 — Test coverage

Every scenario from the refine-phase test matrix (analysis §5, bullets
under "Tests"), plus registry-specific coverage:

- **State store**: unit tests for `record_commit_authorship` /
  `get_commit_authorship_many` (round-trip, shard boundaries,
  concurrent writes from two threads, idempotent re-record with same
  role, re-record with different role is rejected or audit-logged).
- **Partition helper**: unit tests for `partition_files_by_role` —
  all-allowed, all-blocked, mixed, unknown-role default-allow
  behavior, empty input.
- **Registry gateway endpoint**: tests that the POST endpoint
  attributes by `g.session.agent_role`, ignores any role/email in the
  request body, rejects unauthenticated callers, and fails safe when
  the state store is down.
- **Push handler end-to-end** — one test per scenario:
  1. Own-only, all allowed → plain push succeeds, no filter.
  2. Own-only, all blocked → 200 `nothing_to_push=true`, worktree
     unchanged.
  3. Own-only, mixed → 200 `filtered=true`, blocked files are unstaged
     in worktree afterwards.
  4. Mixed-author, pulled commits clean → plain push succeeds, no
     filter.
  5. Mixed-author, pulled commits contain files blocked for the
     pushing role → pulled files are exempt, push succeeds.
  6. Mixed-author, own-authored portion has blocked files → auto-
     filter rewrites only own commits, pulled commits untouched.
  7. Registry unavailable / commit unregistered → fail-closed (treat
     as own-authored); own-authored-blocked is rewritten.
  8. `EGG_AGENT_RESTRICTIONS_ENFORCE=false` → warn-only log, no
     rewrite.
- **Response schema**: `filtered`, `excluded_files`, `pushed_files`,
  `pulled_commits` present on filter-path responses; `pulled_commits`
  present on non-filter responses when any pulled commit is in the
  push (decision-5 / -13 default).
- **Post-commit hook**: integration test that a commit inside a
  sandbox container triggers a registration POST to the gateway mock
  and writes the expected row; and that hook failure (gateway
  unreachable) leaves the commit intact and returns exit 0.
- **`--scope-filter` removal**: test that invoking `egg-orch push
  --scope-filter` now exits non-zero with a clear "removed" message
  (or simply that the flag is absent and argparse fails — pick
  whichever matches the deprecation posture we settle on in the
  coder's implementation).

## Risk & mitigation pointers (for risk_analyst coordination)

Flagging these for the risk_analyst who is running concurrently so
the mitigations can be sanity-checked in their output:

- **Registry corruption / loss**: shard JSON files are append-only per
  SHA; a corrupt shard only affects lookups for SHAs in that shard, so
  at worst we fail-closed for those commits. Mitigation: the state
  store already gets pushed to a remote branch on every write (see
  `state_store.py` sync daemon) — disaster recovery inherits that.
- **Hook bootstrap gap**: commits created between container start and
  `setup_git` finishing won't have the hook installed. Mitigation:
  `setup_git` runs before any agent code in `sandbox/entrypoint.py`
  (confirmed in current source). We add a post-condition assertion:
  entrypoint exits non-zero if the hook file is not chmod +x at the
  end of git setup.
- **Soft-reset on mixed-author push**: the auto-filter must only
  rewrite own-authored tip commits. If there is a pulled commit ahead
  of the own-authored tip (unusual but possible after a rebase), the
  soft-reset would rewrite the pulled commit too. Mitigation: the
  auto-filter engages only when *every* unpushed commit is
  own-authored OR the pulled commits are all older than the own-
  authored tip. Detect and bail to 403 with a clear message otherwise;
  this edge case is rare and surfacing it explicitly is better than
  silently rewriting someone else's work.
- **Registry grows unbounded**: every commit adds a registry row.
  Mitigation: add a `prune_commits_older_than(days)` helper (not
  called in this PR) so a future cron can garbage-collect.

## Post-merge manual steps

- Deploy the new gateway image so the `/api/v1/git/register_commit`
  endpoint is live before new sandbox images are rolled out — the
  post-commit hook will POST to a 404 otherwise, which is harmless
  (hook exits 0) but produces noise.
- Deploy the new sandbox image so the post-commit hook is installed.
  Existing long-running sessions that predate the deploy will
  continue to author unregistered commits, which will fail-closed at
  push time — acceptable, as they keep working under the old
  behavior.
- No database migration beyond the first write to the orchestrator
  state store creating the `commit_authorship/` subdirectory.
