# Plan: Fix checkpoint MCP tools missing repos error

## Summary

Fix the MCP server's gateway session registration to include `pipeline_id="mcp-server"`, which uses the gateway's existing exemption for orchestrator-internal sessions that don't need worktrees. Additionally, add an optional `repo` parameter to both checkpoint tool schemas so callers can explicitly specify the checkpoint repository (e.g., `jwbron/egg-checkpoints`), passed as the `source_repo` query param.

**Risks / edge cases**: The `get_contract` tool shares the same session registration path and is silently affected by the same bug — this fix resolves all three gateway-backed tools. No existing behavior changes for callers that don't pass `repo`.

## Implementation

### Phase 1: Implement

Fix session registration and add repo parameter to checkpoint MCP tools.

**Tasks**:
1. **[task-1-1]** In `orchestrator/mcp_tools.py:_ensure_gateway_session()`, add `pipeline_id="mcp-server"` to the `client.register_session()` call so the gateway allows the session without repos. Acceptance: session registration succeeds without repos.
2. **[task-1-2]** In `orchestrator/mcp_tools.py`, add an optional `repo` property (type string, description "Checkpoint repository in owner/repo format, e.g. jwbron/egg-checkpoints") to both `list_checkpoints` and `search_checkpoints` tool schemas. Acceptance: both tool schemas include the `repo` property.
3. **[task-1-3]** In `orchestrator/mcp_tools.py:_handle_list_checkpoints()` and `_handle_search_checkpoints()`, pass the `repo` arg as `source_repo` query param when provided. Acceptance: `source_repo` query param is forwarded to the gateway when `repo` is specified.
4. **[task-1-4]** Update tests in `orchestrator/tests/test_mcp_tools.py` for the session registration fix and new `repo` parameter. Acceptance: tests pass covering the pipeline_id fix and repo parameter forwarding.
