# Plan: Phase-scope the overseer lifecycle

## Summary

Make the overseer container phase-scoped: spawn at phase start, tear down at phase completion. This saves resources during idle periods between phases and HITL review windows, and gives each phase a fresh overseer instance with no accumulated state. The respawn logic in the health monitor polling thread needs a gating flag so it doesn't respawn an intentionally absent overseer between phases.

**Risks / edge cases**: The respawn logic must distinguish "overseer was intentionally stopped between phases" from "overseer crashed mid-phase". A `phase_overseer_active` flag controlled by the spawn/teardown code gates this. Container name reuse across phases is already handled by the existing cleanup-before-spawn logic. Graceful shutdown mid-poll relies on the existing 10s timeout in `stop_agent_container`. Cross-phase overseer state is intentionally lost (per-issue design goal).

## Implementation

### Phase 1: Implement

Move overseer spawn/teardown from pipeline scope to phase scope.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py`, remove the pre-loop overseer spawn (lines 6157-6184) and move it into the phase-start block (after phase.started event emission at line 6326). Add a `phase_overseer_active` flag (initially `False`) that is set to `True` after spawn and `False` after teardown. Gate `_check_and_respawn_overseer` calls in the health monitor poll thread on this flag. Acceptance: Overseer is spawned at each phase start, not once before the loop.
2. **[task-1-2]** In `orchestrator/routes/pipelines.py`, add overseer teardown (stop_agent_container + set phase_overseer_active=False) before phase advance (before line 7068), before pipeline-complete break (before line 7065), and in the phase-failed path. Acceptance: Overseer is stopped at phase completion, advance, and failure — not left running between phases.
3. **[task-1-3]** In `orchestrator/container_spawner.py:spawn_overseer_container()`, update docstring and BASH_COMMAND_TIMEOUT comment (line 866) to reference phase-scoped lifecycle instead of "entire pipeline lifetime". Acceptance: Comments accurately describe the phase-scoped overseer lifecycle.
4. **[task-1-4]** Update `orchestrator/tests/test_overseer_spawn.py` and `orchestrator/tests/test_pipeline_failure_path.py` to assert per-phase spawn. Add a test verifying `_check_and_respawn_overseer` is skipped when `phase_overseer_active` is `False`. Acceptance: All tests pass; new test covers respawn-gating behavior.
