# Plan: Include BRC context in git history

## Summary

Add deterministic BRC history persistence by having the orchestrator write per-phase BRC message logs to `.egg-state/brc-history/{identifier}-{phase}.md` at phase boundaries, and include a concise BRC summary in the PR body. This replaces reliance on non-deterministic agent-committed review files for BRC context. The orchestrator has direct access to the message store and operates on the pipeline-level worktree where `_commit_statefiles_to_worktree()` runs, making this fully deterministic.

**Risks / edge cases**: Message store may be empty at write time (graceful no-op). The `_commit_statefiles_to_worktree` scoping uses pipeline identifier prefix matching — new files in `brc-history/` will be picked up automatically since they follow the `{identifier}-*` naming convention. GitHub PR body size limit (65536 chars) is respected by keeping the PR section as a summary only while the full log goes to the committed file.

## Implementation

### Phase 1: Implement

Add BRC history file writing at phase boundaries and BRC summary in PR body.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py`, add a `_write_brc_history(worktree_path, pipeline_id, phase, identifier)` helper function. It should: (a) import and call `get_message_store().get_messages(pipeline_id, limit=10000)`, (b) filter to BRC-related message types (`CONSENSUS_PROPOSE`, `CONSENSUS_ACK`, `CONSENSUS_NACK`, `CONSENSUS_WITHDRAW`, `CONSENSUS_CONFIRMED`, `CONSENSUS_RE_REVIEW`), (c) if no BRC messages exist, return early (no-op), (d) format as markdown with a header showing phase and timestamp, then chronological entries with `[timestamp] from_role (message_type): subject` and body if non-empty, (e) write to `{worktree_path}/.egg-state/brc-history/{identifier}-{phase}.md`, creating the directory if needed. Call this function at line ~6734 (after phase completion, just before the existing `_commit_statefiles_to_worktree` call), and also at line ~6433 in the PR phase block (before `_ensure_statefiles_on_branch`). The `identifier` should be computed using `_pipeline_identifier(pipeline.issue_number, pipeline_id)`. Acceptance: After each phase with BRC activity, `.egg-state/brc-history/{identifier}-{phase}.md` exists with chronological BRC messages. Empty store produces no file.
2. **[task-1-2]** In `orchestrator/routes/pipelines.py`, modify `_build_pr_body()` to accept the `pipeline_id` (already available via `pipeline.id`) and add a "## BRC Consensus Summary" section to the PR body. The function should: (a) import and call `get_message_store().get_messages(pipeline.id, limit=10000)`, (b) filter to BRC message types, (c) if no BRC messages, omit the section entirely, (d) group messages by phase (using the `phase` field on each Message), (e) for each phase show: agent roles involved, counts of proposals/ACKs/NACKs/confirmations, and whether consensus was reached (all roles have CONFIRMED), (f) cap the section at ~2000 chars. Insert before the "Authored-by: egg" footer. Acceptance: PR body includes BRC summary when messages exist, omitted when none. Summary stays concise.
3. **[task-1-3]** Add tests in `orchestrator/tests/test_auto_pr.py` for: (a) `_write_brc_history` with BRC messages — verify file is created at correct path with correct content format, (b) `_write_brc_history` with empty store — verify no file is created, (c) `_build_pr_body` with mocked message store containing BRC messages — verify PR body includes "BRC Consensus Summary" section, (d) `_build_pr_body` with empty message store — verify no BRC section in body. Use `unittest.mock.patch` to mock `get_message_store`. Acceptance: All tests pass.
