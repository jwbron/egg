# Plan: Separate BRC progress tracking from liveness in stall detection

## Summary

Separate BRC protocol progress tracking from container liveness tracking in the Tier 1 health monitor. Add a post-propose grace period for reviewers (fixes false positive where active reviewers are killed pre-BRC) and a post-ACK confirmation timeout for producers (fixes false negative where heartbeating producers go undetected for 11+ minutes). The core approach is adding two new public methods to the peer consensus tracker and a new `check_brc_progress()` tripwire in the health monitor.

**Risks / edge cases**: The post-propose grace (5 min default) must not mask genuinely stuck reviewers — 5 min is safe because even complex refine reviews complete initial analysis under 5 min. The post-ACK confirmation timeout (3 min default) must not fire during legitimate commit/push operations — these complete in seconds. The `_is_brc_idle()` change is additive (returns True in more cases), so it can only suppress false positives, never create new false negatives.

## Implementation

### Phase 1: Implement

This phase adds BRC-aware progress tracking to the Tier 1 health monitor, addressing both the false positive (reviewer killed pre-BRC) and false negative (producer stuck post-ACK) failure modes from issue #1613.

**Tasks**:
1. **[task-1-1]** In `orchestrator/peer_consensus.py`, add two public methods to `PeerConsensusTracker`: `get_earliest_proposal_time(reviewer: str) -> float | None` returns the earliest `_proposal_timestamps` entry (as epoch float) among the reviewer's upstream producers, and `get_fully_acked_producers() -> dict[str, float]` returns `{role: proposal_timestamp_epoch}` for producers where `matrix.is_fully_acked(role)` is True and `_producer_phases[role]` is `PROPOSED` (not yet CONFIRMED). These give the health monitor clean read access to BRC state. Acceptance: both methods return correct values in unit tests.
2. **[task-1-2]** In `orchestrator/models.py`, add two fields to `PipelineConfig`: `orchestrator_post_propose_grace_seconds: int = Field(default=300, ge=30, description="Grace period for reviewers after producer proposes before stall detection")` and `orchestrator_post_ack_confirmation_timeout_seconds: int = Field(default=180, ge=30, description="Timeout for producers to send CONFIRMED after being fully ACKed")`. Acceptance: fields exist with correct defaults and are accessible from config.
3. **[task-1-3]** In `orchestrator/health_monitor.py`, extend `_is_brc_idle()` to also return True when the agent is a reviewer-only role (not a producer), at least one upstream producer has proposed, and the earliest upstream proposal is within the `orchestrator_post_propose_grace_seconds` window. Use `tracker.get_earliest_proposal_time(agent_id)` and compare against `time.time() - config.orchestrator_post_propose_grace_seconds`. Acceptance: reviewers within post-propose grace are suppressed from heartbeat/progress alerts.
4. **[task-1-4]** In `orchestrator/health_monitor.py`, add `_fully_acked_first_seen: dict[str, float]` instance variable and `brc_progress_escalated: bool = False` to `AgentState`. Add `check_brc_progress() -> list[dict]` method: queries `tracker.get_fully_acked_producers()`, tracks first-seen time for each, escalates when elapsed > `orchestrator_post_ack_confirmation_timeout_seconds`. Uses same escalation pattern as `check_progress()` (creates alert, fires callbacks). Reset tracking when agent confirms or disappears from fully-acked set. Wire into `check_tripwires()` alongside existing checks. Acceptance: producers stuck post-ACK for >3 min are escalated regardless of heartbeat activity.
5. **[task-1-5]** Add tests in `orchestrator/tests/test_health_monitor.py`: (a) reviewer within post-propose grace not flagged by check_heartbeats/check_progress; (b) reviewer past grace period IS flagged; (c) check_brc_progress escalates fully-ACKed producer past timeout; (d) check_brc_progress does NOT escalate within timeout; (e) check_brc_progress resets when producer confirms. Acceptance: all new tests pass and existing tests still pass.
