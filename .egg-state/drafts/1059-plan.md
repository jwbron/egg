# Plan: Implement two-tier pipeline health monitoring — orchestrator tripwires + overseer agent

> Issue: #1059 | Phase: plan

## Summary

This plan implements a two-tier pipeline health monitoring system: a deterministic
orchestrator tier that processes structured agent progress logs programmatically, and
an LLM-powered overseer agent that handles ambiguous situations via Haiku classification
and Sonnet/Opus decision-making. All work ships in a single PR organized into five
sequential phases.

The orchestrator tier handles clear-cut failures (heartbeat timeouts, container exits,
repeated errors, message volume spikes) instantly without LLM cost. The overseer tier
fires only for ambiguous cases — using `shared/egg_agent/` for all LLM calls. The
overseer is auto-spawned on every pipeline, runs as a separate container with no repo
access, and escalates restart requests via HITL only.

## Design Decisions

This plan follows the analysis's recommended **Option C (Hybrid)** approach and assumes
the recommended defaults for unresolved contract decisions:

- **decision-1**: Separate `health_monitor.py` module (not extending HealthCheckRunner)
- **decision-2**: In-memory progress storage with configurable retention
- **decision-3**: Existing message bus for orchestrator→overseer escalation
- **decision-4**: Autonomous issue filing for high-confidence, HITL for low-confidence
- **decision-5**: Add OVERSEER role independently (don't wait for #1030)
- **decision-6**: Sonnet as default decision-maker model

If HITL resolves any of these differently, the affected tasks will need adjustment.

## Dependency Note

Dependencies #1088 (Agent SDK) and #1164 (Coordinator removal) are already
merged/closed. #1030 (Agent team roster) is still open but we proceed independently —
the pattern for adding roles is well-established.

### Phase 2: Structured Progress API & Deterministic Tripwires

**Goal**: Build the structured progress ingestion and query endpoints, and the
deterministic tripwire processor that evaluates progress events against configurable
thresholds.

**Tasks**:

- **[TASK-2-1]** Create `orchestrator/routes/progress.py` with two endpoints:
  - `POST /api/v1/pipelines/<id>/progress` — agents emit structured progress events.
    Validates agent role against active pipeline agents. Emits `PROGRESS_EMITTED` event
    on EventBus. Stores in-memory with configurable retention window.
  - `GET /api/v1/pipelines/<id>/progress` — query progress events, filterable by
    `?agent_role=&since=&limit=`. Used by both orchestrator and overseer.
  Register the blueprint in `orchestrator/api.py`.

- **[TASK-2-2]** Create `orchestrator/progress_store.py` — in-memory per-pipeline
  progress event storage. Implements `add_event()`, `get_events(since, agent_role, limit)`,
  `get_latest_per_agent()`, `clear(pipeline_id)`. Thread-safe. Configurable max retention
  (default: last 1000 events per pipeline). Periodic pruning of old events.

- **[TASK-2-3]** Add `progress emit` and `progress query` subcommands to the CLI.
  - `egg-orch progress emit --step <text> --state <working|blocked|complete> [--detail <text>] [--blocker <text>]`
  - `egg-orch progress query [--agent <role>] [--since <timestamp>] [--limit <n>]`
  Add corresponding client methods to `shared/egg_orchestrator/client.py`.

- **[TASK-2-4]** Create `orchestrator/health_monitor.py` — deterministic tripwire
  processor. Subscribes to EventBus events (`PROGRESS_EMITTED`, `AGENT_STARTED`,
  `MESSAGE_SENT`, heartbeat signals). Evaluates five tripwire rules against
  PipelineConfig thresholds:
  1. **Heartbeat timeout**: No heartbeat/progress within `orchestrator_heartbeat_timeout_seconds` → auto-nudge agent via message bus.
  2. **Container exit**: Agent container dies → immediate HITL escalation.
  3. **Repeated identical errors**: Same error `orchestrator_error_repeat_threshold` times → escalate to overseer (or HITL if no overseer).
  4. **Message volume spike**: Agent sending > `orchestrator_message_rate_limit` messages/min → auto-throttle.
  5. **Progress stall**: No structured progress update within threshold → nudge, then escalate to overseer if unresolved.

  Auto-nudge sends a message via the existing message bus. Escalation to overseer sends
  a structured escalation message with anomaly type, agent role, and relevant progress
  events.

- **[TASK-2-5]** Add `health alerts` subcommand to the CLI:
  - `egg-orch health alerts [--pipeline <id>]` — list active deterministic alerts.
  Add corresponding route `GET /api/v1/pipelines/<id>/health/alerts` in
  `orchestrator/routes/health.py`.

- **[TASK-2-6]** Write unit tests for progress store (add, get, filter, prune,
  thread-safety), progress routes (emit, query, validation), and health monitor
  (each tripwire rule, auto-nudge, escalation). Write integration test for the
  full flow: agent emits progress → tripwire detects stall → auto-nudge sent.

### Phase 4: Overseer Agent Logic (Haiku/Sonnet/Opus Tiers)

**Goal**: Implement the overseer's internal monitoring loop, Haiku classification
agents, and Sonnet/Opus decision-maker — all using `shared/egg_agent/`.

**Tasks**:

- **[TASK-4-1]** Create `sandbox/.claude/rules/overseer.md` — the overseer agent
  prompt instructions. Define:
  - Monitoring loop: poll each cycle via `egg-orch progress query` and
    `egg-orch health alerts`, check health endpoints.
  - Two-tier architecture awareness: orchestrator handles deterministic cases,
    overseer handles ambiguous escalations received via message bus.
  - Internal Haiku/Sonnet split: use `egg_agent` (`run_agent_async(model="haiku")`)
    for classification, escalate to `run_agent_async(model="sonnet")` for decisions.
  - Adaptive stall detection: orchestrator auto-nudges first, overseer classifies
    if unresolved (stuck vs. legitimate long-running work).
  - Corrective action ladder: auto-nudge → redirect → HITL → issue → Slack.
  - Structured diagnostic format for auto-filed GitHub issues.
  - Self-monitoring: track own poll cycle timing, message volume, LLM call costs.
    If malfunctioning, file issue about itself and signal BLOCKED.
  - Mediator boundary: hand off contradictory message loops and inter-agent
    disagreements to mediator; if no mediator, escalate to HITL.
  - Stay-alive loop until pipeline completes.

- **[TASK-4-2]** Create `orchestrator/overseer/` package with the overseer's
  server-side logic:
  - `orchestrator/overseer/__init__.py` — package init.
  - `orchestrator/overseer/classifier.py` — Haiku classification functions:
    `classify_stall(logs, progress)`, `classify_error(error_context)`,
    `detect_loop(recent_actions)`, `check_alignment(activity, contract)`.
    Each uses `run_agent_async(model="haiku", max_turns=1)` with focused prompts.
    Cache results to avoid re-analyzing the same log lines.
  - `orchestrator/overseer/decision_maker.py` — Sonnet/Opus decision functions:
    `decide_corrective_action(classification, context)`,
    `compose_redirect_message(agent_role, issue, context)`,
    `decide_escalation_level(classification, redirect_history)`.
    Uses `run_agent_async(model=config.overseer_decision_maker_model, max_turns=1)`.
  - `orchestrator/overseer/issue_filer.py` — Autonomous GitHub issue filing:
    `file_diagnostic_issue(pipeline_id, agent_role, anomaly, context)`.
    Uses the structured diagnostic template from the issue spec.
    Auto-labels with `overseer-alert` + error category.
    High-confidence classifications filed autonomously; low-confidence require HITL.
  - `orchestrator/overseer/self_monitor.py` — Self-monitoring:
    Track poll cycle timing, message volume, LLM call counts/costs.
    If self-metrics exceed thresholds, file issue and signal BLOCKED.

- **[TASK-4-3]** Create `orchestrator/overseer/monitor.py` — the main overseer
  monitoring loop that ties everything together:
  - Poll `egg-orch progress query` and `egg-orch health alerts` each cycle.
  - Receive escalation messages from the orchestrator's tripwire processor via
    message bus (`egg-orch message poll`).
  - Route escalations to Haiku classifiers.
  - Route Haiku results to Sonnet/Opus decision-maker when a decision is needed.
  - Execute corrective actions (send redirect, file HITL decision, file issue,
    notify via Slack).
  - Enforce data dependency: Sonnet/Opus only acts on received Haiku outputs
    (hallucination guard).
  - Produce pipeline health summary at pipeline completion.

- **[TASK-4-4]** Write unit tests for each overseer component:
  - Classifier tests with mocked `run_agent_async` responses.
  - Decision-maker tests with mocked classifications.
  - Issue filer tests verifying diagnostic template format and labeling.
  - Self-monitor tests for threshold detection.
  - Monitor loop tests for escalation routing, hallucination guard, and
    corrective action execution.

## Risk Considerations

1. **Hallucination in multi-tier agents**: Sonnet/Opus tier must only act on received
   Haiku outputs. The `monitor.py` orchestration enforces this data dependency explicitly.
2. **False positive stalls**: Adaptive detection (orchestrator nudge → Haiku
   classification) prevents false positives on legitimate long-running work.
3. **Cost control**: Haiku for frequent classification, Sonnet/Opus only on anomaly
   escalation. Most issues resolved deterministically without LLM cost.
4. **Overseer self-failure**: Self-monitoring detects own malfunctions and escalates.
5. **Unresolved contract decisions**: Plan assumes recommended defaults. If HITL
   resolves differently, tasks in affected phases need adjustment.
