# Plan: Replace interactive mode with a generic `run_agent_task` MCP primitive

> Issue: #1762 | Phase: plan | Approach: Option A (single-PR full cutover)

## Strategy

The refine analysis (`.egg-state/drafts/1762-analysis.md`) recommended
**Option A — ship the `run_agent_task` primitive AND delete interactive
mode in a single PR**, with the addition commits landing before the
removal commits inside the PR so reviewers can read the narrative
top-to-bottom. The refine-phase HITL gate has resolved all nine
decisions (`.egg-state/contracts/issue-1762-membump.json`). This plan
adopts those resolutions verbatim as fixed context. They are repeated
here so reviewers don't have to chase the contract:

| Item | Resolved answer | Drives |
|---|---|---|
| D1 (tool name) | **`run_agent_task`** (not `run_custom_phase`). | MCP tool + docs + tests use this name. `run_custom_phase` appears nowhere in final output. |
| D2 (CUSTOM + BABYSIT) | **CUSTOM accepts `pr_number` and subsumes BABYSIT internally.** BABYSIT stays as a user-facing MCP tool but its route handler is refactored to build a CUSTOM pipeline under the hood. Full BABYSIT deprecation is out-of-scope. | One route code path for PR-targeted implement phases; BABYSIT becomes a thin façade. |
| D3 (cli.py scope) | **Remove `bin/egg` AND `egg_lib.cli.main`.** Relocate `gha_exec()` to `sandbox/egg_lib/gha_exec.py`. | GHA still works via the relocated module; no half-dead `cli.py`. |
| D4 (compose removal) | **Full cutover.** Delete `sandbox/egg_lib/compose.py` entirely. Remove every call to `ensure_compose_services()` and `run_compose_mode()` including inside `exec_in_new_container()` and `bin/egg-deploy`. Integration-test fixtures migrate in the same PR. | No compose code path survives. |
| D5 (roster storage) | **New field `Pipeline.active_roles: list[str] \| None`** on the `Pipeline` model. Stored at creation, read by `_run_concurrent_phase()` when building the review-graph filter and the `ConcurrentPhaseExecutor` constructor. Not on `PipelineConfig`, not on `PhaseExecution`. | Self-describing pipeline record; in-flight pipelines survive role-roster version bumps. |
| D6 (degenerate rosters) | **Reject reviewer-only rosters at validation.** Require at least one producer role in the subset; empty or reviewer-only returns HTTP 400. Single-producer-no-reviewers is allowed and short-circuits via `ApprovalMatrix.is_fully_acked()`. | BRC can't deadlock waiting for producers that aren't spawned. |
| D7 (no-branch behavior) | **Auto-generate `egg/custom-<pipeline_id>` when `branch` is omitted.** Callers always get a branch in the returned pipeline record; producers push drafts there; callers retrieve via `git show`. No "no git writes" path — all CUSTOM pipelines have a branch. | Uniform artifact retrieval; no special case for refine/plan-only runs. |
| D8 (cross-phase roles) | **Reject.** Only roles that appear in `_PHASE_ROLES[phase] ∪ _PHASE_REVIEWERS[phase]` (after `has_contract` / `EGG_ONLY_REVIEWERS` filtering) are selectable. `overseer`, `autofixer`, `conflict_resolver` are not selectable through `run_agent_task`. | Strictly phase-scoped; keeps semantics simple. |
| D9 (cutover strategy) | **Option A — one PR.** `run_agent_task` lands first (commits 1–N), interactive removal lands second (commits N+1..M). | One narrative, one review, one merge. |

### Open feedback (F1–F9) — plan-phase resolutions

The refine resolution block explicitly deferred the 9 open-ended
feedback questions to plan-phase. They are resolved here as part of
task decomposition:

- **F1 (HITL gate integration)**: **Out-of-scope for v1.** `run_agent_task` does
  not trigger HITL gates; callers use `provide_input` if the phase
  surfaces decisions. Re-visit only when a concrete caller needs it.
- **F2 (contract-file keying)**: When `issue_number` is provided,
  CUSTOM pipelines share `.egg-state/contracts/issue-<N>.json` with
  any existing ISSUE-mode pipeline for that issue (idempotent merge;
  contracts are append-only for decisions/feedback). When
  `issue_number` is absent, use the pipeline-id-keyed contract file
  (`.egg-state/contracts/<pipeline_id>.json`), same convention as
  `pipeline-<hash>` prompt-driven runs today.
- **F3 (analysis/plan arg semantics)**: `analysis` and `plan` are
  always accepted as pre-populated drafts. Producers may overwrite
  them during the phase (identical to today's
  `submit_task --start-phase=implement` behaviour, which writes the
  inline args to drafts on first run). No reviewer-only restriction.
- **F4 (repo allowlist)**: Reuse the existing `repositories.yaml`
  allowlist enforced by the gateway. `run_agent_task` does not
  introduce a new allowlist surface.
- **F5 (`pr_number` v1 validation)**: Accepted per D2; treated the
  same as BABYSIT's `pr_number` (open non-fork non-empty-diff gate).
  No deprecation warning — this is the intended subsumption path.
- **F6 (CLI surface)**: MCP-only in v1. `bin/egg-sdlc` does **not**
  grow a `custom-phase` subcommand. Hosts can shell out to
  `curl http://orchestrator/api/v1/pipelines` if needed, but that's
  undocumented.
- **F7 (persisted-state migration)**: No migration needed. The new
  `Pipeline.active_roles` field defaults to `None` (Pydantic optional);
  existing serialised pipelines deserialise unchanged. The new
  `PipelineMode.CUSTOM` enum value is additive.
- **F8 (degenerate-roster test coverage)**: Explicit tests cover:
  (a) single-producer-no-reviewer roster reaches CONSENSUS_REACHED on
  first propose (short-circuit path); (b) reviewer-only roster is
  rejected with HTTP 400 before any spawn; (c) mixed
  producer-subset roster spawns only the selected producers and the
  review graph filters to edges between selected roles.
- **F9 (docs rewrite list)**: The canonical list of user-facing docs
  to update is:
  - `README.md` (remove interactive-mode section, add `run_agent_task`
    mention)
  - `docs/guides/local-quickstart.md` (replace `egg --setup` flow
    with MCP-driven host workflow)
  - `docs/guides/deployment.md` (remove compose sections, keep k8s)
  - `docs/architecture/declarative-setup.md` (drop interactive-mode
    references; keep declarative k8s setup)
  - `docs/architecture/kubernetes-migration.md` (append note that
    interactive mode has been removed; keep historical compose→k8s
    mapping as reference)
  - `docs/guides/deploy-migration.md` (remove compose-up/down
    sections)
  - `docs/guides/sdlc-pipeline.md` (add `run_agent_task` as the
    replacement for one-off role work)
  - `docs/reference/mcp-deployment-tools.md` (add `run_agent_task`
    schema)
  - New file: `docs/guides/custom-phase.md` (dedicated tutorial for
    `run_agent_task`: how to pick roles, what each phase produces,
    how to retrieve artifacts)
  - `docs/reference/agent-roles.md` (mention `run_agent_task` as the
    way to invoke individual roles)
  - `CLAUDE.md` (remove "Interactive use goes through `claude` CLI"
    line — now MCP-only)

## Test Strategy

- **Automated unit tests** (under `orchestrator/tests/`, `shared/tests/`,
  `sandbox/tests/`):
  - `PipelineMode.CUSTOM` present in enum; `Pipeline.active_roles`
    field deserialises as `None` when absent, round-trips when set.
  - `validate_roles_for_custom_phase()` in
    `shared/egg_contracts/agent_roles.py`: valid subset, invalid
    subset (role outside phase), empty list, reviewer-only list,
    cross-phase role (`overseer`), `reviewer_contract` without a
    contract artifact, `reviewer_contract` with artifact.
  - `_handle_run_agent_task()` in `orchestrator/mcp_tools.py`:
    minimal-args happy path (phase + roles + repo + description),
    no-branch fallback producing `egg/custom-<pipeline_id>`,
    `pr_number` forwarding (treated as BABYSIT-subsumption path),
    `analysis` / `plan` pre-population, HTTP 400 on reviewer-only
    roster, HTTP 400 on invalid role subset.
  - `create_pipeline()` route in `orchestrator/routes/pipelines.py`:
    `mode=custom` validates `phase` + `roles`, rejects degenerate
    rosters, persists `active_roles` on the returned pipeline,
    defaults `branch` to `egg/custom-<pipeline_id>` when absent,
    sets `has_contract=True` when `analysis`/`plan` supplied or
    `issue_number` resolves an existing contract, filters
    `reviewer_contract` when `has_contract=False`.
  - `_run_concurrent_phase()`: when `pipeline.active_roles` is set,
    roles passed to `ConcurrentPhaseExecutor` match the override;
    review graph is filtered to edges with both endpoints inside
    the override set; degenerate single-producer case reaches
    consensus on first propose.
  - `babysit_pr` route handler: still accepts `pr_number` + `repo`,
    now internally constructs the same CUSTOM pipeline that
    `run_agent_task(phase=implement, roles=<default>, pr_number=N,
    repo=R)` would; end-state pipeline record is identical
    (modulo `mode` string) to before the refactor.
  - Regression tests for interactive-mode callers that still exist
    after removal: `tests/sandbox/test_cli_main.py` is deleted (the
    function it tests no longer exists); new
    `tests/sandbox/test_gha_exec.py` covers the relocated
    `gha_exec()` entry point.
- **Automated integration tests** (`integration_tests/`):
  - Remove `integration_tests/local_pipeline/conftest.py` compose
    port-extraction logic (mentioned in analysis); migrate to
    k8s-based fixture that targets the already-running
    orchestrator/gateway via `kubectl port-forward` or the
    existing service URLs.
  - Add `integration_tests/test_run_agent_task.py`: end-to-end
    exercise of `run_agent_task(phase=refine, roles=[refiner],
    repo=..., description=...)` against the local k8s stack;
    assert that the pipeline reaches consensus and a draft appears
    on the synthetic branch.
- **Manual verification** (reviewer / human):
  - Bring up the local k8s stack via `bin/egg-deploy init` +
    `kubectl apply -f k8s/`. Confirm `bin/egg-deploy up` is gone (or
    exits with a clear "deprecated; use kubectl" message — see
    TASK-6-2).
  - From a host Claude Code session, call
    `run_agent_task(phase="refine", roles=["refiner"], repo="jwbron/egg",

    `issue-*-membump-*` style pipeline with a single refiner that
    reaches consensus on first propose.
  - Confirm `bin/egg` is gone (`ls bin/egg` → "No such file"). The
    other `bin/egg-*` scripts still work.
  - Confirm the GHA action still runs end-to-end: trigger a workflow
    that dispatches `action/entrypoint.sh`; the workflow exits
    cleanly (tests `sandbox/egg_lib/gha_exec.py` relocation).
  - Confirm `babysit_pr(pr_number=<N>, repo=...)` still works on a
    real open non-fork PR (tests BABYSIT subsumption).
  - Confirm `run_agent_task` with `roles=[reviewer_code]` (no
    producer) returns HTTP 400 before any container spawn.

### Manual pre/post-merge steps

- **Pre-merge**: **Drain in-flight BABYSIT pipelines.** Because the
  BABYSIT route now constructs a CUSTOM pipeline under the hood (D2),
  the internal field layout changes (`active_roles` populated). Any
  BABYSIT pipeline created against the pre-merge code that is still
  mid-run at merge time will not find an `active_roles` field and
  will read `None` (the default) — which is fine because the
  executor falls back to `get_roles_for_phase(phase, has_contract)`.
  So technically no drain is required, but operators should be
  warned to cancel or let drain any in-flight BABYSIT pipelines
  before merging to minimise surprise. No DB migration, no config
  schema change.
- **Pre-merge**: Confirm no internal tooling / CI workflows invoke
  `bin/egg` or `egg --setup/--reset/--compose` — grep confirms none
  exist today, but run one more sweep at merge time.
- **Post-merge**: Announce the removal of interactive mode and the
  availability of `run_agent_task` on the team's deprecation
  channel. Point users at `docs/guides/custom-phase.md`. Flag the
  change in release notes. No rollback path for the interactive
  mode — once merged, users must use MCP clients or the GHA action.

## Phases

The PR is organised into 7 phases. Phases 1–4 are **additive** (they
add `run_agent_task` and its plumbing). Phases 5–6 are **subtractive**
(they remove interactive mode + compose). Phase 7 is **docs + tests
cleanup**. Each phase is an independently reviewable commit range.

### Phase 1 — Model + role-validation plumbing

**Goal.** Add the data-model and validation building blocks for
`PipelineMode.CUSTOM` before any route handler or MCP tool references
them. Pure data-layer change; nothing spawns agents yet.

### Phase 2 — Route handler + roster threading

**Goal.** Extend `create_pipeline()` at `orchestrator/routes/pipelines.py:693`
to accept `mode=custom`, validate `phase` + `roles`, apply branch
fallback, and persist `active_roles`. Extend `_run_concurrent_phase()`
at `orchestrator/routes/pipelines.py:7184` to read `pipeline.active_roles`
and pass it as the `roles=` override to the executor; filter the
review graph to edges inside the override set.

### Phase 3 — MCP tool definition + handler

**Goal.** Add the `run_agent_task` tool to `PIPELINE_TOOLS` in
`orchestrator/mcp_tools.py:64` and the `_handle_run_agent_task()`
method. Add routing in the handlers dict at line 865.

### Phase 4 — BABYSIT subsumption

**Goal.** Refactor `_handle_babysit_pr()` at `orchestrator/mcp_tools.py:1055`
and the BABYSIT branch of `create_pipeline()` (lines 754–807) to
build CUSTOM pipelines under the hood. The BABYSIT MCP tool stays
as a user-facing façade — D2. `PipelineMode.BABYSIT` still exists
as an enum value (not removed).

### Phase 5 — Remove interactive mode + compose

**Goal.** Delete `bin/egg`, `sandbox/egg_lib/cli.py::main()`,
`sandbox/egg_lib/compose.py`, `sandbox/egg_lib/runtime.py::run_claude()`
(plus the `ensure_compose_services()` call sites inside
`exec_in_new_container()`), the `run_interactive()` function in
`sandbox/entrypoint.py`, and the compose paths in `bin/egg-deploy`.
Relocate `gha_exec()` to `sandbox/egg_lib/gha_exec.py`. Update
`action/entrypoint.sh` to import from the new module path.

### Phase 6 — Integration-test fixture migration

**Goal.** Migrate `integration_tests/local_pipeline/conftest.py` off
the compose port-extraction it references in its module docstring.
Remove any other compose references in integration tests and wire
them to the k8s-based local stack.

### Phase 7 — Tests + docs rewrite

**Goal.** Delete `tests/sandbox/test_cli_main.py` (the module it
tests is gone). Add new test files for `run_agent_task`, the
role-validation helper, and the relocated `gha_exec()`. Rewrite the
user-facing docs enumerated in F9. Add the new
`docs/guides/custom-phase.md` tutorial. Update `CLAUDE.md` to drop
the "Interactive use goes through `claude` CLI" line.
