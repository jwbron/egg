# Plan: Simplify repository configuration — schema cleanup, layered repo+local config, onboard skill, validator

> Issue: #2073 | Phase: plan

## Approach

The architect recommended sequencing the four pieces, but the human's
resolution to **decision-2** picked "one coordinated feature — all four
together." Per CLAUDE.md (one issue = one PR), this single PR carries
all four pieces, organised into six phases (commits) so reviewers can
walk the diff in dependency order.

The scope, as resolved by HITL decisions and feedback:

- **Hard cutover** on the user-facing schema (decision-4 / Q1). Drop
  `persist_dirs` / `persist_system_dirs` / explicit-only `watch_files`
  in the legacy user-facing shape outright. No dual code paths, no
  migration tool (decision-12). Operators hand-edit on upgrade.
  **Manifest schema is independent** (see Risks): the host-side
  classifier produces the existing `persist_dirs` + `persist_system_dirs`
  two-list `manifest.json` shape from the unified `persist:` so
  `sandbox/docker-setup.py` is unchanged. This honors the architect's
  Component C3 design and avoids the sandbox-image-outlives-launcher
  cross-version trap (risk_analyst risk-1, NACK-1).
- **Repo defaults file** at `<repo>/.egg/repositories.yaml`
  (decision-1). Auto-discovered when the operator runs egg against a
  checkout (decision-10). `schemaVersion: "1.0"` (string, matches
  egg-wide convention in `shared/egg_contracts/checkpoints.py` and
  `.egg/schemas/contract.schema.json` — review-2/risk-4) on both
  files from day one (decision-13).
- **Centralized merge** in a NEW module `shared/egg_config/repos.py`
  (decision-5). Replace-by-default for list-valued fields, no
  `extends:` keyword in v1 (decision-9). Reserve a `template:` field on
  the per-repo block schema so a follow-up template library can land
  without another schema migration (Q4); the validator allows the
  field but only as `string | null` (NACK non-blocking).
- **Persist classification** by leading slash (decision-3): an entry
  starting with `/` is an absolute system dir, otherwise repo-relative.
- **Validator** exposed two ways (decision-6): an `egg validate-config`
  CLI subcommand AND a new `mcp__egg__validate_repo_config` MCP tool.
  The existing `mcp__egg__validate_config` (which validates pipeline
  configs) is **left in place under its current name** to avoid
  breaking external callers; the new repo-config tool registers under
  a distinct name (architect Q-A6 / NACK non-blocking). Two-tier
  output (decision-11): malformed YAML / missing required keys /
  legacy-schema keys / operator-scoped keys in repo file / non-existent
  `local_repos.paths` / `checks.command` referencing missing Makefile
  targets / repo-file `persist:` entries pointing at the safe-by-default
  denylist (NACK-5) → block; heuristic mismatches and runtime-injected
  values (auth tokens, network policy) → warn.
- **Validator checks** (Q5) include the issue's original list plus
  `auth_mode: user` without `GITHUB_USER_TOKEN` (warning — runtime
  injection paths exist), persist of an empty directory (warning),
  and curl/wget in build_commands when the repo runs under egg's
  network-locked private mode (warning, network-mode condition only —
  decoupled from `restrict_to_configured_users` per NACK non-blocking).
- **Repo-file allowlist (NACK-5 / risk-3 mitigation).** The merge
  layer enforces a hard-error denylist on `persist:` entries declared
  in `<repo>/.egg/repositories.yaml`: paths under `/etc`, `/root`,
  `/var`, `/home/`, `/proc`, `/sys`, `/dev`, `/.ssh`, and any path
  outside `/usr/local/`, `/opt/`, or the repo root are rejected
  outright (operators retain full freedom in the user file). This
  limits the blast radius of a malicious feature branch shipping a
  `persist: [/etc/passwd]` entry. Same denylist applies to
  `restrict_to_configured_users` and `disable_auto_fix` keys — these
  are operator-side only and rejected when present in
  `<repo>/.egg/repositories.yaml` (NACK non-blocking).
- **Auto-discovery trust model HITL (NACK-5).** A new HITL decision
  (`decision-15`) is registered in this phase asking whether
  auto-discovery should additionally require an operator-side allow on
  first encounter (direnv-style) on top of the safe-by-default
  denylist above. The plan ships the denylist as the security floor
  unconditionally; the HITL refines whether to layer opt-in on top
  before phase 2 lands.
- **Onboard skill** (decision-7) at `skills/onboard-repo/SKILL.md`. The
  skill drives detection conversationally and **always** calls
  AskUserQuestion to confirm each detected `build_command` / `persist`
  / `checks` entry (Q6). The underlying detector lives as a Python
  module so it can be unit-tested and so a plug-in escape hatch exists
  for non-conventional repos (Q7).
- **Detector languages**: Python (uv + pip), Node (npm + pnpm + yarn),
  and Go for v1 (decision-14). Rust / Java / Ruby deferred until a
  consumer surfaces.
- **Onboard fallback** when the skill cannot write to the target repo
  (decision-8): print the YAML to stdout and offer to append to
  `~/.config/egg/repositories.yaml`.
- **Egg's own config** (Q2): migrate the `jwbron/egg` block out of the
  user file's `repo_settings:` and into `<repo>/.egg/repositories.yaml`
  in this PR. Egg is the canonical first consumer of the new layered
  path and exercises it in CI.

### Why a single PR with six phases

The four pieces reinforce each other (schema simplification removes the
trap classes the validator would otherwise have to flag; the skill
emits the simplified schema; the layered model is what makes the
skill's output useful by committing it). Splitting them across PRs
means the early ones expose intermediate states that aren't reachable
under the final design. Six commit-sized phases inside one PR keeps
reviewability while still letting `git bisect` walk the diff.

### Phases & dependency tree

1. **Schema foundation** — types & schema definitions for the new
   collapsed user-facing format (`persist:` unified list, `template:`
   reserve as `string | null`, `schemaVersion: "1.0"`). Drop legacy
   `persist_dirs` / `persist_system_dirs` / explicit-only
   `watch_files` fields. Pin version-tolerance policy: known major →
   load; unknown newer major → hard-fail with diagnostic naming the
   running egg version (NACK non-blocking).
2. **Centralized layered loader** — new `shared/egg_config/repos.py`
   with `load_merged_repo_config()`. Replace-by-default merge,
   auto-discover repo file, version-tolerant, repo-file allowlist
   gate, mtime-keyed `lru_cache` (NACK non-blocking, risk-13).
3. **Wire host-side consumers to merged view** —
   `config/repo_config.py`, `sandbox/egg_lib/docker.py`. The host-side
   classifier produces the legacy `persist_dirs` + `persist_system_dirs`
   manifest shape from the unified `persist:` so
   `sandbox/docker-setup.py` is unchanged (architect C3 / NACK-1).
   Watch-files inference from a built-in manifest catalog; checks
   inference from `Makefile` / `package.json`. Regression tests for
   #2065, #2087, #2090 reproducers under the new schema (NACK-2).
4. **Validator (CLI + MCP)** — `scripts/validate-config.py` extended
   with a `--repo-config <path>` mode (reuses the existing
   secret-config validator's `✓/✗/⚠` output formatting and its test
   surface — NACK-3); new MCP tool `mcp__egg__validate_repo_config`;
   the existing `mcp__egg__validate_config` (pipeline configs) is
   left under its current name (architect Q-A6 / NACK non-blocking).
   Two-tier errors / warnings; checks (i)/(j)/(k) are warnings
   (NACK-4). Phase 4 can run in parallel with phase 3 (architect's
   `implementation_order_recommendation` — NACK non-blocking).
5. **Onboard skill + detector** — pluggable detector module under
   `shared/egg_config/onboard_detectors.py` for Python+Node+Go;
   conversational skill at `skills/onboard-repo/SKILL.md` driving
   AskUserQuestion confirmation. The skill calls
   `egg validate-config` before write (NACK non-blocking — promoted
   to acceptance).
6. **Egg-own migration + docs sweep** — TASK-6-1 (egg's
   `.egg/repositories.yaml`) depends on phases 1-3; TASK-6-2 (rewrite
   example) depends on phase 1; TASK-6-3 (integration test +
   gateway-side smoke test, NACK non-blocking) depends on TASK-3-2
   and TASK-6-1; TASK-6-4 / TASK-6-5 are docs-only and depend on
   phase 5.

### Test strategy

- **Automated unit** — `tests/shared/egg_config/test_repos.py` covers
  the merge engine (replace-by-default, version tolerance,
  auto-discover, repo-defaults-only-keys-rejected-in-user-file,
  repo-file persist-path denylist enforcement, mtime cache
  invalidation), `tests/shared/egg_config/test_onboard_detectors.py`
  covers each language detector against synthetic project trees, and
  `tests/scripts/test_validate_repo_config.py` covers each heuristic
  check (paired with golden good/bad fixtures) including the
  network-mode-only phrasing of check (k).
- **#2065 / #2087 / #2090 regression tests (NACK-2).**
  `tests/sandbox/test_docker_setup_regressions.py` pins:
  - **#2087 reproducer**: `uv sync` against a watch-files-only
    context (manifest carrying `persist_dirs: [.venv]`, watch_files
    omitting source files) — assert `RuntimeError` from
    `persist_build_dirs` matches the post-#2090 fail-loud message.
  - **#2065 reproducer**: binary installed at `/usr/local/bin/uv`
    without a covering `persist:` entry — assert (a) the validator
    surfaces the error at write-time and (b) `docker-setup.py`
    raises if it slips through.
  - Cite the original commits (514c5afaa #2087, fff9cea56 /
    aa1f5e22d #2065) in the test docstring.
- **Automated integration** — extend `integration_tests/conftest.py`
  to build a fixture repo with `.egg/repositories.yaml` + a user file
  with overrides, assert the merged view fed to
  `_copy_repo_watch_files()` matches expectations, and run
  `sandbox/docker-setup.py::run_build_commands` against the manifest
  emitted by the host classifier (still in legacy field names per
  C3). Add a gateway-side smoke test (NACK non-blocking) that
  `gateway/checkpoint_handler.py` and `gateway/gateway.py` see the
  merged view via `config/repo_config.py` after a
  `<repo>/.egg/repositories.yaml` is added.
- **Updated existing tests** — `tests/config/test_repo_config.py`
  for the renamed schema; existing test fixtures updated to the new
  user-facing shape; `tests/sandbox/test_docker_setup.py` unchanged
  on the manifest interface (C3 keeps it stable).
- **Manual** — (a) run `/onboard-repo` against a clean clone of a
  Python+uv repo, a Node+pnpm repo, and a Go repo, confirm the YAML
  matches the human's expectations; (b) run `egg validate-config` on
  egg's own freshly-checked-in `.egg/repositories.yaml` and confirm a
  clean result; (c) run it against a known-broken config (the #2065
  shape: install to `/usr/local/bin` without `persist:`) and confirm
  the validator surfaces the error before image build; (d) rebuild
  the sandbox image end-to-end with the migrated config and confirm
  `make test` and the prebuilt-deps integration suite still pass.

### Manual steps

- **Pre-merge**: reviewer confirms (1) the new
  `<repo>/.egg/repositories.yaml` checked in by this PR (egg's own
  per-repo block, migrated from the user file) parses through the new
  loader and matches the legacy block's behavior in CI; (2)
  `config/repositories.yaml.example` is rewritten to the new
  user-facing schema (no leftover `persist_dirs` /
  `persist_system_dirs` examples in the user-facing schema, but the
  manifest intentionally keeps the two-list shape internally per C3);
  (3) HITL decision-15 (auto-discovery trust model) is resolved
  before merge, with the implementation matching the resolved
  policy.
- **Post-merge**: every operator with an existing
  `~/.config/egg/repositories.yaml` must hand-edit on upgrade —
  merge `persist_dirs` + `persist_system_dirs` into one `persist:`
  list, delete explicit `watch_files` / `checks` blocks where the
  auto-detect output matches, add `schemaVersion: "1.0"` at the
  top, and delete per-repo blocks for repos that now ship their own
  `.egg/repositories.yaml`. The release notes (and a CHANGELOG
  entry added in phase 6) call out the migration steps. No DB
  migrations, no service restarts beyond the normal egg-launcher
  relaunch.

### Risks & mitigations

(Cross-references risk_analyst's full risk inventory; deferred items
are noted with their disposition.)

- **risk-1 — Sandbox image outlives launcher / manifest cross-version
  trap (NACK-1).** Mitigation: architect's C3 design adopted —
  `manifest.json` keeps the legacy `persist_dirs` + `persist_system_dirs`
  two-list shape produced by the host-side classifier from the
  unified `persist:`. `sandbox/docker-setup.py` is **not** modified.
  No manifest schema bump, no layer cache invalidation, no
  cross-version trap. Phase 3 acceptance enforces this contract.
- **risk-3 — Auto-discovery trust model (NACK-5).** Mitigation:
  hard-error denylist enforced in `shared/egg_config/repos.py` for
  repo-file `persist:` entries (paths under `/etc`, `/root`, `/var`,
  `/home/`, `/proc`, `/sys`, `/dev`, `/.ssh`, and outside the safe
  set `/usr/local/`, `/opt/`, repo root). Operator-scoped policy
  keys (`restrict_to_configured_users`, `disable_auto_fix`) rejected
  when in the repo file. New HITL decision-15 registered for whether
  to additionally require operator opt-in on first encounter; PR
  cannot merge before that resolves.
- **risk-7 — #2065 / #2087 / #2090 regressions (NACK-2).** Mitigation:
  `tests/sandbox/test_docker_setup_regressions.py` pins both
  reproducers under the new schema (see Test strategy above).
- **risk-13 — Derive-on-load adds FS scans.** Mitigation:
  `functools.lru_cache` keyed by config-file mtime in
  `shared/egg_config/repos.py`. Skip derivation paths when explicit
  `watch_files` / `checks` are present. Cache invalidation on
  SIGHUP via existing `reload_config()` hook.
- **risk-14 — Version-tolerance under-specification (NACK
  non-blocking).** Mitigation: TASK-1-1 acceptance pins the policy
  explicitly: known major → load; unknown newer major → hard-fail
  with a diagnostic naming the running egg version and the file's
  declared `schemaVersion`. No silent-degrade.
- **Hard cutover on user-facing schema breaks every existing user's
  config.** Mitigation: the validator's blocking error message on
  legacy keys quotes the exact migration steps; the example file's
  diff in this PR shows the before/after. CHANGELOG entry is the
  user-facing migration guide.
- **Skill detection produces wrong block silently.** Mitigation: Q6's
  AskUserQuestion-per-detection requirement is enforced in the skill
  prose; the detector module returns `(detection, confidence,
  reasoning)` triples so the skill can show the user *why* it picked
  a given build command. The skill calls `egg validate-config`
  before write.
- **Other risks deferred** — risk_analyst risks 2, 4, 5, 6, 8, 9, 10,
  11, 12 are tracked in the risk_analyst output; none are
  load-bearing for the plan-phase decisions and all are addressable
  inside the existing tasks (typically by acceptance-criteria
  tightening). No follow-up issues required.

### Rollback plan

If the PR ships and surfaces a regression in production:

1. **Revert the merge commit** on `main` (single PR per CLAUDE.md
   means one revert restores the pre-#2073 state).
2. **Operator-side recovery**: a sed snippet documented in the
   CHANGELOG inverts the migration (`persist:` → `persist_dirs` /
   `persist_system_dirs` based on leading-slash classification). No
   DB migrations to roll back.
3. **Image-level recovery**: because manifest format is unchanged
   (C3), no layer cache invalidation or rebuild is forced. Existing
   sandbox images keep working with the reverted launcher.
