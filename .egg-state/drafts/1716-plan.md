# Plan: BRC messages must carry substantive content (CLI + protocol enforcement)

## Summary

ACK messages are guaranteed-empty because the CLI has no slot for rationale; proposals carry only a free-form `summary`. The fix is to close the CLI/protocol asymmetry and enforce a minimum-content floor in the orchestrator so the content bar becomes a protocol-level guarantee rather than an agent-discretion one.

Approach: (a) extend `egg-orch` argparsers and payload construction for `ack` and `propose`; (b) add a `_validate_brc_content` helper in `orchestrator/routes/signals.py` and invoke it from the four BRC signal handlers before any state mutation; (c) update the reviewer/producer lifecycle text in `_build_brc_protocol_block` in `orchestrator/routes/pipelines.py` so agents learn the new CLI shapes and what substantive content looks like. The downstream enforcement bullets in the issue (overseer anomaly detection, post-consensus quality gate) are explicitly out of scope for this PR — they are tracked separately on #1717/#1718.

**Risks / edge cases**: Making `--reason` required on `ack` breaks any mid-flight agent — mitigated by the fact that agents are stateless per run and new pipelines use the new prompt + CLI together, so error messages must be loud. Boilerplate regex must be kept small and conservative (exact-match, case-insensitive) to avoid false positives against legitimate short rationales; the length floor (≥50 chars) is the primary bar. Content validation must run on the re-propose path as well (`changed_artifacts` branch in `handle_consensus_propose_signal`). `consensus withdraw` already requires `--reason` at the CLI but still needs to pass through the content validator. The reviewer/producer prompt text must match the new CLI shapes exactly so agents' commands don't get rejected by the validator.

## Implementation

### Phase 1: Implement

Close the CLI/protocol asymmetry and add a content-floor validator. Update agent-facing prompts to match.

**Tasks**:
1. **[task-1-1]** In `sandbox/bin/egg-orch`, add `cons_ack.add_argument("--reason", required=True, help="Substantive rationale: what was read, what was checked, why the verdict follows")` to the `ack` parser (near line 1848), and in `cmd_consensus_ack` (line 1305-1308) add `"reason": args.reason` to the payload dict alongside `artifact_references`. Also extend the `propose` parser (near line 1811-1834) with `--commit`, `--files-changed` (nargs="*"), `--tests-run` (nargs="*"), `--tasks` (nargs="*"), and fold them into the payload in `cmd_consensus_propose` (after line 1267) under keys `commit`, `files_changed`, `tests_run`, `tasks_satisfied`. Acceptance: `egg-orch consensus ack` fails argparse without `--reason`; `egg-orch consensus propose` accepts the new args and serializes them into the signal payload.
2. **[task-1-2]** In `orchestrator/routes/signals.py`, add a module-level `_validate_brc_content(body: str, kind: str) -> str | None` helper returning an error message (or `None`) when `body.strip()` is empty, shorter than a configurable `_BRC_MIN_CONTENT_LEN = 50`, or matches a short case-insensitive exact-match boilerplate list (`{"lgtm", "looks good", "no issues", "approved", "ok"}`). Invoke it at the top of `handle_consensus_propose_signal` (validate `payload["summary"]`), `handle_consensus_ack_signal` (validate `payload["reason"]`), `handle_consensus_nack_signal` (validate `payload["reason"]`), and `handle_consensus_withdraw_signal` (validate `reason`). On failure, return `make_error_response(<reason>, 400)` **before** touching the tracker or message store (no partial state). The re-propose path (when `changed_artifacts` is present) must also pass through validation. Acceptance: each handler rejects empty/short/boilerplate content with a 400 and does not mutate state; substantive content passes through unchanged.
3. **[task-1-3]** In `orchestrator/routes/pipelines.py` `_build_brc_protocol_block`, update the producer lifecycle line at 5336-5337 to describe the new propose args (`--summary`, `--commit`, `--files-changed`, `--tests-run`, `--tasks`, `--artifacts`) and describe what substantive proposal content looks like (what was built, what was tested, which contract tasks it satisfies, ≥50 chars). Update the reviewer lifecycle lines at 5366-5367 to require `--reason "<rationale>"` on `ack` and describe what substantive review content looks like (what was read, what was checked, why the verdict follows, ≥50 chars). Acceptance: the rendered BRC protocol block produces commands whose argument shapes pass `_validate_brc_content`, and explains the content bar to agents.
4. **[task-1-4]** Add tests covering: in `sandbox/tests/` — (a) `egg-orch consensus ack` exits non-zero when `--reason` is missing, and threads the reason into the payload when present; (b) `egg-orch consensus propose` accepts `--commit`, `--files-changed`, `--tests-run`, `--tasks` and includes them in the payload. In `orchestrator/tests/` — (a) `_validate_brc_content` unit tests for empty, whitespace-only, <50-char, boilerplate, and substantive inputs; (b) integration-style tests per handler (`propose`, `ack`, `nack`, `withdraw`) confirming a 400 return and no message-store write on validation failure, and a 200 on success; (c) re-propose (with `changed_artifacts`) is subject to the same validation. Acceptance: all new tests pass; existing BRC tests still pass or are updated in-place to supply valid content.
