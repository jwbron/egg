# Plan: Fix restart review items from PR #1577

## Summary

Fix 7 non-blocking issues identified during review of the agent restart PR #1577, tracked in GitHub issue #1695. The approach follows the issue's suggested implementation order (1→4→2+3→5→6→7), grouped by file to minimize conflicts. The key structural change is eliminating the overseer's shadow restart counter in favor of reading the spawner's authoritative count from the REST API response — this unifies tracking and auto-resolves the phase-keying bug. Incrementing the restart count before the spawn attempt (issue 4 fix) means a transient Docker failure burns one restart attempt — this is the correct tradeoff since the alternative is infinite retries. Moving consensus reset after spawn (issue 5) means a successful spawn with a failed consensus reset leaves stale consensus state, but this is recoverable (the restarted agent re-enters consensus).

**Risks / edge cases**: Lock granularity for issue 1 must be per-(pipeline_id, role) to avoid contention across unrelated restarts. Issue 6 must be conservative about which infra errors are "restartable" — only unresponsive/crashed/OOM/timeout, not permission/filesystem errors.

## Implementation

### Phase 1: Implement

Fix all 7 restart review items grouped by file, plus comprehensive tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/container_spawner.py`, add a per-`(pipeline_id, agent_role)` `threading.Lock` guarding `_restart_counts` access in `restart_agent_container()`, `get_restart_count()`, and `reset_restart_counts()`. Follow the `state_store.py:get_pipeline_state_lock` pattern (a module-level dict of locks protected by a global lock). Also increment `_restart_counts` *before* `spawn_agent_container()` (currently at L867, move to before L847) so failed spawns count toward the limit. Also change the `mode` parameter default from `"public"` to `None` at L748 and raise `ValueError("mode must be explicitly provided")` if `mode is None`. Acceptance: concurrent restart calls are serialized; failed spawns increment count; missing mode raises ValueError.
2. **[task-1-2]** In `orchestrator/overseer/monitor.py:_execute_restart_agent()`, remove `self._agent_restart_counts` (L121) and `self._max_agent_restarts` (L122). Instead, read `restart_count` from the REST API response at L713 (which already returns restart count info). For the "restart limit reached" check (L658-691), attempt the restart and handle the error response indicating limit exceeded — the spawner is now the single source of truth. Remove all reads of `self._agent_restart_counts` (L658, L668-671, L716). This also resolves issue 3 automatically since the spawner's counts are properly reset per-phase via `reset_restart_counts()`. Acceptance: overseer has no independent restart counter; limit enforcement comes from the spawner via the REST API.
3. **[task-1-3]** In `orchestrator/routes/pipelines.py:restart_agent`, move the consensus reset block (L1249-1292) to after the successful `spawner.restart_agent_container()` call at L1386-1398. If spawn raises `ContainerSpawnError`, consensus state is preserved (no change needed). If spawn succeeds but consensus reset fails, log a warning but don't fail the restart (the restarted agent will re-enter consensus). Acceptance: consensus is only reset after successful container spawn; failed spawn preserves consensus state.
4. **[task-1-4]** In `orchestrator/overseer/decision_maker.py:decide_corrective_action()`, replace the blanket HITL fast-path (L59-66) with a check that parses the `reasoning` field for restartable subcategories. Define `RESTARTABLE_PATTERNS = ["unresponsive", "crashed", "oom", "timeout", "hung", "not responding"]`. If any pattern matches (case-insensitive) in `reasoning`, return `{"action": "restart_agent", ...}` instead of `"hitl"`. Keep non-matching infrastructure errors on the HITL path. Apply the same logic in `escalate_redirect_decision` (L140-150). Acceptance: infrastructure errors matching restartable patterns produce `restart_agent` action; non-matching infra errors still produce `hitl`.
5. **[task-1-5]** Add/update tests in `orchestrator/tests/test_restart_agent.py` and `orchestrator/tests/test_restart_overseer.py`: (a) concurrent restart race — two threads calling `restart_agent_container` simultaneously, only one succeeds past the limit; (b) failed spawn increments count — mock `spawn_agent_container` to raise, verify count incremented; (c) mode=None raises ValueError; (d) consensus reset ordering — mock spawn to raise, verify consensus reset was NOT called; (e) overseer reads count from API response, no shadow counter; (f) decision_maker routes "unresponsive"/"crashed" to restart_agent, routes "permission denied" to hitl. Acceptance: all new tests pass; all existing tests pass.
