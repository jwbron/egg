## Goal

egg's documentation has drifted from a **snapshot of current state** into a
**ledger of changes** — process artifacts (slice numbers, `TASK-N` ids,
phase/HITL iteration numbers, "what was removed in #NNNN") interleaved with the
description of how the system works today. Two coupled work streams fix it:

1. **Change the documenter agent** so it produces snapshots, not ledgers — its
   task instructions (assembled in `orchestrator/routes/pipelines.py`) and role
   definition (`shared/egg_contracts/agent_roles.py`) currently frame the job as
   documenting *the change*. Reframe to current-state, with a hard rule against
   emitting SDLC artifacts in any doc/docstring/comment it writes.
2. **Clean the existing corpus** — a bounded pass over `docs/`, `**/CLAUDE.md`,
   `**/README.md`, and code docstrings/comments to strip slice/TASK/process-ledger
   references and rewrite change-log prose into current-behavior descriptions.

This is **not** "delete all issue references": issue links that justify *why the
current system is shaped the way it is* stay (reframed as rationale). The line is
chronology-as-default vs. rationale-where-valuable.

## Binding constraints (carried from refine + the issue)

- **Preserve the documenter's gateway file boundaries** — `allowed_write` =
  `docs/`, `**/README.md`, `**/*.md`, `.egg-state/agent-outputs/`; `blocked_write`
  blocks code/tests/`.github/`. Only the *wording* of the role/prompt changes,
  never the write boundaries (`shared/egg_contracts/agent_roles.py`
  `DOCUMENTER_ROLE`).
- **Preserve the BRC no-op / no-doc-impact propose path.** The
  `### When the slice warrants no doc updates (#3027)` block
  (`pipelines.py` ≈14800) and the plan-phase no-op branch (≈14157) must keep
  instructing a generic `consensus propose --no-changes-needed`.
- **Docs are a snapshot, never a ledger of how the work was sequenced** —
  including *this* pipeline's own slices. The cleanup's commits/PRs carry the
  process context in their messages; the docs they touch must not.

## Role/file split (verified via `check_file_restriction`, phase=implement)

The load-bearing slicing constraint: the documenter role is **blocked from
`**/*.py`**, so within the per-package cleanup slices the work splits by file
type:

- **Markdown** (`docs/`, `**/CLAUDE.md`, `**/README.md`) → **documenter**.
- **Python docstrings / inline comments** (`.py`) → **coder** (documenter
  `can_write=false` on `.py`; `alternative_role=coder`).
- **Prompt-assembly source + role definition** (`pipelines.py`,
  `agent_roles.py`) are `.py` → **coder**; their tests → **tester**.

This is why slices 4 and 5 (gateway, orchestrator) each carry a coder task (the
`.py` docstrings) and a documenter task (that package's `CLAUDE.md`).

## Live-machinery vs. archaeology (scope guard for the `.py` sweep)

A grep for `slice-N` / `TASK-N` over `.py` overcounts badly: `pipelines.py`
alone has ~153 hits, most of which are **live machinery** — the prompt strings
the orchestrator assembles, and `TASK-N` as a parsed plan-format type
(`plan_parser.py`), slice scheduling, and `event_prompt.py` runtime slice
handling. Those describe the system *as it works today* and are **out of scope
to strip**. In scope is **archaeology**: docstrings/comments that narrate *when*
something landed ("added in #3064 slice-2", "the slice-8 gate", "#3077 slice-4").
The coder applies the chronology-vs-current-concept line per file.

## Slice DAG (architect's design)

```
slice 1 (documenter agent → snapshot doctrine)        ← root, establishes the standard
   ├─> slice 2 (architecture docs, line-edit)          documenter
   ├─> slice 3 (architecture docs, total-refactor)     documenter
   ├─> slice 4 (gateway: .py docstrings + CLAUDE.md)   coder + documenter
   ├─> slice 5 (orchestrator: .py docstrings + CLAUDE.md) coder + documenter
   └─> slice 6 (shared: .py docstrings + bounded sweep) coder + documenter
```

Slice 1 is the single root: it lands the go-forward standard before the corpus
is cleaned against it. Slices 2-6 each depend only on slice 1 (forest, ≤1 parent
each) and are **mutually file-disjoint** — each owns a distinct package or doc
area — so they run in parallel without colliding (#3046). The split between
slice 2 (sentence-level line edits) and slice 3 (pages whose ledger framing is
load-bearing, needing a full rewrite) isolates the highest-judgment work.
