# Plan: Phase-aware stall detection with BRC-idle suppression

## Summary

Add phase-aware stall detection thresholds and BRC-idle suppression to the Tier 1 health monitor. The implement phase gets a separate, higher timeout (default 600s) so legitimate deep implementation work isn't flagged. Agents correctly idle in BRC protocol (waiting for an upstream producer to propose) are excluded from heartbeat/progress checks entirely. This fixes the false-positive alerts observed in pipelines `issue-1523-v2` and `issue-1527`.

**Risks / edge cases**: Genuinely stuck agents in the implement phase will take longer to detect (~10 min vs ~2 min), but the Tier 2 overseer LLM classifier provides a secondary detection layer. BRC suppression must only apply while the upstream producer is in `WORKING` — once the producer has `PROPOSED`, reviewers resume normal monitoring. The `set_current_phase()` call must happen before agents spawn for each phase.

## Implementation

### Phase 1: Implement

Add phase-aware thresholds and BRC-idle suppression to the health monitor.

**Tasks**:
1. **[task-1-1]** In `orchestrator/models.py:PipelineConfig`, add `orchestrator_implement_heartbeat_timeout_seconds: int = Field(default=600, ge=10, description="Seconds without heartbeat/progress before auto-nudge during implement phase")`. Acceptance: Field exists with default 600, validated ≥10.
2. **[task-1-2]** In `orchestrator/health_monitor.py:HealthMonitor`, add a `_current_phase: str | None = None` instance variable and a `set_current_phase(phase: str) -> None` method. In both `check_heartbeats()` and `check_progress()`, replace `threshold = self._config.orchestrator_heartbeat_timeout_seconds` with logic that selects `orchestrator_implement_heartbeat_timeout_seconds` when `self._current_phase == "implement"`, falling back to the default threshold otherwise. Acceptance: During implement phase, threshold is 600s; during other phases, threshold remains 120s.
3. **[task-1-3]** In `orchestrator/health_monitor.py:HealthMonitor.check_heartbeats()` and `check_progress()`, before escalating an agent, query the peer consensus tracker (`peer_consensus.get_peer_consensus_tracker(self._pipeline_id)`) and check if the agent is a reviewer-only role whose upstream producers are all still in `WORKING` phase. If so, skip the escalation for that agent. Import the tracker lazily (try/except ImportError) to avoid circular imports. Acceptance: Agents waiting for an upstream producer's proposal do not trigger alerts.
4. **[task-1-4]** In `orchestrator/routes/pipelines.py`, at each phase transition (where the pipeline's `current_phase` is updated), call `health_monitor_instance.set_current_phase(phase_name)` to keep the threshold in sync. Acceptance: `set_current_phase()` is called before agents are spawned for each phase.
5. **[task-1-5]** In `orchestrator/tests/test_health_monitor.py`, add tests: (a) verify implement-phase threshold uses `orchestrator_implement_heartbeat_timeout_seconds`; (b) verify non-implement phases use the default threshold; (c) verify BRC-idle agents are suppressed from heartbeat/progress alerts; (d) verify BRC agents resume normal monitoring after producer proposes. Acceptance: All new tests pass.
