# Plan: babysit-pr — run a one-off implement-phase BRC cycle against the PR diff

> Issue: #1748 | Phase: plan | Approach: Option A (in-place mode-aware reuse)

## Strategy

The refine analysis (`.egg-state/drafts/1748-analysis.md`) lays out four
options and recommends **Option A**: extend the existing implement-phase
code path with a `babysit_pr` `PipelineMode` rather than fork a new phase
or vendor BRC inside `shared/egg_babysit/`. This plan executes Option A
in eight phases, organised so each phase is independently testable and
can be reviewed as a discrete commit on the single PR for this issue.

The plan assumes a default answer for each open Decision and Feedback
item documented in the analysis so that task breakdown can proceed
without blocking; the `pr.description` block at the bottom flags the
defaults the human should confirm or override at PR-review time. If a
HITL response lands during implementation that disagrees with a default,
the affected phase(s) can be re-scoped via `egg-contract update-notes`
without restructuring the rest of the plan.

### Default answers used in this plan

| Item | Plan default | Rationale |
|---|---|---|
| Decision 1 (PipelineMode migration) | Add `BABYSIT_PR`; keep `BABYSIT` as deprecated alias for one release | Safer for any persisted pipeline state or external automation that may currently send `mode=babysit`. |
| Decision 2 (no-contract signal) | Pass `pipeline.mode` into `get_roles_for_phase()` and filter inline | No new model field; keeps the route handler lean; `agent_roles.py` already holds roster knowledge. |
| Decision 3 (MCP-skill scope) | Lean form (PR number + single confirmation, then watch) | Smallest first cut; matches `shared/egg_babysit/cli.py`'s current UX; full `/sdlc`-style flow can land in a follow-up. |
| Decision 4 (mid-cycle human commits) | Detect on each NACK round; if PR head moved, abort with HITL escalation | Cheaper than always-rebase; avoids racing with humans without throwing away half the cycle. |
| Decision 5 (`conflict_resolver` policy) | On-demand only — producers detect overlap during their own resolution and request the role | Matches the analysis's "rare overlap" framing; no new pre-flight step every cycle. |
| Decision 6 (base-branch sweep) | Full sweep — fix every hardcoded `origin/main` in production code paths reachable from any PR-aware flow | Without it, babysit-pr is silently incorrect for non-`main` PRs; deferring is a known-correctness regression. |
| Decision 7 (orient-builder refactor) | Inline mode branch (Option A); defer per-mode template refactor | No third mode is on the immediate roadmap; refactor cost unjustified now. |
| Feedback 1 (other reviewer pre-filters) | `reviewer_agent_design` and `reviewer_refine` are not in `_PHASE_REVIEWERS["implement"]` today, so no extra filter needed; capture as comment | Inspecting `agent_roles.py:978-990` confirms only `REVIEWER_CODE` and `REVIEWER_CONTRACT` are implement-phase reviewers. The `EGG_ONLY_REVIEWERS` filter (`:996`) is orthogonal. |
| Feedback 2 (fork-PR UX) | Fail-fast with stderr error AND post a one-line PR comment explaining the limitation | Cheap, observable, no HITL required for an unrecoverable case. |
| Feedback 3 (concurrency / pipeline-id collisions) | Pipeline-id format `pr-{N}-{short-sha}` where `short-sha` is the PR head SHA at invocation time | Naturally disambiguates concurrent invocations; deterministic for a given head. |
| Feedback 4 (scope-expansion guardrails) | Soft orient-prompt hint ("prefer focused improvements within the diff's neighbourhood; explain large refactors"); no hard cap | Trust the role prompts per issue intent; avoid first-cut over-policing. |
| Feedback 5 (BRC-history identifier) | Use the same `pr-{N}-{short-sha}` identifier for `_write_brc_history` | Keeps history files unique per cycle; aligns with pipeline-id. |
| Feedback 6 (CLI removal vs deprecation shim) | Remove `egg-babysit` console script entirely; document migration in the same PR | Issue says "remove the existing fixer/reviewer-based loop"; the CLI has no external automation in the repo (Makefile, scripts/, .github/ all clean per survey). |

### Test strategy (overview)

- **Automated unit tests** (under `orchestrator/tests/` and `shared/tests/`):
  - `get_pr_base_branch()` helper: present, missing, fork, base != `main`.
  - `get_roles_for_phase("implement", mode=PipelineMode.BABYSIT_PR)` filters out `REVIEWER_CONTRACT`.
  - `_build_reviewer_preparation()` and `_build_producer_orientation()`: emit babysit-pr-specific text when `mode == babysit_pr`, leave issue-mode text unchanged.
  - Staging-branch derivation in `concurrent_executor.py`: produces `egg/babysit-pr/{pr-num}/{short-sha}/{role}` from PR head; falls back cleanly if PR closed.
  - Early-exit checks: PR merged, PR closed, empty diff, fork PR.
  - Pipeline-id format: `pr-{N}-{short-sha}` is what the route handler chooses for babysit-pr mode without an explicit override.
  - BRC-history identifier propagation through `_write_brc_history()` call site.
  - Hardcoded `origin/main` parameterization: each touched call site accepts a base ref and uses it.
- **Automated integration tests** (`integration_tests/test_babysit_pr/`):
  - Rewrite the legacy babysit-pr integration tests to drive the new BRC flow end-to-end (create pipeline → spawn implement-phase agents → reach consensus → push final commit to PR head).
  - Cover the fork-PR early-exit and the empty-diff early-exit paths.
- **Manual verification** (reviewer / human):
  - Trigger `babysit-pr` against a real PR with a base != `main` and confirm orientation prompts and diff calls use the right base.
  - Trigger against an already-merged PR; confirm clean early-exit with stderr message.
  - Confirm legacy `egg-babysit` console script is gone and that the new `babysit-pr` MCP skill works under `/babysit-pr`.

### Manual pre/post-merge steps

- **Pre-merge**: none — no DB migrations, no config schema changes, no env-var changes. The new `BABYSIT_PR` enum value is additive and the deprecated `BABYSIT` alias preserves any in-flight pipeline state.
- **Post-merge**: announce the deprecation of `egg-babysit` CLI on the team's deprecation channel; confirm no scheduled jobs invoke it (Makefile / scripts / `.github/workflows/` are already clean per code survey, but flag for awareness).

## Phases

### Phase 1 — Foundation: PR base-branch parameterization

**Goal.** Eliminate every hardcoded `origin/main` in production code paths reachable from any PR-aware flow, behind a single named helper. This is preparatory work that babysit-pr depends on, and it is also a correctness fix for any future non-`main` based PR even outside babysit-pr.

Sites to fix (from refine analysis + survey):
- `orchestrator/routes/pipelines.py:6046, 6048` (reviewer-code orient prompt)
- `orchestrator/routes/pipelines.py:6732, 6735, 6760, 6763` (coder prompts: clean-branch creation, merge target)
- `orchestrator/health_checks/tier1/phase_output.py:175, 185` (`_branch_has_new_commits` + the `git rev-list` invocation)
- `orchestrator/health_checks/context.py:110-113` (diff-stat health check)

Existing helpers to consolidate behind:
- `orchestrator/routes/pipelines.py:2972, 3119` (inline `f"origin/{base_branch}" if base_branch else "origin/main"`)
- `orchestrator/routes/pipelines.py:5855` (`branch or base_branch or "main"`)
- `orchestrator/routes/pipelines.py:4145-4202` (`_detect_default_branch()`)

### Phase 2 — `PipelineMode.BABYSIT_PR` + no-contract roster filter

**Goal.** Introduce the new mode value and teach `get_roles_for_phase()` to skip reviewer roles whose upstream artifacts are absent in babysit-pr mode (today: `REVIEWER_CONTRACT`).

### Phase 3 — Mode-aware orientation prompts

**Goal.** Extend the per-role orient-prompt builders so reviewers in babysit-pr mode read `base...head` of the PR and producers rebase/merge `pr.base.ref` and resolve conflicts within their own role scope.

### Phase 4 — Staging-branch isolation + pipeline-route plumbing

**Goal.** Producers and reviewers operate on a per-cycle staging branch derived from the PR head; only the final consensus commit is pushed to the PR branch. Wire up the new `BABYSIT_PR` mode through the pipeline-creation route, including pipeline-id format and early-exit cases.

### Phase 5 — BRC-history identifier disambiguation + mid-cycle commit detection

**Goal.** BRC history files for babysit-pr cycles do not collide across re-invocations on the same PR; concurrent agents bail out cleanly if the human pushes a new commit to the PR mid-cycle.

### Phase 6 — `babysit-pr` MCP skill (lean form)

**Goal.** New skill that takes a PR number/URL, confirms once, creates the pipeline via the orchestrator REST API, and watches it.

### Phase 7 — Remove legacy `shared/egg_babysit/` package and tests

**Goal.** Delete the legacy fixer/reviewer loop, its console-script entry, its unit tests, and rewrite the integration test suite to exercise the new BRC-driven path.

### Phase 8 — Documentation

**Goal.** Rewrite the babysit-pr guide for the new flow; update other doc pages that reference the legacy CLI; refresh `docs/index.md`.

## Dependency Ordering

```
Phase 1 ─┬─> Phase 2 ─> Phase 3 ─> Phase 4 ─> Phase 5 ─> Phase 6 ──┐
         │                                                          │
         │                                                          ├─> Phase 7 ──> Phase 8
         │                                                          │
         └──────────────────────────────────────────────────────────┘
```

Phase 1 unblocks every later phase that touches orient prompts or
diff-based health checks. Phases 2–5 build the orchestrator-side babysit-pr
machinery sequentially. Phase 6 (skill) only depends on Phase 4 for the
route surface. Phase 7 (deletion) must come after Phases 2–6 so the new
flow is in place before the old one is removed. Phase 8 (docs) depends
on Phase 7 because doc copy describes the new and only flow.
