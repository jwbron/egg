# Plan: Async container cleanup on cancel

## Summary

Make the PATCH handler in `update_pipeline()` return immediately after marking the pipeline as cancelled, cancelling decisions, and syncing state records. Move the slow container/worktree cleanup to a background thread. The DELETE handler already re-runs `cleanup_pipeline()` as a safety net, so it will catch anything the background thread hasn't finished. Add a `cleanup_pending` field to the response so callers know async cleanup is in progress.

**Risks / edge cases**: The DELETE call from `_handle_cancel_task` may arrive while the background thread is still cleaning up — this is safe because `cleanup_pipeline()` is idempotent (already handles `ContainerNotFoundError`). `_mark_pipeline_records_terminated()` runs before returning the response, so state is accurate. Thread errors are already handled with best-effort try/except.

## Implementation

### Phase 1: Implement

Move synchronous container cleanup in the PATCH cancel path to a background thread so the HTTP response returns immediately.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py:update_pipeline()` (lines 841-863), move the `spawner.cleanup_pipeline()` call into a daemon `threading.Thread` so the PATCH response returns immediately after decision cancellation and state sync. The thread should use the same best-effort error handling pattern already in place. Reorder so `_mark_pipeline_records_terminated()` runs before the response (keeping state accurate), and container cleanup happens in the background after. Acceptance: PATCH returns before `spawner.cleanup_pipeline()` completes.
2. **[task-1-2]** In `orchestrator/routes/pipelines.py:update_pipeline()` (lines 885-888), add `cleanup_pending: true` to the response data dict when the pipeline status is cancelled or failed, so callers know async cleanup is in progress. Acceptance: Response JSON includes `cleanup_pending: true`.
3. **[task-1-3]** Add tests in `orchestrator/tests/` to verify: (a) `update_pipeline` PATCH with `status: cancelled` returns before container cleanup completes (mock `cleanup_pipeline` with a sleep/delay and verify response arrives first), (b) the response includes `cleanup_pending: true`, (c) container cleanup still runs to completion in the background (verify mock was called). Acceptance: Tests pass and cover the async behavior.
