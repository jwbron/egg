# Plan: Add diagnostic logging for PR-phase BRC history and draft cleanup

## Summary

Add comprehensive INFO-level diagnostic logging to the four functions involved in PR-phase state file management (`_write_brc_history`, `_commit_statefiles_to_worktree`, `_rewrite_brc_history_for_pr`, `_cleanup_drafts_for_pr`) and the PR-phase handler's push block. This instrumentation will identify which early-return path is being taken on the next pipeline run. Additionally, add an integration test proving the functions are called from the PR-phase handler and produce commits (closing the test gap identified in the issue), and promote silent failure logging from DEBUG to WARNING.

**Risks / edge cases**: Logging additions are low-risk (executed once per pipeline at PR time, not in hot loops). The integration test uses a real git repo in tmp_path, avoiding mock-based false confidence. No behavioral changes to production code — only log level promotions and new log statements.

## Implementation

### Phase 1: Implement

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py:_write_brc_history()` (line 4122), add INFO-level logs at function entry (with pipeline_id, phase, identifier), at each early-return point (message store unavailable, no messages, no BRC messages for phase), and at function exit (with file path and message count). Acceptance: running a pipeline produces INFO logs showing whether `_write_brc_history` entered and which path it took.
2. **[task-1-2]** In `orchestrator/routes/pipelines.py:_commit_statefiles_to_worktree()` (line 3755), add INFO-level logs for: glob match count and matched paths (line ~3802), staged/not-staged outcome after `git diff --cached` (line ~3830), and commit success. Acceptance: running a pipeline produces INFO logs showing how many files were matched, whether anything was staged, and whether the commit succeeded.
3. **[task-1-3]** In `orchestrator/routes/pipelines.py:_rewrite_brc_history_for_pr()` (line 4193), add INFO-level log at entry with the count of COMPLETE phases being processed, and at exit with outcome. In `_cleanup_drafts_for_pr()` (line 2401), add INFO-level log at entry with match count, per-file git rm outcome, and at exit with commit result. Promote the commit failure log at line 2478 from `logger.debug` to `logger.warning`. Acceptance: INFO logs trace function entry/exit; commit failure is visible at WARNING level.
4. **[task-1-4]** In `orchestrator/routes/pipelines.py` PR-phase handler (lines 8228-8252), add INFO-level logging after the push attempt reporting success/failure with the number of local commits ahead of remote. Also log when the push is skipped due to `worktree_repo_path == repo_path`. Acceptance: INFO logs show push outcome with commit count delta.
5. **[task-1-5]** Add integration test in `orchestrator/tests/test_pr_phase_brc_rewrite.py` that creates a real git repo with tracked draft files and BRC messages, then calls `_rewrite_brc_history_for_pr` followed by `_cleanup_drafts_for_pr`, and asserts: (a) a commit with message containing "Persist BRC history" exists, (b) a commit with message containing "Remove pipeline draft" exists, (c) BRC history files are in the committed tree, (d) draft files are not in the committed tree. Acceptance: `pytest orchestrator/tests/test_pr_phase_brc_rewrite.py` passes with the new integration test.
