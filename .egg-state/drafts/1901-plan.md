# Plan: Coder file-boundary policy — blocklist-complement rewrite

> Issue: #1901 | Phase: plan | Base: HITL-resolved refiner analysis (Option A)

## Approach

The refine phase landed on **Option A** from the analysis: rewrite
`CODER_PATTERNS` with an explicit catch-all (`allowed_patterns=["**"]`)
and rely on `blocked_patterns` + `block_exempt_patterns` to carve out
tester/documenter/pipeline-state scopes. The matcher's deny-all-when-
`allowed_patterns`-is-empty invariant stays untouched so every other
role's backstop is preserved. In the same PR we also:

1. Fix the pre-existing `_matches_pattern` bug that lets nested test
   directory files (e.g. `gateway/tests/__init__.py`) leak past
   directory patterns of the form `**/tests/` (decision 5).
2. Update `.egg/phase-permissions.json` so its role-based
   `file_restrictions` section mirrors the new three-role model
   (coder/tester/documenter) rather than the legacy single
   `implementer` entry (feedback Q1).
3. Add a `TODO(#1903)` comment to both `patterns.py` and
   `shared/egg_container/__init__.py::_IMPLEMENT_READONLY_DIRS`
   noting the three-surface sync requirement (feedback Q2).
4. Update tests in `shared/tests/test_egg_restrictions.py` and
   `gateway/tests/test_agent_restrictions_patterns.py` to cover the
   new behaviors: extensionless files are coder-writable, nested test
   directories are fully blocked, `.egg-state/` is blocked with
   `.egg-state/agent-outputs/` still permitted, and `skills/` stays
   coder-owned.
5. Update `docs/reference/agent-roles.md` to describe the new
   mutual-exclusion model.

**Out of scope for this PR** (per refine HITL):

- `AUTOFIXER_PATTERNS` and `CONFLICT_RESOLVER_PATTERNS` rewrites
  (decision 2 — follow-ups will be filed separately if needed).
- `OVERSEER_PATTERNS` rewrite (decision 4 — already tracked as
  #1902).
- Making `patterns.py` the single source of truth so
  `phase-permissions.json` and `_IMPLEMENT_READONLY_DIRS` derive from
  it (feedback Q2 — tracked as #1903). We keep the three surfaces in
  sync manually in this PR and annotate with `TODO(#1903)`.
- Preemptively blocking hypothetical future `.egg-state/` subdirs
  (feedback Q3 — not needed; the catch-all `.egg-state/` block plus
  the `agent-outputs/` exemption already covers any new subdir).

## Phase breakdown

### Phase 1 — Policy rewrite

Rewrite `CODER_PATTERNS` and (in the same file) tighten the
`_matches_pattern` directory-pattern branch so nested test files no
longer leak past blocklist entries like `**/tests/`.

- Rewrite `CODER_PATTERNS.allowed_patterns` to `["**"]`.
- Rewrite `CODER_PATTERNS.blocked_patterns` to cover: `.egg-state/`,
  `docs/`, `**/*.md`, `**/README.md`, `tests/`, `test/`,
  `**/tests/`, `**/test/`, the test-file-name patterns (`**/*_test.py`,
  `**/test_*.py`, `**/*_test.go`, `**/test_*.go`, `**/*.test.{ts,tsx,js,jsx}`,
  `**/*.spec.{ts,tsx,js,jsx}`), and `**/conftest.py`.
- Rewrite `CODER_PATTERNS.block_exempt_patterns` to: `.egg-state/agent-outputs/`,
  `sandbox/agent-config/rules/*.md`, `sandbox/agent-config/commands/*.md`,
  `skills/`.
- Update the dataclass's `description` to reflect
  "everything not owned by tester/documenter/pipeline-state".
- Add a `# TODO(#1903): keep in sync with
  shared/egg_container/__init__.py::_IMPLEMENT_READONLY_DIRS and
  .egg/phase-permissions.json until #1903 unifies these surfaces.`
  comment above `CODER_PATTERNS`.

### Phase 2 — Matcher bug fix

Fix `AgentFilePattern._matches_pattern` so patterns of the form
`**/<dir>/` (directory patterns under the `**` branch) match any file
under a nested directory of that name.

- Today the `**` branch splits on `**` and then checks the split's
  suffix via `fnmatch` on the *basename* of `file_path`. A pattern like
  `**/tests/` becomes `("", "/tests/")`, and the suffix branch drops
  the trailing slash, leaving `"tests/"` which `fnmatch` tests against
  the basename (e.g. `"__init__.py"`), so the match fails.
- Fix: when the pattern ends with `/`, treat it as a directory prefix
  and check whether the normalized `file_path` contains that segment
  anywhere in its path when the pattern starts with `**/`, or begins
  with that prefix when the pattern is a bare directory (`foo/`).
- Behavior change is limited to patterns that end with `/`. File-name
  patterns (`**/*.py`, `**/*.test.ts`, …) keep their current behavior.
- Preserve the existing `_normalize_path` path-traversal defence.

### Phase 3 — Sync gateway `phase-permissions.json`

Update `.egg/phase-permissions.json` so the `file_restrictions` array
reflects the three-role model.

**Matcher caveat (verified in `gateway/phase_filter.py:94`).** The
`FileRestriction.is_file_blocked` method does
`normalized.startswith(pattern)` — NOT `fnmatch` — so glob patterns
like `**/*.md`, `**/tests/`, `**/*_test.py`, `**/conftest.py`, and
`**/*.test.ts` are dead entries at this layer. They do nothing. The
authoritative glob matcher lives in
`shared/egg_restrictions/patterns.py::AgentFilePattern._matches_pattern`
(the agent-push layer), which already enforces glob exemptions for
the coder/tester/documenter patterns we're rewriting. Therefore the
`phase-permissions.json` entries in this PR use **prefix-only**
patterns — the phase_filter layer only needs to enforce coarse
directory blocks, and patterns.py handles the glob-level exemptions
at push time.

- Replace the single `implementer` entry with three entries using
  prefix-only patterns:
  - `coder` — blocked: `.egg-state/contracts/`, `docs/`, `tests/`,
    `test/`.
  - `tester` — blocked: `.egg-state/contracts/`, `docs/`.
  - `documenter` — blocked: `.egg-state/contracts/`, `tests/`,
    `test/`.
- Each entry's `description` field is prefixed with
  `"TODO(#1903): prefix-only blocks; glob exemptions enforced by
  CODER_PATTERNS / TESTER_PATTERNS / DOCUMENTER_PATTERNS in
  shared/egg_restrictions/patterns.py."`.
- **Keep the legacy `implementer` entry unchanged** (blocked_patterns
  = `[".egg-state/contracts/"]`). Rationale: the gateway's
  `check_file_restrictions` matches role names exactly, and sessions
  now carry the fine-grained role (`coder`/`tester`/`documenter`)
  from `session.agent_role` — NOT the coarse `implementer` — so the
  `implementer` entry is effectively a dead-weight back-compat
  record. Retaining it costs nothing and guards any future call-site
  that still passes `"implementer"`. The new three entries are what
  actually enforce at push time.

### Phase 4 — Sync `_IMPLEMENT_READONLY_DIRS`

The in-container readonly-mount list is already consistent with
Option A's blocklist (`contracts`, `drafts`, `pipelines`, `reviews`).
The only change is an annotation:

- Add `# TODO(#1903): keep in sync with CODER_PATTERNS.blocked_patterns
  in shared/egg_restrictions/patterns.py and .egg/phase-permissions.json

### Phase 5 — Tests

Add and update tests covering the new behavior. The bulk of tests
live in `shared/tests/test_egg_restrictions.py` and
`gateway/tests/test_agent_restrictions_patterns.py`. Related files
(`gateway/tests/test_agent_restrictions_enforce.py`,
`gateway/tests/test_push_error_enrichment.py`,
`gateway/tests/test_agent_restrictions_comprehensive.py`,
`gateway/tests/test_phase_filter_restrictions.py`) may need small
updates if they assert on the legacy CODER_PATTERNS enumeration.

New test cases:

- **Extensionless files** — coder can write `bin/egg`, `sandbox/egg`,
  `LICENSE`, `.dockerignore`, and an arbitrary new top-level file
  `path/to/new-thing` (acts as a regression test for the issue).
- **Docs still blocked** — coder cannot write `docs/foo.md`,
  `README.md`, `**/*.md`.
- **Tests still blocked** — coder cannot write `tests/test_x.py`,
  `test/test_y.py`, `gateway/tests/__init__.py` (regression test for
  the matcher bug fix), `**/conftest.py`.
- **`.egg-state/` blocks + agent-outputs exemption** — coder cannot
  write `.egg-state/contracts/spec.json`, `.egg-state/drafts/1901-plan.md`,
  `.egg-state/reviews/verdict.json`, or a hypothetical future
  `.egg-state/secrets/key` — but **can** write
  `.egg-state/agent-outputs/out.json`.
- **skills/ exemption** — coder can write `skills/my-skill/SKILL.md`,
  `skills/my-skill/handler.py`.
- **sandbox/agent-config exemptions** — coder can write
  `sandbox/agent-config/rules/foo.md`,
  `sandbox/agent-config/commands/bar.md`.
- **Tester/documenter scopes unchanged** — regression tests that
  tester still owns `tests/test_x.py` and is still blocked from
  `docs/foo.md`, etc.
- **Matcher bug regression** — `_matches_pattern("gateway/tests/__init__.py", "**/tests/")`
  must return `True`; `_matches_pattern("src/foo.py", "**/tests/")`
  must return `False`.
- **Leave `test_no_allowed_patterns_denies_all` untouched** —
  matcher semantics are unchanged under Option A.

Update any pre-existing test that enumerates CODER_PATTERNS'
allow-list literally (e.g. iterating through `allowed_patterns` and
expecting a specific set); replace with membership checks against
the new shape.

### Phase 6 — Documentation

Update `docs/reference/agent-roles.md` to describe the three-role
mutual exclusion model:

- Section `### coder` (line 129 area): replace the long extension
  enumeration in the **File access** block with a short description
  — "coder owns all files except tester's test scope, documenter's
  markdown/docs scope, and the pipeline-state `.egg-state/`
  directory (with `.egg-state/agent-outputs/` carved back in as
  coder's handoff dir). `skills/` and `sandbox/agent-config/{rules,commands}/*.md`
  are functional code, not docs, and remain coder-owned via
  block-exemption patterns."
- Sections `### tester` and `### documenter`: reword so the three
  are described symmetrically as complementary scopes.
- Add a short note that this mutual exclusion is "by construction":
  if tester's or documenter's scope grows, coder's shrinks
  automatically because coder is defined as the complement.

## Risks & mitigations

Handled in detail by the `risk_analyst`; below is the summary this
plan relies on:

- **Matcher semantics flip risk** — not taken (we chose Option A
  precisely to avoid this).
- **Blocklist completeness** — any new sensitive scope added to
  tester/documenter must be added to coder's blocklist. Mitigated by
  the `TODO(#1903)` comment directing future maintainers to the
  single-source-of-truth follow-up.
- **Matcher bug fix side-effects** — fix is narrow (pattern ends
  with `/` under the `**` branch). Existing tests pin file-name
  patterns, which are unaffected.
- **Phase-permissions.json schema** — if the runtime's
  `check_file_restrictions` only understands `blocked_patterns` and
  not `block_exempt_patterns`, the agent-push layer in `patterns.py`
  remains authoritative for exemptions. Implementer verifies before
  merging.
