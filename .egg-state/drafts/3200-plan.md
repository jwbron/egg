# Plan — Full-context backstop for BRC event-pump agents (Issue #3200)

## HITL Decisions
- **cq-1 (scope):** Option A — Full scope: all 3 components + restart-memory preservation fix.

## Architecture Overview

The plan delivers four sequential slices, each building on prior slices:

```
Slice 1: Restart-memory preservation      ← prerequisite fix
Slice 2: Session resume (warm path)        ← #3186
Slice 3: Deterministic seed layer composer  ← #3189
Slice 4: Enrichment layer injection        ← #3188
```

Each slice is independently shippable. The ordering ensures the foundation (restart fix) ships before the resume path depends on artifact survival, and the deterministic layer ships before the enrichment layer is composed on top of it.

---

## Slice 1: Restart-memory preservation

**Motivating incident:** #3183 — `restart_phase` deleted per-role worktrees and BRC memory files with them, causing 14.7M prompt tokens in 30 min of re-review.

**What:** Extend the salvage path to preserve BRC memory files alongside unpushed commits.

**Files:**
| File | Change |
|------|--------|
| `orchestrator/agent_salvage.py` | Add `brc-memory*` glob to `auto_salvage_pipeline()`: before worktree deletion, copy agent-output memory files from `.egg-state/agent-outputs/<role>/brc-memory-<pipeline-id>.md` to a persisted location (alongside the existing commit salvage). |
| `orchestrator/agent_salvage.py` | Add `restore_salvaged_memory()` call in the recovery path — on pipeline restart, detected salvaged memory files are placed back where agents expect them. |

**Key decisions:**
- Memory files are identified by the same pipeline-id key used for commits
- Salvage is best-effort (existing behavior — if files are missing, no error)
- The deterministic seed composer reads from the message record, not salvaged files — the salvage here protects the enrichment-only half

## Slice 2: Session resume (warm path)

**Motivating incident:** Every event re-spawns a fresh agent context; resume would serve cached history from the provider's prompt cache at near-zero cost.

**What:** Agent SDK `resume=<session_id>` pass-through from orch → sandbox agent.

**Files:**
| File | Change |
|------|--------|
| `shared/egg_agent/result.py` | (Already done — `AgentResult.session_id` exists) |
| `sandbox/egg_agent_tools/handlers/midturn_messages.py` | Persist `session_id` to a cursor file `egg-resume-cursor-<digest>` parallel to existing `midturn_messages.py` persistence pattern. Write on agent exit, read on next invocation. |
| `orchestrator/consensus_wrapper.py` | `invoke_agent_for_event()`: read persisted `session_id` from the cursor file; inject `--resume <session_id>` into agent CLI command. |
| `shared/egg_agent/command.py` | (Already done — `--resume` CLI flag exists on `ClaudeAgentOptions`) |

**Key decisions:**
- `resume` and `--system-prompt` (seed) are **mutually exclusive** — if the seed path is taken (context full, cold start), `resume` is omitted and a fresh session is spawned with `--system-prompt <seed>`
- Cursor is keyed by `pipeline_id + role` (digest hash), same pattern as midturn messages
- Missing cursor file → fresh session (graceful degradation to today's behavior)

## Slice 3: Deterministic seed layer composer

**Motivating incident:** Without the deterministic layer, a fresh agent has no anchor for what it reviewed or what verdicts it issued — it starts blind.

**What:** New orchestrator module that reads peer-consensus state and renders a deterministic, bounded, cache-stable system-prompt block.

**Files:**
| File | Change |
|------|--------|
| `orchestrator/routes/seed_composer.py` | **New file** — `SeedComposer` class: `render_deterministic_layer()` reads from `PeerConsensusTracker` message store and renders per-producer block: last-reviewed SHA, latest verdict, NACK reasons, conditional-ACK obligations. Output: sorted, stable bytes with hard per-section caps. |
| `orchestrator/peer_consensus.py` | Export `_proposal_commit_shas` and verdict-derivation helpers as public methods for the composer to consume (currently private, accessed via tracker state). |
| `orchestrator/routes/pipelines.py` | Bridge: `_write_brc_history` already persists phase-completion transcripts; the composer reads both live (current phase) and committed (past phases) message stores for deterministic anchor derivation. |

**Key decisions:**
- Data source: message store (`PeerConsensusTracker` state + committed `.egg-state/brc-history/*.json`), NOT agent-authored files — ensures authoritative source
- **Rendering rules:**
  - Sorted by producer role name (stable order)
  - Per-producer section capped at 1 KB
  - Section rendering: `producer: <role> | last-reviewed: <SHA or "none"> | verdict: <ACK/NACK/pending> | obligations: <list or "none">`
  - NACK reasons truncated at 256 chars, eldest dropped when section would exceed budget
- Composer runs at seed-build time (per fresh-session spawn), not cached to disk — idempotent, always reflects latest state

## Slice 4: Enrichment layer injection

**Motivating incident:** Deterministic anchors tell you *what happened* (SHA, verdict) but not *why* — a fresh agent lacks the judgment context to resume effectively.

**What:** Seed composer integrates agent-authored enrichment (from persisted `brc-memory*.md`) into the system-prompt seed, following the deterministic layer.

**Files:**
| File | Change |
|------|--------|
| `orchestrator/routes/seed_composer.py` | Add `render_enrichment_layer()` — reads agent-authored `brc-memory-<pipeline-id>.md`, validates SHA stamps, renders bounded enrichment block. |
| `orchestrator/routes/seed_composer.py` | Add `render_seed()` — full pipeline: deterministic prefix → enrichment (capped) → pass to `--system-prompt`. |
| `sandbox/egg_agent_tools/handlers/brc_memory.py` | Add SHA-stamped claim format: each enrichment claim line includes `<sha:commit>` reference so the composer can detect stale claims vs. current git HEAD. |
| `orchestrator/consensus_wrapper.py` | `invoke_agent_for_event()`: mutual-exclusion logic for resume vs fresh seed. When `--system-prompt` is passed (seed path), `resume` is omitted. The decision is: try resume cursor → if missing/invalid, build seed and spawn fresh. |

**Key decisions:**
- Each enrichment claim is SHA-stamped (`path:line@<sha>` format) — the composer warns (but does not block) when SHA no longer matches HEAD
- Enrichment rendered AFTER deterministic layer in the seed flow
- Prefixed with: `⚠️ The following is agent-authored orientation-to-spot-check — NOT ground truth. Reference cited SHAs to verify.`
- Hard cap of 4 KB total for the enrichment segment
- Stale claims (SHA in enrichment doesn't match current) are annotated with `[STALE — verify]`

## Integration: invoke flow

```
invoke_agent_for_event():
  cursor = read_resume_cursor(pipeline_id, role)
  if cursor and cursor_still_valid():
    # Warm path — cached history from prompt cache
    spawn(resume=cursor.session_id)
  else:
    # Cold path — fresh session with seed
    seed = compose_seed(pipeline_id, role)
    # deterministic layer from message store
    # enrichment from persisted brc-memory.md
    spawn(system_prompt=seed)
```

## Test plan

| Test area | What it covers |
|-----------|---------------|
| Restart salvage | `pipelines.py::restart_phase()` deletes worktree → verify `brc-memory.md` survived and is restored on restart |
| Session resume | Agent exits with session_id → next invocation spawns with `--resume <id>` → agent receives cached context |
| Deterministic layer | Message store has N records → composer renders N per-producer blocks in sorted order, within budget |
| Enrichment layer | `brc-memory.md` has stale SHA claim → composer annotates `[STALE]`, does not omit |
| Seed composition | Full seed → deterministic prefix, enrichment suffix, caps enforced, stable rendering on repeated calls |
| Mutual exclusion | `--resume` and `--system-prompt` never appear in same agent command |
