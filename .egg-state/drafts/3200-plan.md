# Plan — Full-context backstop for BRC event-pump agents (Issue #3200)

## HITL Decisions
- **cq-1 (scope):** Option A — Full scope: all 3 components + restart-memory preservation fix.

## Architecture Overview

The plan delivers four sequential slices, each building on prior slices. Slice ordering ensures prerequisites ship before dependents:

```
Slice 1: Restart-memory preservation      ← prerequisite fix (#3183)
Slice 2: Session resume (warm path)        ← #3186
Slice 3: Deterministic seed layer composer  ← #3189
Slice 4: Enrichment layer injection        ← #3188
Slice 5: Integration & mutation-detection    ← cross-cutting
```

Each slice is independently shippable. The ordering ensures the foundation (restart fix) ships before the resume path depends on artifact survival, and the deterministic layer ships before the enrichment layer is composed on top of it.

        acceptance: Agent uses --resume <id> and receives cached context from provider prompt cache.

    name: Deterministic seed layer composer

          sorted per-producer blocks with last-reviewed SHA, verdict, NACK reasons, obligations.
          
          **M4:** Hard enforced byte caps. The composer must actively reject (not warn) sections
          that exceed their budget. Cap is enforced at composition time; truncation is reserved
          only for the enrichment layer (Slice 4) and must truncate with sentinel marker.
          No actual byte budgets exceed 4KB after rendering (2KB deterministic + 2KB enrichment).
          Integration tests verify byte budget at composition time.
          
          **M2 (partial):** SHA-stamped enrichment claims must be cross-checked against the
          deterministic layer's last-reviewed SHA per producer. Cross-check is performed during
          render, not at usage time.
        acceptance: |
          Composer output is byte-stable on repeated calls with same store state and fits within
          budget. Sections exceeding budget cause hard error. Test verifies: compose → verify
          output ≤ 4KB (2KB deterministic + 2KB enrichment). Spark verification: compose from
          same inputs → identical SHA256 hashes.
        files:
          - orchestrator/routes/seed_composer.py
          - orchestrator/peer_consensus.py

  - id: 4
    name: Enrichment layer injection into seed
    depends_on: "3"
    tasks:
      - id: task-plan-4-1
        description: |
          Add render_enrichment_layer() and render_seed() to SeedComposer. Reads agent-authored
          brc-memory.md, validates SHA stamps, renders bounded enrichment 4 KB cap after
          deterministic prefix. Annotates stale SHA-stamped claims.
          
          **M2 complete:** Every SHA claim in enrichment is cross-checked against the deterministic
          layer's last_reviewed_sha per producer. SHA mismatch on cross-check → blocked:
          the enrichment section is dropped from the seed (truncated to empty) with a logged
          warning, so the seed is still usable but without stale content. Output is always
          within cap: truncation with "..." sentinel + byte-count remaining.
          
          **M4 (final):** hard per-section caps enforced via test infrastructure.
        acceptance: |
          Integration test: produce BRC-memory → compose → verify output ≤ 4KB (2KB + 2KB).
          Test: stale SHA injected → enrich_on dropped; fresh SHA matches → enrichment retained.
          Composer fails closed (truncation) not silently (bypass caps).
        files:
          - orchestrator/routes/seed_composer.py
          - sandbox/egg_agent_tools/handlers/brc_memory.py

          **M5:** Implement the 5-state decision matrix specified in the risk assessment
          (M5 in the reviewer checklist).
        acceptance: |

          untrustworthy), fall back to a clean launch with --system-prompt '' empty or absent

          unseeded fresh launch succeeds.
        acceptance: |
          Test matrix: 5-state algorithm with each fallback validated. Resume file missing →

          - config/litellm/litellm-config.yaml
