# Plan: Decompose 15 oversize Python source files to clear the file-size allowlist

> Issue: #2261 | Phase: plan | Pipeline: issue-2261

## Approach

The architect's recommendation (A1 + B2 + C1) plus the operator's HITL
resolutions give us a tight, well-bounded shape:

- **Module layout: A1** — every oversize file becomes a sub-package
  `<file>/__init__.py` with private `_*.py` submodules. The `__init__.py`
  acts as a re-export barrel (decision-1, decision-5, decision-6,
  decision-7).
- **Re-export style: explicit per-symbol** — `from ._run_loop import
  _run_pipeline, _spawn_pipeline_run_thread, ...` (decision-5).
- **Submodule naming: underscore-prefixed** — matches existing
  package-private convention (decision-6).
- **Routes: thin wrappers in `__init__.py`** — both `routes/pipelines.py`
  and `gateway/gateway.py` keep the existing Blueprint /
  `@app.route(...)` registrations on `__init__.py`; each route's body is
  a one-line delegate to the submodule implementation
  (decision-8, feedback Q5). Note that `pipelines.py` already uses a
  Flask Blueprint (`pipelines_bp`), which simplifies the move.
- **`_run_pipeline` strategy: B2 per-phase handler refactor** — the
  2,362-line state machine is split into per-phase handlers
  (`_run_refine_phase`, `_run_plan_phase`, `_run_implement_phase_slices`
  is already extracted, `_run_pr_phase`) plus a thin orchestration loop
  (decision-2). Per-phase handlers stay private and tested through
  `_run_pipeline`; new isolated unit tests are out of scope for this
  refactor (feedback Q7).
- **Slice DAG: C1 forest** — one slice per file, fanned out under a
  pattern-adoption parent. Forest constraint satisfied: every child has
  exactly one DAG parent (slice-1) (decision-3). The implement-phase
  scheduler will run the children in waves of 5
  (`EGG_ORCH_MAX_PARALLEL_SLICES=5`, decision-10).
- **Pattern-adoption parent (slice-1)**: lands
  `docs/guides/decomposition-pattern.md`, updates the seam tables in
  `orchestrator/CLAUDE.md` and `gateway/CLAUDE.md`, AND decomposes
  `scripts/select_tests.py` as the worked reference (decision-4,
  feedback Q8 precondition).
- **Pre-existing growth: use current sizes as baselines**
  (`pipelines.py` 16,401, `select_tests.py` 1,875) — the issue body's
  numbers are informational (feedback Q2).

### Slice ordering (decision-10, feedback Q3)

Strict size-ordered fan-out, smallest first, with the two structural
outliers last. The pattern-adoption slice (slice-1) decomposes a small
file (`scripts/select_tests.py`) so the convention is exercised before
the children fan out. Children are siblings of slice-1, listed in
ascending complexity:

15 slices total. Children are siblings under slice-1 — the forest rule
holds (each slice has ≤1 DAG parent). Once slice-1 lands, slices 2–15
become READY simultaneously and the scheduler runs them in waves of 5,
i.e. ~3 waves to drain the easy/medium tier. slices 14 and 15 sit at
the end of the chain because they are the largest and likely longest-
running; if they happen to be promoted earlier by the scheduler that's
fine — the dependency edge just gates "before slice-1 lands" — but in
practice they tend to fall to the third wave because earlier waves
saturate the parallelism budget first.

### Why slice-15 stays a single slice

Decision-9 selected "single slice with multiple commits/sub-tasks" for
`pipelines.py` over a chain of sub-slices. The slice has multiple
internal tasks (one per cluster: `_criteria`, `_readers`, `_pr_lifecycle`,
`_worktree_ops`, `_brc_verdicts`, `_status_helpers`, `_decisions`,
`_prompt_building`, `_run_loop`) but they all land in the same slice's
PR. The internal task ordering inside slice-15 is:

1. **Inventory.** `git grep` audit of every external importer / patch
   target — identifies the canonical re-export list (feedback Q6).
2. **Mechanical cluster extractions** (`_criteria`, `_readers`,
   `_decisions`, `_status_helpers`, `_prompt_building`,
   `_brc_verdicts`, `_pr_lifecycle`, `_worktree_ops`) — one commit per
   cluster; each commit lands the new submodule plus the
   `__init__.py` re-exports.
3. **`_run_pipeline` B2 refactor** — last, after all helpers are
   extracted. Per-phase handlers (`_run_refine_phase`,
   `_run_plan_phase`, `_run_pr_phase`; `_run_implement_phase_slices`
   already exists) live in `_run_loop.py`. Shared per-call state goes
   on a `_PipelineRunContext` dataclass.
4. **`__init__.py` finalisation** — explicit re-export barrel + thin
   `pipelines_bp.route(...)` wrappers delegating to submodule handlers.
5. **Allowlist drop** — remove `orchestrator/routes/pipelines.py`
   entry from `scripts/file-size-allowlist.yaml`. If any submodule
   itself exceeds the cap, the slice owner must split that submodule
   further within the same slice — adding an allowlist entry is **not
   allowed** (the issue's "allowlist empty" acceptance criterion).

The slice's PR diff will be huge (>1,000 LOC). The plan reviewer issues
an advisory at >2,000 LOC; per HITL decision-6 of #2137 the advisory is
non-blocking. The issue's explicit "_run_pipeline is in scope"
non-negotiable is the operator's standing override.

### Per-slice template (slices 2–15)

Each child slice follows the same internal task shape, parameterised on
the file F being decomposed:

1. **Audit external imports** — `git grep` for every public symbol in F
   to identify required re-exports. Re-export every symbol referenced
   from outside F's package (feedback Q6: "Re-export everything that
   has any external reference"); skip re-exports only for symbols that
   are (a) underscore-prefixed AND (b) referenced exclusively inside
   the file's own package.
2. **Extract submodules** — convert `F.py` into `F/__init__.py` plus
   `F/_<cluster>.py` files. Group symbols by cohesion (caller graph,
   shared imports, conceptual boundary).
3. **Re-export barrel** — `__init__.py` does `from ._<cluster> import
   <sym>, ...` per submodule, listing every name explicitly.
4. **Allowlist drop** — remove F's entry from
   `scripts/file-size-allowlist.yaml`. If any submodule still exceeds
   the cap, split it further within this slice; do not add a fresh
   allowlist entry.
5. **Seam-table update** — add an entry to the relevant
   `<package>/CLAUDE.md` documenting the new submodule layout. This is
   a documenter task because of the file-boundary split.

### Test back-compat invariants

- **Patch-target stability.** Every `unittest.mock.patch("<path>.<sym>")`
  resolved against the original module before the move resolves against
  the same path after the move. Verified by `make test-all`.
- **Production importer stability.** External imports
  (`from routes.pipelines import _read_phase_draft`,
  `from gateway.gateway import get_anthropic_client`, etc.) resolve
  through the barrel. Decision-7 keeps consumers on the barrel
  (`from <pkg> import <sym>`) so future internal moves don't require
  consumer churn.
- **Behavior preservation.** No functional change in any slice; if a
  decomposition surfaces a latent bug, file separately and don't bundle
  the fix (issue's out-of-scope clause).
- **Test patch-path drift fix scope.** The same slice that owns a moved
  symbol may fix mechanical patch-path rewrites in tests
  (one-line `patch("orchestrator.routes.pipelines._foo")` →
  `patch("routes.pipelines._foo")`); test-logic rewrites stay strictly
  out of scope and get filed as follow-ups (feedback Q1).

### Test strategy

- **Automated** — every slice runs `make lint` + `make test-all`. The
  test patch-target audit (43+ symbols per the analysis) is implicitly
  exercised by the existing test suite — if a re-export is missed, the
  tests that patch the moved symbol fail with `AttributeError`.
- **CI green at every slice boundary** — required by issue acceptance
  criteria. The slice-DAG run loop already gates each slice's PR on
  consensus + CI green.
- **No new unit tests for `_run_pipeline` per-phase handlers** — they
  remain private and tested through `_run_pipeline` for this refactor
  (feedback Q7). A follow-up issue should add isolation tests.
- **Manual verification (per slice)** — reviewer spot-checks (a) the
  `__init__.py` re-export list against `git grep` for external
  importers, (b) the submodule clustering is cohesive (no
  cross-submodule reach-throughs that defeat the seam), and (c) the
  CLAUDE.md seam-table entry matches the submodule layout.

### Manual steps

- **Pre-merge (terminal slice = slice-15 only):** verify the seam
  tables in `orchestrator/CLAUDE.md` and `gateway/CLAUDE.md` reflect
  the final submodule layouts after all 15 slices land. Verify
  `scripts/file-size-allowlist.yaml` has no entries linked to issue
  "2248" remaining.
- **Pre-merge (slices 2–14):** none beyond the standard reviewer
  spot-checks listed under the per-slice template.
- **Post-merge:** none. Pure refactor; no migrations, config changes,
  or deployment coordination. `make test-all` is the contract; no
  release-channel smoke tests required (feedback Q4).

### Risks & mitigations summary

- **Re-export drift.** A submodule extraction misses a public symbol →
  patch target raises `AttributeError`. *Mitigation:* explicit per-
  symbol re-exports (decision-5) + the inventory audit task in every
  slice's template + `make test-all` gate.
- **`_run_pipeline` behavior risk.** B2 per-phase refactor on a
  state machine with subtle ordering. *Mitigation:* refactor lands
  last (slice-15) after the pattern is proven on 13 simpler files;
  per-phase handlers stay private; existing dense test coverage at
  this seam (`test_consensus_polling.py`,
  `test_brc_nack_iteration.py`, `test_concurrent_*.py`,
  `test_advance_phase_*.py`) is the gate.
- **Sub-package circular imports.** Splitting `routes/pipelines.py`
  into a sub-package may surface latent circular-import issues that
  were masked by the single-file shape. *Mitigation:* the existing
  lazy-import pattern in `routes/phases.py` is already the precedent;
  new submodules use the same `try: from ..foo / except ImportError:
  from foo` dual-import shape consistently.
- **Allowlist ratchet failure.** A slice's submodule extraction
  produces a still-over-cap file. *Mitigation:* per-slice template
  step 4 mandates further splitting within the same slice rather than
  adding a fresh allowlist entry.
- **Concurrency contention.** 5 parallel slices run concurrently.
  *Mitigation:* default `EGG_ORCH_MAX_PARALLEL_SLICES=5` is the
  operator-tested ceiling (decision-10); cascade-block protects the
  downstream subtree if a slice fails.
