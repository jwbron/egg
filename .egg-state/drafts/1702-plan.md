# Plan: Add server-computed timing to get_status response

## Summary

Add server-computed timing fields to `_handle_get_status` so the `/sdlc` monitor gets accurate elapsed times instead of relying on client-side wall-clock tracking that drifts during blocking dialogs. The phase's `started_at` is already in the pipeline data — we just need to surface it and compute `elapsed_seconds` server-side.

**Risks / edge cases**: `started_at` can be `None` for pending phases or agents that haven't initialized — guard with conditionals; omit the fields when timing data is unavailable rather than returning nulls.

## Implementation

### Phase 1: Implement

Add `phase_started_at`, `phase_elapsed_seconds`, and per-agent `elapsed_seconds` to the `get_status` response in the MCP tools handler, with tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/mcp_tools.py:_handle_get_status()`, after building the status dict (~line 898), extract `phase_started_at` from `phase_data.get("started_at")` and compute `phase_elapsed_seconds` as `int((now - started_at).total_seconds())`. Add both to the status response. Guard against `None`. Acceptance: `get_status` response includes `phase_started_at` (ISO 8601) and `phase_elapsed_seconds` (int) when the phase has started.
2. **[task-1-2]** In the same method, after filtering `running_agents` (~line 904), iterate over each agent and add `elapsed_seconds` computed from `agent["started_at"]`. Guard against missing/`None` `started_at`. Acceptance: each `running_agents` entry includes `elapsed_seconds` (int) when the agent has a `started_at` value.
3. **[task-1-3]** In `orchestrator/tests/test_mcp_tools.py`, update the `_pipeline_response` fixture to include `started_at` on the phase and agents. Add tests verifying `phase_started_at`, `phase_elapsed_seconds`, and per-agent `elapsed_seconds` appear in the response, and that they are omitted when `started_at` is `None`. Acceptance: tests pass for both present and absent `started_at` cases.
