# Implementation Plan: Per-Agent Worktree Isolation and Role-Aware File Enforcement

> Issue: #1481 | Phase: plan | Single PR

## Approach

This plan implements the full six-layer defense-in-depth enforcement model described in the issue and validated by the architect analysis. The core problem is that all agents in a pipeline share a single git worktree, causing cascading failures: agents commit disallowed files → push blocked → recovery burns tokens (#1470); `auto_commit_worktree()` sweeps disallowed files into WIP commits → CI fails (#1480); agents overwrite each other's uncommitted work.

The solution replaces the shared-worktree model with per-agent worktree isolation as the structural foundation, then layers on SDK tool interception for early feedback, per-agent git identity for auditability, scoped push detection, and removal of auto-commit-push in favor of HITL recovery. Each layer addresses a distinct failure mode and can be tested independently.

### Key Design Decisions (from HITL-approved analysis)

1. **Per-agent worktrees are default for all pipelines** — no opt-out. No workflows depend on shared uncommitted state.
2. **SDK tool interception covers Write, Edit, NotebookEdit** — not Bash. Agent SDK (`egg_agent`) only, not the interactive `claude` CLI.
3. **Auto-commit-and-push is removed entirely** — replaced by orchestrator detection of uncommitted changes + HITL decision for recovery.
4. **Push retry uses `git pull --rebase`** — conflict signals error to orchestrator (indicates pattern bug).
5. **Per-agent git author** uses `egg (<role>)` / `<role>@egg.local` format — informational, not enforcement.

### Risk Mitigations (from risk analyst)

- **RISK-1 (CONTAINER_ID semantics change)**: Orchestrator and gateway updates must be atomic. Integration test verifies distinct worktree paths for concurrent agents.
- **RISK-3 (Orphaned worktrees)**: Implement cleanup policy — auto-discard clean worktrees on exit; HITL decision with 24h timeout for dirty worktrees; periodic cleanup for stale worktrees.
- **RISK-10 (Circular dependency)**: Extract `AgentFilePattern` and role definitions to a shared package importable by both gateway and `egg_agent`.

### Dependency Ordering

```
Phase 1: Extract shared restrictions (enables Phase 4)
Phase 2: Per-agent worktrees + scoped detection (structural foundation)
Phase 3: Per-agent git identity (trivial, no dependencies)
Phase 4: SDK tool interception (depends on Phase 1 extraction)
Phase 5: Remove auto-commit-push + HITL recovery (depends on Phase 2 worktree persistence)
Phase 6: Integration tests + documentation
```

## Phase 1: Extract Agent Restrictions to Shared Package

**Goal**: Move `AgentFilePattern` and role pattern definitions from `gateway/agent_restrictions.py` into a shared package so that both the gateway and the Agent SDK can import them without circular dependencies.

### Rationale

The SDK tool interception (Phase 4) needs access to `check_agent_file_access()` and role definitions. These currently live in `gateway/` which the `shared/` packages cannot import. Extracting to a shared location is a prerequisite.

### Tasks

**TASK-1-1**: Create `shared/egg_restrictions/` package with `__init__.py`, `patterns.py`, and `checker.py`. Move `AgentFilePattern`, all role pattern definitions (CODER, TESTER, DOCUMENTER, etc.), `check_agent_file_access()`, and `AgentRestrictionResult` from `gateway/agent_restrictions.py` into this new package. The pattern definitions and matching logic must be identical — this is a pure extraction, no behavior change.

**TASK-1-2**: Update `gateway/agent_restrictions.py` to import from `shared/egg_restrictions/` instead of defining patterns locally. `validate_agent_push()` and any gateway-specific logic remain in the gateway module. Ensure all existing gateway tests pass unchanged.

**TASK-1-3**: Add `egg_restrictions` to the shared package installation (update `shared/setup.py` or `shared/pyproject.toml` and any dependency declarations). Verify the package is importable from both gateway and shared contexts.

**TASK-1-4**: Write unit tests for `shared/egg_restrictions/` covering: pattern matching for all 15+ roles, blocked vs. allowed file classification, unknown role fallback behavior (change from allow-all to deny-all per RISK-7 mitigation), edge cases (empty file lists, path traversal patterns).

## Phase 2: Per-Agent Worktree Isolation and Scoped Push Detection

**Goal**: Give each agent its own isolated worktree. Fix push file detection to only report the pushing agent's files.

### Rationale

This is the structural foundation that eliminates the root cause (shared worktrees). All other layers build on this. Scoped push detection is free with per-agent worktrees — each worktree only contains that agent's commits.

### Tasks

**TASK-2-1**: In `orchestrator/routes/pipelines.py` (line 5770-5772), change `worktree_id = pipeline_id` to use a per-container identifier (e.g., `f"{pipeline_id}-{agent_role}"` or the container's unique ID). This makes each agent get a distinct worktree from `WorktreeManager.create_worktree()`. Ensure the worktree branch name remains on the shared pipeline branch (`egg/issue-<N>`), not a per-agent branch.

**TASK-2-2**: Update `orchestrator/container_spawner.py` to propagate the per-container worktree ID. Verify `CONTAINER_ID` environment variable is updated to reflect the new per-container value (currently set to `pipeline_id` at line 387). Ensure `repo_volumes` mount the agent-specific worktree path.

**TASK-2-3**: Verify `gateway/worktree_manager.py` `create_worktree()` handles the new per-container ID correctly — it should already work since it's keyed by `container_id`, but verify path resolution, branch creation, and ownership. Ensure the gateway's `map_container_path_to_worktree()` resolves correctly with the new ID.

**TASK-2-4**: Verify `gateway/git_client.py` `get_changed_files_in_push()` correctly scopes to the agent's commits with per-agent worktrees. Since each worktree only has that agent's commits, the existing `origin/<branch>..HEAD` diff should naturally scope correctly after `git pull --rebase`. Add a defensive comment documenting why this works. If edge cases exist (e.g., initial push before any remote commits), handle them.

**TASK-2-5**: Update `gateway/session_manager.py` session registration to use the new per-container ID so `map_container_path_to_worktree()` resolves correctly. Verify all gateway endpoints that consume `container_id` from the session handle the change.

**TASK-2-6**: Extend pipeline cleanup logic (`orchestrator/routes/pipelines.py` or `orchestrator/container_spawner.py`) to iterate over and clean up N per-agent worktrees instead of 1 shared worktree. Add a `list_worktrees_for_pipeline()` utility if one doesn't exist. Implement best-effort cleanup that logs failures but doesn't fail the pipeline.

**TASK-2-7**: Write integration-style tests: (a) two agents spawned in the same pipeline get different worktree paths, (b) file changes in one worktree are invisible in another, (c) cleanup removes all per-agent worktrees for a pipeline.

## Phase 4: Agent SDK Tool Interception

**Goal**: Add pre-execution hooks in `egg_agent` that check Write/Edit/NotebookEdit file paths against role restrictions, giving agents early feedback.

### Rationale

This is the token-saving optimization. Agents learn immediately that they can't write to a file instead of discovering at push time after spending tokens generating content. Also drives delegation behavior — agents are told which role owns the file.

### Tasks

**TASK-4-1**: Add a `tool_interceptor.py` module in `shared/egg_agent/` with a `check_file_write_permission(tool_name: str, tool_input: dict, agent_role: str) -> str | None` function. For Write, Edit, and NotebookEdit tools, extract `file_path` from `tool_input` and call `check_agent_file_access()` from the extracted `egg_restrictions` package (Phase 1). Return `None` if allowed; return an error message string if blocked (e.g., "Role 'coder' cannot write to tests/test_foo.py — this file belongs to the 'tester' role").

**TASK-4-2**: Integrate the interceptor into `shared/egg_agent/client.py`. The `claude_agent_sdk` `query()` function supports a `tool_filter` or similar callback mechanism — hook `check_file_write_permission()` into the tool dispatch pipeline so blocked tools return an error to the LLM without executing. If the SDK doesn't support a filter callback, use the `disallowed_tools` mechanism or wrap the stream processing to intercept `ToolUseBlock` events. Read `EGG_AGENT_ROLE` from environment.

**TASK-4-3**: Write unit tests: (a) Write to a disallowed path returns an error without executing, (b) Write to an allowed path proceeds normally, (c) Edit to a disallowed path returns an error, (d) NotebookEdit to a disallowed path returns an error, (e) Bash tool is NOT intercepted, (f) interception is skipped when `EGG_AGENT_ROLE` is not set (backward compat / interactive mode).

## Phase 5: Remove Auto-Commit-Push and Add HITL Recovery

**Goal**: Eliminate unreviewed WIP commits by removing auto-commit-push and replacing it with orchestrator-side detection of uncommitted work.

### Rationale

With per-agent worktrees (Phase 2), uncommitted work persists in the worktree on disk after container exit. There's no need to auto-commit and push it — that behavior bypasses BRC consensus and is the direct cause of #1480. The replacement is a HITL decision letting humans choose whether to recover or discard uncommitted work.

### Tasks

**TASK-5-1**: In `gateway/post_agent_commit.py`, remove or disable the auto-commit-and-push logic in `auto_commit_worktree()`. The function should become a no-op that logs a message ("Auto-commit disabled — per-agent worktrees preserve uncommitted work"). Ensure all call sites handle the change gracefully (the function may return `None` instead of a commit SHA).

**TASK-5-2**: In the orchestrator's container exit handler (likely in `orchestrator/routes/pipelines.py` or `container_spawner.py`), add logic to detect uncommitted changes in the agent's worktree after container exit. Use `git -C <worktree_path> status --porcelain` to check for changes. If changes exist, create a HITL decision via the contract system: "Agent `<role>` exited with uncommitted changes in `<N>` files. Recover or discard?"

**TASK-5-3**: Implement worktree cleanup policy: (a) auto-discard worktrees with no uncommitted changes immediately after container exit, (b) for worktrees with uncommitted changes, preserve until HITL decision is resolved, (c) implement a 24-hour timeout on the HITL decision that defaults to discard, (d) add a periodic cleanup that removes worktrees older than 48 hours regardless of state.

**TASK-5-4**: Update any callers of `auto_commit_worktree()` — search for all call sites in the codebase and verify they handle the new behavior (no push, no commit SHA returned). Update the post-agent-commit reference doc (`docs/reference/post-agent-commit.md`) to reflect the removal.

**TASK-5-5**: Write tests: (a) container exit with uncommitted changes does NOT result in a push, (b) HITL decision is created when uncommitted changes detected, (c) clean worktree is auto-discarded on exit, (d) worktree persists when uncommitted changes exist, (e) 24h timeout discards the worktree.

## Phase 6: Integration Tests and Documentation

**Goal**: End-to-end validation of the full enforcement stack and documentation updates.

### Rationale

Each phase has unit tests, but the six layers must work together. Integration tests verify the full flow. Documentation ensures the changes are discoverable.

### Tasks

**TASK-6-1**: Write an integration test that simulates a full multi-agent pipeline: spawn 2+ agents with different roles, have each write to their allowed files, commit, and push. Verify: (a) agents get distinct worktrees, (b) each agent's push succeeds with their own files, (c) push would fail if an agent tried to push files outside its role, (d) git log shows per-agent authorship.

**TASK-6-2**: Write an integration test for the SDK interception path: spawn an agent with `egg_agent`, attempt a Write to a disallowed path, verify the error is returned without the file being written.

**TASK-6-3**: Update architecture docs: `docs/architecture/git-isolation.md` to describe per-agent worktree model, `docs/reference/post-agent-commit.md` to document auto-commit removal, `docs/reference/agent-roles.md` to document the SDK interception behavior and the extracted `egg_restrictions` package.

**TASK-6-4**: Update agent prompt templates in `sandbox/agent-config/` and `shared/prompts/` that reference the shared worktree model or auto-commit behavior. Remove references to agents sharing a worktree; update guidance on push-retry behavior.
