# Plan: Make `make test` changeset-aware via grimp + sidecar LKG

> Issue: #1973 | Phase: plan | Agent: task_planner

## Summary

`make test` today unconditionally runs the full unit-test suite (~356
test files) regardless of what changed on the branch. The refine phase
converged on a grimp-based static reverse import graph that narrows
the default `make test` run to the transitive reverse closure of files
touched since a Last-Known-Good (LKG) sha, falling back to the base
branch when no LKG exists, and falling back to the **full suite**
whenever static analysis cannot be trusted (conftest / lockfile /
workflow changes, non-`.py` changes, dynamic-import reachability,
`shared/tests/` fixture edits, unresolvable baseline, or LKG-not-an-
ancestor-of-HEAD).

Correctness posture is preserved: the gate is "never skip a test that
exercises a changed code path", and any sign of static-analysis fog
widens selection to the full suite with an explicit trigger reason
printed to stderr. A `--why <test>` flag prints the import chain that
selected a given test, for agents debugging "I expected this to run".

All refine-phase HITL decisions (13) and feedback answers (16) are
treated as locked-in constraints here; this plan does not revisit
them. CI (`.github/workflows/test.yml`) switches to `make test-all`
to preserve the existing `--cov-fail-under=80` gate unchanged.

Work ships as a **single PR** split across six commit-phases:
foundation (dependency + `.gitignore`), selector script, Makefile
wiring, CI switch, tests, and documentation.

## Approach

### Locked-in design decisions (from refine HITL)

Refine-phase HITL resolved 13 decisions and 16 feedback questions.
Relevant locked values carried into implementation:

- **d3 = grimp** for the selection engine; module-level granularity
  (d12). Rust-backed, `find_downstream_modules(module, as_package=True)`
  is the reverse-closure primitive.
- **d9 = non-tracked sidecar** at
  `.egg-state/last-known-good/<branch>.sha` (gitignored, per-branch,
  bare 40-char sha — d4). No tracked file; flips the issue's default.
- **d1 = auto-write after every green `make test-all`** +
  `make test-record-good` as the manual override. No commit involved
  because storage is a sidecar.
- **d8 = N/A** (untracked file sidesteps gateway role policy entirely).
- **d6 = leave LKG alone on merge** (sidecar is per-branch; branches
  cut from `main` inherit no LKG, which is fine — absence means "use
  base branch baseline").
- **d2 = CI uses `make test-all`** to preserve the 80% coverage gate
  unchanged. Narrowing in CI is explicitly out of scope.
- **d11 = N/A** — only `make test` (the narrowing target) needs a
  baseline-ref fetch; CI uses `make test-all` so `fetch-depth` is
  untouched.
- **d7 = `make test` narrows by default; `make test-all` is the full-
  suite escape hatch.** Current `make test` semantics move to
  `make test-all`.
- **d5 = full suite on any non-`.py` change** (simple v1 policy, no
  allowlist maintenance).
- **d10 = scan-during-graph-construction for dynamic imports**:
  during graph build, record which modules contain `importlib`,
  `__import__`, `SourceFileLoader`, or entry-point patterns; widen
  to full suite if a changed module is in (or reachable from) that
  set.
- **Q1** — no hard perf target for v1. Instrument the selector with
  `(selected, total, compute_ms, pytest_ms)` logged to stderr and
  persisted to `.egg-state/selection/<sha>.json`.
- **Q2** — any change under `shared/tests/` triggers full-suite
  fallback (coarse v1 default). Inspection performed during plan
  phase: `shared/tests/` contains `conftest.py`,
  `test_agent_roles_has_contract.py`, `test_egg_harness/` (dir),
  `test_egg_health.py`, `test_egg_restrictions.py`,
  `test_tool_interceptor.py`, `test_validate_roles_for_custom_phase.py`.
  Of these, only `conftest.py` is a universally-consumed cross-
  package fixture; the rest are self-contained test modules.
  Nevertheless v1 ships the coarse rule ("any path under
  `shared/tests/` widens") to avoid an allowlist we have not yet
  proven is stable — if any future fixture is added under
  `shared/tests/` without also updating the allowlist, we silently
  miss coverage. Follow-up issue (post-Q8 / post-Q1-baseline-data)
  may narrow to `shared/tests/conftest.py` + any identified fixture
  modules once the allowlist has been audited and we have real
  miss-rate data to justify the narrower rule.
- **Q3** — fallback-trigger list: any `conftest.py`, `Makefile`,
  `pyproject.toml`, `uv.lock`, `.python-version`,
  `.github/workflows/test.yml`, dynamic-import-touched files,
  unresolvable baseline, non-`.py` changes.
- **Q4** — canary every 10th `make test` invocation on a branch
  forces a full suite. Per-branch counter in sidecar.
- **Q5** — intersect with user-supplied `PYTEST_ARGS`: narrow to
  the selected set, then apply user args within it. Bypass narrowing
  only when `PYTEST_ARGS` names explicit test file paths.
- **Q6** — `--why <test>` prints the import chain from changed
  module to test.
- **Q7** — explicit trigger identification on fallback
  ("Falling back: Makefile changed"), not generic wording.
- **Q8** — pytest-testmon follow-up is a separate issue; not in
  this PR.
- **Q9** — last-writer-wins on concurrent sidecar writes; no
  coordination needed (both shas represent green states).
- **Q10** — integration, e2e, security targets stay full-suite-only
  in this PR.
- **Q11** — docs land in `docs/guides/testing.md`; `CONTRIBUTING.md`
  gains a one-line pointer; `make help` documents the new targets.
- **Q12** — LKG never updates on a partial (narrowed) pass. Only
  `make test-all` writes LKG.
- **Q13** — read-only agent phases always fall back to base-branch
  baseline (they do not `make test-all`, so no LKG to update; reading
  a stale cross-sandbox sidecar would confuse more than help).
  Detection: `EGG_AGENT_ROLE` environment variable; the role is
  considered read-only if it starts with `reviewer_` or equals
  `refiner`. When read-only, the selector SKIPS the sidecar read
  entirely (treats LKG as absent regardless of on-disk state) AND
  never invokes `--record-good` / never writes the sidecar. When
  `EGG_AGENT_ROLE` is unset (local developer, CI, arbitrary
  automation), the default is "non-read-only" and LKG is preferred
  when present — this keeps the local inner loop fast without
  env-var ceremony.
- **Q14** — absent sidecar is "no LKG, use base branch"; no
  bootstrap ceremony.
- **Q15** — selection-decision logging: human-readable to stderr +
  JSON at `.egg-state/selection/<sha>.json` per invocation.
- **Q16** — sidecar keyed by `<branch>` only; worktree-path keying
  deferred.

### Architecture

1. **`scripts/select_tests.py`** (new, single file, standalone CLI;
   `#!/usr/bin/env python3` + module docstring + argparse, matching
   the pattern of `scripts/check-claude-imports.py`). Entry points:
   - `select_tests.py` (default) — prints selected test paths, one
     per line, on stdout. Empty output means "no tests selected"
     (callers treat as success with zero tests run).
   - `select_tests.py --why <test_path>` — prints the import chain(s)
     that selected the given test (changed module → intermediate
     modules → test module).
   - `select_tests.py --record-good [--sha <sha>]` — writes the LKG
     sidecar to the given sha (defaults to `HEAD`). Never runs pytest.
   - `select_tests.py --full-suite` — emits all test directories as
     output and resets the canary counter (used internally by
     `make test-all`).
   **Exit codes — fail-open contract**: the default, `--full-suite`,
   and `--why` modes MUST exit 0 in all cases except argparse syntax
   errors. The selector wraps its main body in a blanket
   `try/except BaseException` that, on any unhandled exception,
   prints the traceback to stderr, emits the full set of test
   directories on stdout (equivalent to `--full-suite` output), and
   exits 0. Rationale: a bug in the selector must NEVER block agent
   or developer iteration — correctness is preserved by falling back
   to the full suite, and the traceback on stderr lets the operator
   file a follow-up. Only `--record-good` is allowed to exit non-zero
   (on validation failure — typo, non-existent sha, non-ancestor)
   because it is a pure write-side operation, not a test-gate.
   Fallback to full suite (conftest change, non-`.py` change, canary,
   etc.) is also exit 0 — it is the expected path, not an error.

2. **Grimp graph configuration**. The script registers BOTH source
   packages and test roots — grimp only reports edges between modules
   it has been told about, so leaving test roots off the list would
   make the test-file-mapping step (§6) return an empty set and
   `make test` would always print "no tests selected" in narrow mode.
   The full registry, derived from the architect's `packages_for_grimp`
   recommendation:
   - **Source packages**: `gateway`, `orchestrator`, `sandbox`,
     `shared.egg_agent`, `shared.egg_anchor`, `shared.egg_config`,
     `shared.egg_container`, `shared.egg_contracts`, `shared.egg_git`,
     `shared.egg_harness`, `shared.egg_harness_integration`,
     `shared.egg_health`, `shared.egg_logging`, `shared.egg_orchestrator`,
     `shared.egg_restrictions`.
   - **Test roots**: `tests`, `gateway.tests`, `orchestrator.tests`,
     `shared.tests`.
   - `orchestrator/` imports via bare names through the `PYTHONPATH`
     tweak in `orchestrator/tests/conftest.py`, so grimp must be given
     the `orchestrator/` directory as a top-level package root.
   - `shared/tests/` has no `__init__.py` today (verified against the
     current tree: `tests/`, `gateway/tests/`, `orchestrator/tests/`
     each have one; `shared/tests/` does not). To make grimp include
     it without changing pytest-collection semantics, the selector
     creates a lightweight `shared/tests/__init__.py` (empty file)
     as part of TASK-2-1. Pytest already treats `shared/tests/` as
     a testpath via `pyproject.toml`, so an empty `__init__.py` is
     a no-op for collection and a prerequisite for grimp's package
     resolution. (Alternative: PEP-420 namespace mode in grimp —
     rejected because it adds a second configuration path without
     removing the `__init__.py` cost for `tests/`, `gateway/tests/`,
     `orchestrator/tests/` which already have them.)
   - The selector exposes a `PACKAGES` constant listing every entry
     above; a unit test (TASK-5-4 monorepo case) asserts EVERY
     `test_*.py` file under the four test roots is a node in the
     graph built from this registry — a staleness guard against
     the list drifting out of sync with the repo layout.

3. **Baseline resolution**. Order of precedence:
   - **Read-only role override (Q13)**: if `EGG_AGENT_ROLE` starts
     with `reviewer_` or equals `refiner`, skip the sidecar entirely
     (never read, never write — even if a sidecar file happens to
     exist on disk) and proceed directly to the base-branch
     resolution below. This prevents cross-sandbox LKG contamination
     in roles that do not themselves run `make test-all`. When
     `EGG_AGENT_ROLE` is unset, `coder`, `tester`, or any other
     non-read-only value, the default LKG-preferred path applies.
   - `.egg-state/last-known-good/<branch>.sha` exists AND
     `git merge-base --is-ancestor <sha> HEAD` succeeds → use sha.
   - Otherwise, compute base branch from `$BASE_BRANCH` (default
     `main`) via `git merge-base HEAD origin/<base>`. If `origin/<base>`
     is missing or merge-base fails → fall back to full suite with
     trigger "unresolvable baseline".

4. **Diff → changed-files list**. `git diff --name-only <base>...HEAD`
   plus `git status --porcelain` for uncommitted work. Uncommitted
   changes ALWAYS participate; a dirty tree cannot have a clean LKG
   effect. Empty diff → full suite (conservative; empty diff from a
   fresh clone before any work should still be honest about coverage).
   Note: pure empty-tree diffs are rare in agent inner-loops (they
   almost always have at least one touched file), so "empty diff → full
   suite" is not a performance regression in practice.

5. **Fallback-trigger evaluation** (any of the following widens to
   full suite, short-circuiting further analysis):
   - Any changed path matches one of:
     `**/conftest.py`, `Makefile`, `pyproject.toml`, `uv.lock`,
     `.python-version`, `.github/workflows/test.yml`,
     `shared/tests/**`.
   - Any changed file has extension other than `.py` (decision-5).
   - Any changed path matches `gateway/*.py` (i.e., a production
     file directly under `gateway/`, NOT under `gateway/tests/`).
     **Trigger reason**: "gateway source change (importlib
     test-loader)". Rationale — `gateway/tests/conftest.py` uses
     `_load_module_with_replaced_imports` to load production
     modules via `importlib.util.spec_from_file_location`, so
     every gateway test imports production modules by bare name
     (`from policy import ...`, not `from gateway.policy import
     ...`). Grimp cannot see those edges; a change to
     `gateway/policy.py` would otherwise resolve an empty
     test-set. Widening to full suite is the simple, stable fix.
     This is a KNOWN static-analysis blind spot for this
     monorepo and is documented in
     `docs/guides/testing.md`. Risk_analyst R1 mitigation.
   - Any changed module is in, or reachable from, the set of
     modules the graph-construction pass identified as containing
     dynamic-import patterns (decision-10).
   - `select_tests.py` cannot resolve a changed path to an
     in-repo module (e.g., brand-new module not yet in grimp's
     graph, or a script under `scripts/` that has no wheel
     binding).
   - **Source-file staleness guard (runtime)**: during graph
     construction, the selector enumerates every `.py` file under
     the source roots (`gateway/`, `shared/`, `orchestrator/`,
     `sandbox/`, excluding `__pycache__/`, `.venv/`, and test
     directories) and confirms each path maps to a node in
     `graph.modules`. If any source `.py` file is NOT a node
     (e.g., missing `__init__.py`, encoding quirk, grimp cache
     bug), widen to full suite with trigger "source file
     missing from graph: <path>". Risk_analyst R2 mitigation.
     This is a cheap integrity check (one stat + one set
     intersect) and catches PACKAGES-vs-repo drift at runtime
     rather than only in the TASK-5-4 CI test.
   - Unresolvable baseline (no LKG ancestor + no `origin/<base>`).
   - LKG sha is not an ancestor of `HEAD` (e.g., after force-push /
     reset).
   - Canary trigger fires (every 10th invocation on the branch).

6. **Test-file mapping**. For each module in the reverse-closure set
   over changed modules, map module path → test file(s) via the same
   grimp graph (test roots are registered per §2, so test-module
   edges are visible). Algorithm: for each changed module `m`, take
   `graph.find_downstream_modules(m, as_package=<see below>)`, then
   intersect the downstream set with the pre-collected
   `all_test_modules` set (every `test_*.py` / `*_test.py` file
   node in the graph). The selector emits the resulting set of test
   file paths (not pytest test-id strings) so pytest's own collection
   handles intra-file filtering.

   **`as_package` semantics**: the selector uses a mixed strategy
   that reflects the semantic difference between a leaf-module edit
   and a package `__init__.py` edit:
   - If the changed path is an `__init__.py`, call
     `find_downstream_modules(<package>, as_package=True)` — a
     change to the package re-exports or to the package-level init
     logic can affect any downstream of the whole package.
   - Otherwise (regular `.py` leaf), call with `as_package=False`
     — a leaf-module change only affects downstream of that
     specific module.
   TASK-5-1 includes a unit test for each case: a leaf edit pulls
   in only downstream of the leaf; an `__init__.py` edit pulls in
   all downstream of the package.

7. **Intersect with `PYTEST_ARGS`**. If `PYTEST_ARGS` contains any
   token that resolves to an existing path under `tests/`,
   `gateway/tests/`, `orchestrator/tests/`, or `shared/tests/`, treat
   that as a developer override and bypass narrowing entirely (pass
   the args through unchanged). Otherwise, intersect: emit the
   selected test files AND pass `PYTEST_ARGS` through to pytest
   (so `-k`, `-x`, `-v`, `-m foo` compose correctly).

8. **LKG sidecar I/O** (`.egg-state/last-known-good/<branch>.sha`):
   - Write: `scripts/select_tests.py --record-good [--sha <sha>]`.
     Atomic write (tempfile + `os.replace`) so a concurrent reader
     never sees a half-written file. Branch derived from
     `git symbolic-ref --short HEAD`; detached HEAD → no write (log
     stderr notice `select-tests: detached HEAD; sidecar write
     skipped`, exit 0). Write-side sha validation: the argument (or
     HEAD) MUST satisfy (a) 40-character lowercase hex regex, (b)
     `git cat-file -e <sha>` success (object exists in repo), (c)
     `git merge-base --is-ancestor <sha> HEAD` success. On any
     validation failure, print an explicit error to stderr
     (`select-tests: --record-good validation failed: <reason>`)
     and exit non-zero WITHOUT writing the sidecar. This prevents a
     typo or stale value silently poisoning the sidecar.
   - Read: on `make test` narrowing path, read the sidecar and
     validate as a 40-hex-char sha (else treat as absent). In
     read-only roles (Q13) the read is skipped entirely.
   - Detached-HEAD on the read path: the sidecar is keyed by
     branch name, so a detached HEAD has no sidecar to read. Emit
     stderr notice `select-tests: detached HEAD; using base branch
     baseline, sidecar reads/writes skipped` so agents know why
     narrowing fell to the base-branch path. Test in TASK-5-3.
   - Never updated on partial pass (Q12) — only `make test-all`
     invokes `--record-good` after a green pytest.

9. **Canary counter**. Per-branch counter at
   `.egg-state/last-known-good/<branch>.canary`, incremented on every
   `make test` narrow-mode invocation. When `count % 10 == 0`, force
   full suite with trigger "canary (every-10th invocation)" and reset
   counter to 0. Counter file is bare integer, gitignored.

10. **Structured logging**. Every `make test` invocation logs to
    stderr a one-line human-readable decision record in the form
    `select-tests: narrowed 47/356 tests in 0.18s (baseline=abc1234, trigger=diff)`
    or
    `select-tests: full suite 356 tests (trigger=Makefile changed)`.
    Additionally, a JSON record is persisted to
    `.egg-state/selection/<head_sha>.json` with fields:
    `{schema_version (integer, currently 1), head, baseline (object
    with sha + source ∈ {"LKG", "BASE_BRANCH"}), branch, mode
    (narrow | full_suite | bypass), trigger (explicit enum string or
    "none"), selected_count, total_count, compute_ms, pytest_ms
    (written by Makefile after pytest returns), timestamp,
    canary_fired (bool), changed_files (list), changed_modules (list),
    dynamic_import_seeds_hit (list)}`. `schema_version` pins the
    envelope so future consumers can detect drift; bump to 2 only
    on a backward-incompatible change. The JSON file is gitignored.

11. **`--why <test>` introspection**. Loads the grimp graph, finds
    the shortest import path from any changed module to the given
    test module, prints the chain one module per line with "via"
    arrows. If the test is not in the selection, prints "test is
    not in the selected set; closest reachable chain from changed
    modules follows" or "no path exists".

12. **Makefile wiring** (`Makefile` at lines 251-291 in the current
    tree):
    - `test` target becomes narrowed-default: invokes
      `scripts/select_tests.py`, feeds its stdout into
      `pytest $(SELECTED) -v -m "not functional" $(PYTEST_ARGS)`. If
      the selector emits zero lines, skip the pytest invocation and
      print a summary "no tests selected". Timing is wall-clock
      wrapped and the pytest result code is surfaced. After a green
      narrowed pass, `test` does NOT update LKG (Q12).
    - `test-all` target: runs the current full-suite command
      (`pytest tests/ gateway/tests/ orchestrator/tests/ shared/tests/
      -v -m "not functional" $(PYTEST_ARGS)`). On green exit, calls
      `scripts/select_tests.py --record-good` to atomically write the
      sidecar. On red exit, does NOT update LKG.
    - `test-record-good` target: calls
      `scripts/select_tests.py --record-good` unconditionally (manual
      override for cases where the developer knows the suite passed
      but `make test-all` wasn't the path).
    - `make help` gains entries for `test-all` and `test-record-good`
      in the CI-checks section (Makefile lines ~50-52).

13. **CI switch** (`.github/workflows/test.yml`). Change the unit-job
    step from
    `make test PYTEST_ARGS="--cov=gateway --cov=shared --cov=sandbox --cov-report=term-missing --cov-fail-under=80"`
    to
    `make test-all PYTEST_ARGS="--cov=gateway --cov=shared --cov=sandbox --cov-report=term-missing --cov-fail-under=80"`.
    No `fetch-depth` change (full-suite path does not need the
    baseline ref).

14. **.gitignore additions**:
    ```
    .egg-state/last-known-good/
    .egg-state/selection/
    ```
    (Note: `.egg-state/` as a whole is not currently ignored — drafts,
    contracts, reviews, brc-history, oversight live inside it and are
    tracked. Two targeted subdirectories only.)

15. **Documentation**:
    - New `docs/guides/testing.md` — canonical testing guide covering
      `make test` narrow default, `make test-all`, `make test-record-good`,
      sidecar LKG semantics, fallback triggers, `--why` introspection,
      canary mode, structured logging, known limits (dynamic imports,
      subprocess crossings), pointers to the pytest markers defined
      in `pyproject.toml`.
    - `CONTRIBUTING.md` (lines 65-87 testing section) gains a
      one-line pointer: "See `docs/guides/testing.md` for changeset-
      aware test selection, LKG semantics, and fallback triggers."

### What explicitly does NOT change

- `orchestrator/tests/conftest.py`, `gateway/tests/conftest.py`,
  `shared/tests/conftest.py`, `tests/conftest.py` — not modified.
  Any change to these files is a fallback trigger.
- `gateway/tests/conftest.py`'s `_load_module_with_replaced_imports`
  importlib-based test loader (lines 47-85) is explicitly NOT
  refactored. The R1 mitigation accepts the loader's invisibility
  to grimp and widens `gateway/*.py` edits to full suite; a
  conftest refactor to standard imports would be a separate,
  larger, gateway-scoped change beyond this PR's scope.
- Integration / e2e / security test targets (`test-integration`,
  `test-e2e`, `test-security`) — remain full-suite-only (Q10).
- Coverage gate (`--cov-fail-under=80`) — unchanged; CI picks it up
  through `make test-all`.
- Pre-commit hooks, pre-merge hooks, merge behavior — no changes
  (d6 leaves LKG as-is through merge; sidecar is per-branch).
- Python SDK MCP surface — no changes; this is a Makefile / script
  change only.

### Risk summary — cross-references to risk_analyst output

The canonical risk register is
`.egg-state/agent-outputs/1973-risk_analyst-output.json` (R1 through
R15, overall recommendation `PROCEED_WITH_MITIGATIONS`). Mitigations
this plan explicitly adopts:

- **R1 — static graph misses gateway's importlib-based test loader
  (HIGH × HIGH)**. Mitigation: hard-coded gateway/*.py → full-suite
  fallback trigger in TASK-2-3 (algorithm §5); test in TASK-5-2;
  documented blind-spot note in TASK-6-1.
- **R2 — cross-root edges dropped if grimp misses a root (HIGH ×
  MEDIUM)**. Mitigation: PACKAGES constant enumerates every source
  and test root (§2 architecture); runtime source-file staleness
  guard in TASK-2-3 walks every non-test `.py` and widens to full
  suite on any missing node; exhaustive CI test in TASK-5-4
  ("every test_*.py is a node") + corresponding test in TASK-5-2
  for the source-side runtime check.
- **R5 — PYTEST_ARGS parse ambiguity (MEDIUM × HIGH)**. Mitigation:
  classify any PYTEST_ARGS token that resolves to an existing path
  under the four test roots as a developer override (bypass
  narrowing), otherwise intersect. Ambiguous-token test case in
  TASK-5-4 (e.g. `--hypothesis-seed=gateway/tests/helper.py`) locks
  the classifier against regressions. EGG_TEST_SELECT=off env var
  opt-out deferred (Q5 resolved to "intersect by default").
- **R6 — grimp graph-build cost (LOW × MEDIUM)**. Mitigation:
  configure grimp's `cache_dir` to `.egg-state/grimp-cache/`
  (TASK-2-1); gitignore the directory (TASK-1-2).
- **R7 — unbounded selection / LKG accumulation (LOW × HIGH)**.
  Decision adopted: **no automated pruning**; the directories are
  gitignored, accumulate on disk, and `rm -rf
  .egg-state/selection/` / `rm -rf .egg-state/last-known-good/` is
  the documented recovery. Rationale: simpler code; aligns with
  architect's `logging_format.retention` note; per-invocation
  pruning adds filesystem churn and a subtle GC dependency for
  marginal disk savings. Documented in TASK-6-1.
- **R10 — backward-compat for external `make test` callers (MEDIUM
  × MEDIUM)**. Audit conducted in plan phase: the only repo-wide
  `make test` callers are `.github/workflows/test.yml` (switched
  to `test-all` in TASK-4-1), `CONTRIBUTING.md` testing section
  (enhanced by TASK-6-2 pointer), and `make help` (updated in
  TASK-3-2). No other call sites depend on full-suite semantics.
- **R14 — read-only role detection (LOW × LOW)**. Mitigation:
  TASK-2-2 checks `EGG_AGENT_ROLE` env var AND `.egg-readonly`
  marker file; either presence triggers the base-branch-only
  path. Parametrized in TASK-5-3.
- **Dynamic imports (decision-10)**: scan-during-graph-construction
  + widening to full suite; canary-every-10th catches silent
  drift.
- **Stale LKG after force-push / reset**: LKG-not-an-ancestor-of-
  HEAD detection triggers full suite.
- **Non-Python resource changes**: any non-`.py` change is a hard
  full-suite trigger.
- **Concurrent sidecar writes**: last-writer-wins with atomic
  rename; both values represent green state (Q9).

- **Graph construction** (`tests/tools/test_select_tests_graph.py`).
  Synthetic mini-repo fixtures with known import edges; assert

  variety of changed-file inputs (leaf module, mid-layer module,
  cross-package edge, namespace-package edge, `TYPE_CHECKING`-only
  edge).
- **Fallback triggers** (`tests/tools/test_select_tests_fallbacks.py`).
  Parametrized cases for each trigger from §5: conftest change,
  Makefile change, `pyproject.toml` change, `uv.lock` change,
  `.python-version` change, workflow change, `shared/tests/**` change,
  non-`.py` change, unresolvable baseline, LKG-not-ancestor, canary-
  every-10th, dynamic-import module, unresolvable module path.
- **Baseline resolution** (`tests/tools/test_select_tests_baseline.py`).
  Sidecar present-and-ancestor; sidecar present-but-not-ancestor;
  sidecar absent → base-branch; base-branch missing → unresolvable.
- **LKG I/O** (`tests/tools/test_select_tests_lkg.py`). Atomic
  write/read round-trip; detached-HEAD skip with warning; malformed
  sidecar contents treated as absent; per-branch isolation.
- **PYTEST_ARGS intersect** (`tests/tools/test_select_tests_pytest_args.py`).
  `-k`, `-x`, `-v`, `-m foo` compose with narrowing; explicit path
  in `PYTEST_ARGS` bypasses narrowing; mixed args (flag + path)
  classified as override.
- **`--why` introspection** (`tests/tools/test_select_tests_why.py`).
  Import chain printed for selected test; "not in selection" message
  for unselected test; "no path exists" for unreachable test.
- **Structured logging** (`tests/tools/test_select_tests_logging.py`).
  Stderr line format matches spec; JSON file at
  `.egg-state/selection/<sha>.json` has expected keys and types;
  trigger names are explicit strings.
- **Canary counter** (`tests/tools/test_select_tests_canary.py`).
  Counter increments; fires on every 10th invocation; resets on
  fire; `--full-suite` mode resets counter.
- **Grimp monorepo config** (`tests/tools/test_select_tests_monorepo.py`).
  Exhaustive staleness guard: every `test_*.py` under the four test
  roots is a node in the graph built from `PACKAGES`. Plus at least
  one known cross-package edge from `orchestrator`,
  `shared.egg_contracts`, `gateway`, and `sandbox` resolves
  correctly.
- **Read-only role handling** (covered in
  `tests/tools/test_select_tests_baseline.py` per TASK-5-3).
  `EGG_AGENT_ROLE=reviewer_*` / `refiner` bypass the sidecar;
  `coder` / unset use the LKG-preferred path.
- **Fail-open contract** (covered in
  `tests/tools/test_select_tests_fallbacks.py` per TASK-5-2).
