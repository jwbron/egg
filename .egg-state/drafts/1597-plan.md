# Plan: Fix restart losing worktrees by gating on repos not repo_volumes

## Summary

The fix is a single-line condition change in `spawn_agent_container()`. By changing the per-agent worktree creation guard from `if repo_volumes and repos:` to `if repos:`, worktrees are always created (or reused) when repos are specified — regardless of whether the caller provided `repo_volumes`. This fixes both `restart_phase` and `restart_agent` without modifying those callers, since the gateway's idempotent `create_worktree` will find the existing worktree and return its host paths for mounting.

**Risks / edge cases**: None identified — `repo_volumes` was never read inside the block (only overwritten), so the change has no effect on callers that already pass `repo_volumes`. The `preserve_worktree_on_failure=True` flag used by restart paths prevents cleanup on Docker failure.

## Implementation

### Phase 1: Implement

Fix the worktree creation guard and add test coverage for the restart code path.

**Tasks**:
1. **[task-1-1]** In `orchestrator/container_spawner.py:spawn_agent_container()`, change the worktree creation guard at line 308 from `if repo_volumes and repos:` to `if repos:` — `repo_volumes` served only as a truthy flag and is always overwritten by the gateway result. Acceptance: spawn_agent_container with repos but no repo_volumes triggers gateway.create_worktrees and mounts result.
2. **[task-1-2]** Add a test in `orchestrator/tests/test_container_spawner.py` that verifies `spawn_agent_container` creates per-agent worktrees when `repos` is provided but `repo_volumes` is `None` (the restart path). Acceptance: Test passes and covers the restart code path.
