# Plan: Define agent team roster, roles, and access controls

> Issue: #1030 | Phase: plan

## Summary

Formalize the agent roster for the async, self-organizing agent team model.
This consolidates the triple-defined `AgentRole` enum into a single source of
truth with category metadata, adds two new utility roles (`AUTOFIXER`,
`CONFLICT_RESOLVER`), cleans up vestigial `integrator` test references,
generalizes the concurrent execution gate to all phases, updates gateway
file-restriction patterns for new roles, and updates all documentation to
reflect universal concurrency support across all agent categories.

## Approach

The implementation follows **Option B** from the architect analysis:
**Consolidated Role Registry with Category Metadata**. This consolidates the
`AgentRole` enum (currently duplicated in 3 files) into
`shared/egg_contracts/agent_roles.py` as the single source, adds an
`AgentCategory` enum (`EXECUTION`, `ANALYSIS`, `REVIEW`, `UTILITY`,
`INTERFACE`), and adds two new roles.

### Why Option B

- Eliminates the sync-hazard of maintaining three identical enums
- Category metadata enables dynamic team composition queries (e.g., "all review agents")
- Better foundation for the team framework (#1028)
- Builds on the already-functional role system without over-engineering

### Key Decisions Pending (HITL)

Four decisions registered in the contract remain unresolved. The plan proceeds
with **default assumptions** that the coder should follow unless a HITL
resolution arrives before implementation:

| Decision | Default Assumption |
|----------|-------------------|
| decision-1: Tester source-file write access | Keep broad write access (current) — auto-fix workflow depends on it |
| decision-2: COORDINATOR role | Defer to #1028 — avoid scope creep |
| decision-3: Enum consolidation | Consolidate to single source (Option B) |
| decision-4: Gateway enforcement default | Keep warn-only default — enforcement is a behavioral change requiring its own rollout |

If HITL resolutions differ from assumptions, the coder should adapt accordingly.

### Scope Boundaries

**In scope:**
- `AgentRole` enum consolidation (3 files → 1 source + re-exports)
- `AgentCategory` enum and category metadata on `AgentRoleDefinition`
- New roles: `AUTOFIXER`, `CONFLICT_RESOLVER` (with gateway patterns)
- Vestigial `integrator` reference cleanup in test fixtures
- Generalizing `ConcurrentPhaseExecutor` phase gate and role selection
- Gateway `AGENT_PATTERNS` entries for new roles
- Documentation updates (agent-roles.md, guides, CLAUDE.md, architecture docs)

**Out of scope (deferred to other issues):**
- `COORDINATOR` role (deferred to #1028)
- Gateway enforcement mode change (decision-4 defaults to warn-only)
- Cross-agent messaging implementation (#1027)
- Overseer implementation (#1059)
- Shared worktree infrastructure

### What Already Works

The codebase is more advanced than the issue description suggests:

- `ConcurrentPhaseExecutor.get_agent_roles()` already calls `get_roles_for_phase(phase)` dynamically — not hardcoded to implement-phase roles
- `is_concurrent_execution()` already supports `concurrent_phases` config (defaults to `["refine", "plan", "implement"]`)
- `reviewer_unified` and `checker` are already removed from enums with migration logic in place
- Gateway `AGENT_PATTERNS` already has entries for all 13 current roles
- Consensus evaluator, message bus, and readiness signaling are already phase-agnostic

## Phases

### Phase 1: Enum Consolidation and Category Metadata

Consolidate the three `AgentRole` enum definitions into
`shared/egg_contracts/agent_roles.py` as the single source. Add an
`AgentCategory` enum. Update `AgentRoleDefinition` to include category.
Make `orchestrator/models.py` and `shared/egg_orchestrator/types.py`
import from the canonical source (or re-export for backward compatibility).

This is the foundation — all subsequent phases depend on a clean, single
source of truth for roles.

**Key considerations:**
- `orchestrator/models.py` has extra roles (`INSPECTOR`, `REVIEWER` generic) not in `agent_roles.py`. These must be reconciled — `INSPECTOR` is a health-check role that should be kept; `REVIEWER` is a generic alias that should be removed or mapped.
- Pydantic model validators in `orchestrator/models.py` use the enum for deserialization. The import-and-re-export pattern must preserve this.
- The `_REMOVED_ROLE_MIGRATION` dict in `orchestrator/models.py` must remain functional for backward-compat deserialization.

### Phase 2: New Roles and Updated Role Definitions

Add `AUTOFIXER` and `CONFLICT_RESOLVER` to the `AgentRole` enum and create
their `AgentRoleDefinition` entries with category=`UTILITY`. Update all
existing role definitions to include their `AgentCategory`. Update
`_PHASE_ROLES` and `_PHASE_REVIEWERS` mappings if needed. Update
the gateway's mirror `AgentRole` class in `agent_restrictions.py`.

### Phase 3: Gateway File Restrictions for New Roles

Add `AGENT_PATTERNS` entries in `gateway/agent_restrictions.py` for
`AUTOFIXER` and `CONFLICT_RESOLVER` with the write/block patterns specified
in the issue:

- **Autofixer**: writable = source files + config files; blocked = `docs/`, `**/*.md`, `.egg-state/contracts/`
- **Conflict Resolver**: writable = source + test + docs + config; blocked = `.egg-state/`

### Phase 4: Vestigial Role Cleanup

Clean up remaining `integrator` references in test fixtures:
- `orchestrator/tests/test_concurrent_integration.py` — replace `integrator` with a valid current role (e.g., `documenter`) in test fixtures
- `orchestrator/tests/test_dag_visualizer.py` — same
- `gateway/worktree_manager.py` — remove comment reference

These are test-level changes only; no production role changes needed since
`integrator` is already absent from all enums.

### Phase 5: Concurrent Execution Generalization

Ensure `ConcurrentPhaseExecutor` has no residual phase-specific gates:

- Verify `is_concurrent_execution()` accepts any phase in `concurrent_phases` config
- Verify `get_agent_roles()` returns dynamic role sets for all phases
- Add `"review"` to default `concurrent_phases` list if not present
- Ensure `EGG_CONCURRENT_MODE` is set based on whether the phase is concurrent, not by phase name

Most of this is already in place. The main code change is adding `"review"` to the default concurrent phases and verifying there are no hardcoded phase checks remaining.

### Phase 6: Documentation Updates

Update all documentation to reflect the new roster and universal concurrency:

- `docs/reference/agent-roles.md` — comprehensive roster with categories, access controls, team templates
- `docs/guides/` — SDLC pipeline guide, agent development guide
- `docs/architecture/` — system design docs referencing concurrency model
- `sandbox/` — CLAUDE.md concurrent execution section (generalize beyond implement-phase)
- Component READMEs — `orchestrator/`, `gateway/`, `shared/`

### Phase 7: Tests

Add/update tests to validate the new roster:

- Sync test: verify `orchestrator/models.py` and `shared/egg_orchestrator/types.py` AgentRole values match canonical source
- Category test: verify all roles have a category assigned
- New role tests: verify `AUTOFIXER` and `CONFLICT_RESOLVER` have valid definitions and gateway patterns
- Concurrent execution tests: verify all phases can be concurrent
- Migration test: verify removed roles still deserialize correctly

## Test Strategy

1. **Run existing tests first** to establish a green baseline
2. **Unit tests** for each phase:
   - Enum consolidation: import tests, Pydantic deserialization tests
   - New roles: role definition completeness, gateway pattern validation
   - Concurrent execution: phase support verification
3. **Integration tests**: verify `ConcurrentPhaseExecutor` works with new roles
4. **Regression tests**: ensure `_REMOVED_ROLE_MIGRATION` still works, existing gateway patterns unchanged
5. **Run `make lint` and `make test`** after each phase to catch breakage early

## Risk Mitigations

| Risk | Mitigation |
|------|-----------|
| Import cycle from consolidation | Use re-export pattern: `orchestrator/models.py` imports from `egg_contracts.agent_roles` and re-exports |
| Pydantic validator breakage | Keep `AgentRole` as a `StrEnum` with same string values; migration dict stays in models.py |
| Gateway pattern mismatch | Gateway `AgentRole` class uses string constants (no import dependency); update independently and add sync test |
| Test fixture breakage from integrator cleanup | Replace `integrator` with valid role (`documenter`) in affected fixtures; minimal functional change |
| Concurrent phase default change | Adding `"review"` to defaults is backward-compatible since pipelines without review agents simply skip it |

## Dependency Ordering

```
Phase 1 (Enum Consolidation)
    └── Phase 2 (New Roles) ─── depends on enum being consolidated
         ├── Phase 3 (Gateway Patterns) ─── depends on new role definitions
         └── Phase 4 (Vestigial Cleanup) ─── independent, can parallel with 3
    └── Phase 5 (Concurrent Generalization) ─── depends on role definitions
Phase 6 (Documentation) ─── depends on all code phases (1-5) being stable
Phase 7 (Tests) ─── runs incrementally with each phase, final suite at end
```
