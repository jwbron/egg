# Plan: Remove per-phase/task breakdown delegation from implement phase

> Issue: #1165 | Phase: plan | Revision: 3

## Summary

This plan collapses all conditional execution paths in the implement phase into a
single code path: every phase always runs concurrent BRC execution. The work
removes Tier 3 phase-level dispatch, multi-agent wave execution, single-agent
fallback, short-circuit mode, complexity tiers, the integrator role, and all
associated configuration — approximately 5000-6000 lines across ~30 files.

The work is organized into four phases within a single PR: (1) prerequisite
relocations and refactors, (2) core orchestrator removal, (3) configuration,
gateway, and role cleanup, and (4) documentation and test cleanup. Each phase
builds on its predecessor; the ordering prevents broken intermediate states by
ensuring dependencies are relocated before their source files are deleted.

## Architecture Analysis Summary

The analysis (`.egg-state/drafts/1165-analysis.md`) identified 47 discrete
removal items organized into 9 categories (A-I). Key findings:

- **Two prerequisite refactors** must happen before bulk deletion:
  `is_concurrent_execution()` must move from `multi_agent.py` to
  `concurrent_executor.py`, and `signals.py` must be refactored to inline
  dispatch calls before `dispatch.py` can be deleted.
- **PR #1171** (docs: add integrator to concurrent implement phase roles) has
  been **merged** — the integrator docs it added will be removed as part of this
  work.
- **No backward compatibility**: old `.egg-state/pipelines/*.json` files with
  removed fields will fail validation intentionally. Clean break.

## Pending Decisions

**Decision 1** (PR splitting): Moot — pipeline constraint requires a single PR.

**Decision 2** (PR #1171): Resolved — PR #1171 is merged. Its integrator docs
will be removed in Phase 4.

**Decision 3** (config flags `concurrent_execution` / `concurrent_phases`): The
analysis recommends removal since BRC is now the only mode. This plan assumes
removal in Phase 3. If the decision resolves to "keep as kill switches," TASK-3-4
adjusts to retain the flags and wire them to a no-op/bypass path instead.

## Test Strategy

- **Run tests before any changes** (baseline) to identify pre-existing failures.
- **Run `make test` after each task** — every task's acceptance criteria includes
  passing tests. This ensures no broken intermediate states.
- **Phase 1** (relocations): Tests verify that relocated functions work identically
  and all import sites are updated.
- **Phase 2** (core removal): Tests verify the implement phase routes exclusively
  to concurrent BRC. Removed test targets are expected to fail/be absent.
- **Phase 3** (config/gateway): Tests verify no gateway or config references to
  removed concepts.
- **Phase 4** (test cleanup): Delete dead tests, update surviving tests, then
  final `make test` + `make lint` + stale reference grep for clean bill of health.
- **No new tests needed**: This is a pure deletion/simplification. Existing
  concurrent BRC tests validate the remaining code path.

## Risk Mitigations

| Risk | Mitigation |
|------|------------|
| Broken intermediate state during deletion | Strict phase ordering: relocate deps → delete sources → clean up config → clean up docs/tests |
| Missing stale references | TASK-4-4 greps entire codebase for removed concept names |
| Decision 3 not resolved before implement | Plan assumes removal; TASK-3-4 has explicit contingency for "keep" |
| Old pipeline JSON files fail validation | Intentional per analysis — clean break, no migration |
| `metadata.complexity_tier: high` in refine output consumed by current orchestrator | After removal, this field is ignored — refine output is free-form text consumed by plan phase prompts, not validated against a schema |
