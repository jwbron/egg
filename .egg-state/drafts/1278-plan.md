# Implementation Plan: Replace GHA review workflows with babysit-pr pipelines

> Issue: #1278 | Phase: plan | Agent: task_planner

## Overview

Replace eight GHA review/fix workflows and six bash prompt builders with a single
orchestrator-based babysit-pr pipeline triggered on push to PR branches. The
babysit-pr cycle uses concurrent fixer + reviewer agents coordinating via BRC
consensus, running through the Agent SDK exclusively.

This is a **single-PR cutover**: one PR adds the concurrent pipeline, deletes the
old workflows/scripts, and stops calling `gha_exec()` from the replaced
workflows. `gha_exec()` itself is retained because `on-push-doc-updater.yml`
and `reusable-autofix.yml` (both out of scope) still route through the GHA
action which calls it. The PR validates itself — the babysit-pr cycle exercises
against its own review.

## Approach

The work splits into five phases within the single PR, ordered by dependency:

1. **Concurrent BRC engine** — Restructure `BabysitLoop` from sequential state
   machine to concurrent agent pipeline with BRC consensus.
2. **Prompt consolidation** — Ensure Python prompt modules cover all review
   criteria (base, contract, agent-mode design) with conditional inclusion.
3. **Pipeline trigger** — Add the single GHA workflow that invokes babysit-pr
   on push, with concurrency/deduplication controls.
4. **GHA/script deletion** — Delete old workflows and bash scripts. Note:
   `gha_exec()` is NOT removed because out-of-scope workflows still use it.
5. **Testing & validation** — Unit tests for BRC integration, integration tests
   for the full cycle, and manual validation against the cutover PR itself.

## Dependency Graph

```
Phase 1 (BRC engine) ──┬──> Phase 3 (trigger) ──> Phase 4 (deletion) ──> Phase 5 (validation)
Phase 2 (prompts)  ────┘
```

Phases 1 and 2 are independent and can be committed in any order. Phase 3
depends on both. Phase 4 depends on 3. Phase 5 spans the entire PR.

## Phase 1: Concurrent BRC Engine

**Goal**: Restructure `BabysitLoop` to run fixer and reviewer agents concurrently
using BRC consensus, replacing the sequential state machine.

### TASK-1-1: Define babysit-pr pipeline mode and agent roles

Add `PipelineMode.BABYSIT` support (verify already exists in orchestrator) and
define babysit-specific agent roles (`babysit_fixer`, `babysit_reviewer`). Define
the review graph topology: reviewer → fixer (CRITICAL edge). Update
`BabysitConfig` with BRC-related parameters (consensus timeout, flip-flop cap).

**Files**: `shared/egg_babysit/config.py`, `shared/egg_babysit/types.py`

**Acceptance**: `BabysitConfig` includes `consensus_timeout_minutes` and
`max_consensus_rounds` fields. Agent role constants defined. Review graph
configuration for fixer/reviewer is specified.

### TASK-1-2: Refactor BabysitLoop to concurrent phase execution

Replace the sequential `while` loop in `loop.py` with a phase-based concurrent
executor. Each phase (conflict resolution, CI fix, review+feedback) spawns
agents concurrently and waits for BRC consensus before advancing. Preserve the
existing step ordering: `CHECK_CONFLICTS → WAIT_CI → FIX_CHECKS → WAIT_CI →
REVIEW → ADDRESS_FEEDBACK`.

The key change: within the REVIEW → ADDRESS_FEEDBACK phase, fixer and reviewer
run concurrently. Fixer proposes changes; reviewer ACKs/NACKs. They iterate
via BRC until consensus or escalation.

**Files**: `shared/egg_babysit/loop.py`, new `shared/egg_babysit/concurrent.py`

**Acceptance**: `BabysitLoop.run()` spawns fixer and reviewer concurrently for
the review/feedback phase. BRC consensus is used for the review cycle. Sequential
phases (conflict, CI wait, check fix) remain sequential. Existing exit
conditions (timeout, max iterations, escalation) still function. Loop state
tracks BRC consensus phase.

### TASK-1-3: Update fixer and reviewer agent spawning for BRC

Modify `fixer.py` and `reviewer.py` to use `build_consensus_wrapped_command()`
(from `orchestrator/consensus_wrapper.py`) instead of plain
`build_agent_command()`. Inject BRC environment variables
(`EGG_CONCURRENT_MODE`, `EGG_BRC_ROLE_TYPE`, `EGG_BRC_REVIEWERS`,
`EGG_BRC_PRODUCERS`). Add message bus integration for cross-agent coordination
(HANDOFF messages when fixer pushes commits).

**Files**: `shared/egg_babysit/fixer.py`, `shared/egg_babysit/reviewer.py`

**Acceptance**: Fixer agent starts with `EGG_BRC_ROLE_TYPE=producer` and uses
consensus propose/confirmed flow. Reviewer agent starts with
`EGG_BRC_ROLE_TYPE=reviewer` and ACKs/NACKs fixer proposals. Both agents
communicate via orchestrator message bus. Non-LLM fix path still works
(auto-propose on success).

### TASK-1-4: Add BRC consensus signaling to agent prompts

Update prompts in `prompts.py` to include BRC consensus instructions for agents.
Fixer prompts include: "When you've completed fixes, run `egg-orch consensus
propose`". Reviewer prompts include: "After reviewing, run `egg-orch consensus
ack` or `egg-orch consensus nack`". Add instructions for handling NACKs
(withdraw, fix, re-propose).

**Files**: `shared/egg_babysit/prompts.py`

**Acceptance**: All four prompt builders (check_fixer, reviewer, conflict,
feedback) include BRC consensus instructions when concurrent mode is active.
Prompts degrade gracefully to non-BRC mode when `EGG_CONCURRENT_MODE` is not
set (backward compatibility for manual invocation).

## Phase 2: Prompt Consolidation

**Goal**: Consolidate three review criteria (base code, contract verification,
agent-mode design) into the single reviewer agent with conditional inclusion.

### TASK-2-1: Implement conditional review criteria in reviewer prompt

Update `build_review_prompt()` to conditionally include contract verification
criteria (when `sdlc:pr` label is present on the PR) and agent-mode design
review criteria (when changed files match `action/`, `.github/workflows/`,
`sandbox/`, `shared/prompts/` patterns). Base code review criteria are always
included. Pull criteria content from existing `shared/prompts/` files.

**Files**: `shared/egg_babysit/prompts.py`, `shared/egg_babysit/pr_state.py`

**Acceptance**: Reviewer prompt includes all three review domains when applicable.
Contract verification only appears with `sdlc:pr` label. Agent-mode design
review only appears when relevant files are changed. No review criteria from
the existing bash scripts are lost. Prompt builder reads criteria from
`shared/prompts/` source files (not hardcoded).

### TASK-2-2: Implement status comment lifecycle and stale comment management

Build new status comment management in babysit-pr. The current GHA workflows
use `<!-- egg-status-comment -->` HTML markers to find and minimize prior bot
status comments as "OUTDATED" via GraphQL mutations. This logic exists only in
the GHA workflow YAML (e.g., `reusable-autofix.yml`, `reusable-check-fixer.yml`,
`on-review-feedback.yml`) — it does **not** exist in babysit-pr today.

Implement: (1) post status comments with `<!-- egg-status-comment -->` markers,
(2) find and minimize prior status comments before posting new ones,
(3) deduplication to avoid duplicate comments on the same commit.

**Files**: `shared/egg_babysit/steps/review.py`, `shared/egg_babysit/reviewer.py`,
new `shared/egg_babysit/comments.py`

**Acceptance**: Babysit-pr posts status comments with HTML markers matching
current GHA format. Prior status comments from the same bot are minimized
before new ones are posted. No duplicate comments on the same commit. Logic
is reusable across all babysit steps (review, check fix, conflict resolution).

## Phase 3: Pipeline Trigger

**Goal**: Add the GHA workflow that triggers a babysit-pr cycle on push to PR
branches, with deduplication controls.

### TASK-3-1: Create push-triggered babysit workflow

Create `.github/workflows/on-push-babysit.yml` that triggers on
`pull_request: [opened, synchronize, ready_for_review, reopened]`. The workflow
calls the orchestrator API to create a babysit pipeline (`mode=babysit`) for
the PR. Include concurrency group (`egg-babysit-${{ github.event.pull_request.number }}`)
to cancel in-flight cycles on new pushes (matching current GHA deduplication).

**Files**: `.github/workflows/on-push-babysit.yml`

**Acceptance**: Workflow triggers on PR push events. Creates orchestrator pipeline
with `mode=babysit`. Concurrency group prevents duplicate cycles on rapid pushes.
Supports `workflow_dispatch` for manual trigger with PR number input. Workflow
uses the existing action infrastructure (entrypoint, container setup) but invokes
`egg-babysit` instead of `gha_exec()`.

### TASK-3-2: Extend existing babysit pipeline with BRC agent registration

The orchestrator already supports `mode=babysit` (`PipelineMode.BABYSIT` in
`models.py`, pipeline creation in `routes/pipelines.py` generating `pr-{N}` IDs).
This task extends the existing endpoint to also: (1) register fixer and reviewer
agent entries with appropriate permissions (fixer=read-write, reviewer=read-only),
(2) initialize the BRC review graph (reviewer → fixer, CRITICAL edge), and
(3) set BRC environment variables for the spawned agents.

**Files**: `orchestrator/routes/pipelines.py`, `orchestrator/models.py`

**Acceptance**: `POST /api/v1/pipelines` with `mode=babysit` creates a pipeline
with fixer and reviewer agents registered. BRC review graph is initialized with
reviewer → fixer CRITICAL edge. Agents receive correct `EGG_BRC_*` environment
variables. Existing `pr-{N}` ID generation and `pr_number` validation preserved.

## Test Strategy

| Layer | What | How |
|-------|------|-----|
| **Unit** | BRC consensus flow, prompt building, config | pytest with mocked subprocess/message bus |
| **Unit** | Review criteria conditional inclusion | pytest with label/file fixtures |
| **Integration** | Pipeline lifecycle, agent registration | pytest against running orchestrator |
| **Integration** | Message bus fixer↔reviewer communication | pytest with real Redis streams |
| **E2E** | Self-validation against cutover PR | Manual: babysit-pr cycle runs on this PR during review |
| **Regression** | Existing babysit-pr tests | `make test` — must all pass |

## Risk Mitigations

| Risk | Mitigation |
|------|------------|
| Race conditions between fixer pushes and reviewer reads | Reviewer is read-only; HANDOFF messages signal push completion; reviewer re-evaluates after push |
| BRC consensus doesn't converge | Flip-flop cap (3), revision round cap (2), consensus timeout → HITL escalation |
| External consumers of `reusable-autofix.yml` break | Keep `reusable-autofix.yml` and `build-autofixer-prompt.sh` out of scope |
| Review criteria lost during consolidation | Conditional inclusion pulls from existing `shared/prompts/` files; diff against bash scripts to verify parity |
| `gha_exec()` still needed by out-of-scope workflows | Retain `gha_exec()` — `on-push-doc-updater.yml` and `reusable-autofix.yml` both route through it. Document for future removal. |
| Concurrent agents double token costs | Sequential fallback mode preserved (non-BRC) for cost-sensitive contexts |

## Open Questions for HITL

These decisions from the analysis should be resolved before implementation:

1. **Trigger mechanism**: New `on-push-babysit.yml` (recommended) vs. orchestrator webhook vs. repurpose existing workflow
2. **`on-check-failure.yml`**: Delete (recommended, babysit-pr handles check fixing) vs. rewire to trigger babysit cycle
3. **Review marker format**: Preserve existing markers (recommended for backward compat) vs. new BRC-aware format
4. **Pipeline deduplication**: GHA concurrency group cancel-in-progress (recommended) vs. orchestrator-level debounce
5. **Feedback iteration limit**: Keep at 5 (recommended) or adjust for concurrent model
