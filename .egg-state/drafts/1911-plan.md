# Plan: Sync pipeline state after implement-phase push + PR creation

## Summary

Fix three distinct bugs in the orchestrator that co-occur to create the false-positive "post-consensus-push-stall" overseer alert on successful implement-phase completions:

1. Auto-PR creation in `_finalize_pr_phase_failed` (`orchestrator/routes/pipelines.py:4985`) stores only `phase_execution.artifacts["pr_url"]`. It never writes `pipeline.pr_number` / `pipeline.pr_head_sha`, which were designed for babysit-mode (pipeline-creation time) but are now read by issue-mode consumers (overseer, `get_pipeline_snapshot`, babysit-worker handoffs).

2. The overseer stall detector `_check_post_consensus_stall` (`orchestrator/overseer/monitor.py:1065`) only checks `consensus.is_complete` and `pipeline.status == "running"`. That matches any legitimate implement→pr→complete transition that exceeds its 90s grace window, producing false-positive `[high]` alerts.

3. Per-agent commit SHA population at `orchestrator/routes/pipelines.py:7913–7916` relies on `_brc.get_proposal_commit_sha(role)`. For the three-role implement phase (coder/tester/documenter) the tracker may silently return `None` or the `"RECONSTRUCTED_NO_SHA"` sentinel, leaving `agent.commit` null with no diagnostic.

The fix writes `pr_number` / `pr_head_sha` inside the existing auto-PR transaction (re-using `_fetch_pr_state` at line 4859 for the head SHA), short-circuits the overseer detector when any transition-completion evidence is visible, and adds a WARN log in `_update_agents_complete` when the BRC tracker returns null so we can diagnose the three-role wiring gap without masking it.

**Risks / edge cases**: `_fetch_pr_state` may fail if `gh` is unavailable or the PR was just created (propagation delay) — treat `head_sha` as best-effort (always populate `pr_number` from parsed URL, populate `pr_head_sha` only when a valid hex SHA returned). The push-failure fallback-to-remote-HEAD path (#1731) means reading `head_sha` from the created PR (not the push intent) is correct. The overseer short-circuits must be strictly additive — a genuine stall won't populate any of pr_number / pr_url artifact / advanced current_phase. Model validators: `pr_number` is `ge=1`, `pr_head_sha` matches `[0-9a-f]{7,40}` — must guard.

## Implementation

### Phase 1: Implement

Fix the three bugs in one cohesive change, plus regression tests.

**Tasks**:

1. **[task-1-1]** In `orchestrator/routes/pipelines.py:_finalize_pr_phase_failed` (line 4985), inside the `if pr_url:` success branch at lines 5019–5024, parse `pr_number` from `pr_url` using the same `re.search(r"/pull/(\d+)", pr_url)` pattern that `_get_pr_info` uses (line 2258). Then call `_fetch_pr_state(pr_number, pipeline.repo)` (line 4859) to get `head_sha`. Inside the existing `with get_pipeline_state_lock(pipeline_id): ... store.save_pipeline(reloaded)` transaction, set `reloaded.pr_number = pr_number` when parsed successfully, and set `reloaded.pr_head_sha = head_sha` only when the returned value matches the `[0-9a-f]{7,40}` model validator. Do not fail the PR phase if `_fetch_pr_state` returns an empty dict — leave `pr_head_sha` null and proceed. The existing `phase_execution.artifacts = {"pr_url": pr_url}` write at line 5023 must still happen. Acceptance: on issue-mode pipelines, after `_finalize_pr_phase_failed` returns `False`, the reloaded pipeline has both `pr_number` populated and (when gh succeeds) `pr_head_sha` populated.

2. **[task-1-2]** In `orchestrator/overseer/monitor.py:_check_post_consensus_stall` (line 1065), after the existing `consensus.is_complete` and `pipeline_status_str == "running"` gates but before the grace-period / broadcast logic (line ~1087), load the current pipeline via the monitor's existing state-store access (the monitor already has `self.pipeline_id`; look for existing patterns in the class — `_load_pipeline` or similar — and reuse). Return early (no alert, no HITL decision, no Slack) if any of these hold: `pipeline.current_phase.value != "implement"` OR `pipeline.pr_number is not None` OR `pipeline.phases.get("pr")` has `artifacts.get("pr_url")` set. When short-circuiting, also reset `self._post_consensus_stall_first_seen = None` so a subsequent genuine stall gets its own grace period. If loading the pipeline raises, fall through to the existing behavior (fail open — don't suppress alerts on a bug in the short-circuit). Acceptance: when any of the three transition-completion indicators is present, the detector does not broadcast, does not create an HITL decision, and does not send a Slack notification.

3. **[task-1-3]** In `orchestrator/routes/pipelines.py:_update_agents_complete` (lines 7913–7916), replace the `if sha and sha != "RECONSTRUCTED_NO_SHA": agent.commit = sha` block with a conditional that also logs on the null/sentinel case. When `_brc.get_proposal_commit_sha(agent.role.value)` returns `None` or `"RECONSTRUCTED_NO_SHA"` and `agent.commit` is not already set, emit `logger.warning("BRC tracker returned no commit sha for completed agent", pipeline_id=pipeline_id, phase=phase_str, role=agent.role.value, brc_value=sha)`. No behavior change — diagnostic only, so we can see on real runs whether the three-role (coder/tester/documenter) wiring misses SHAs. Deliberately no auto-fallback to a guess SHA: that would mask the real bug. Acceptance: when the BRC tracker returns null/sentinel for an agent role, a structured warning log is emitted carrying `pipeline_id`, `phase`, `role`, and `brc_value`.

4. **[task-1-4]** Add regression tests in `orchestrator/tests/test_finalize_pr_phase.py` and `orchestrator/tests/test_overseer_monitor.py`. In `test_finalize_pr_phase.py` (pattern off existing `test_push_ok_and_pr_url_stores_artifact_and_reports_no_failure` at line 34): add tests that mock `_auto_create_pr` to return `"https://github.com/owner/repo/pull/99"` and mock `_fetch_pr_state` to return `{"head_sha": "abc1234def"}` — assert the reloaded pipeline has `pr_number == 99` and `pr_head_sha == "abc1234def"`. Add a second test where `_fetch_pr_state` returns `{}` — assert `pr_number == 99` but `pr_head_sha is None`. In `test_overseer_monitor.py` (pattern off `test_detects_post_consensus_stall_after_grace_period` at line 560): add three tests asserting the detector does NOT broadcast when (a) `pipeline.current_phase != "implement"`, (b) `pipeline.pr_number is not None`, (c) `phases["pr"].artifacts["pr_url"]` is populated. Each new test must fail on the pre-fix code and pass post-fix.
