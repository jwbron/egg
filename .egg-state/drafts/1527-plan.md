# Plan: Enrich gateway push rejections with recovery guidance

## Summary

Enrich the gateway's push-denied error with actionable remediation steps so agents know *how* to fix a rejected push, add an `egg-orch push --scope-filter` command that auto-strips out-of-scope files before pushing, and add a sandbox rule file that teaches agents the recovery pattern for push rejections. The prompt reinforcement part of #1527 is already implemented via #1431's `_build_file_boundary_section()`.

**Risks / edge cases**: The error message format change must preserve the existing JSON structure (`blocked_files` key in `details`) since agents may parse it. The `egg-orch push --scope-filter` command needs to handle the case where all files are out of scope (nothing left to push). The recovery rule must not conflict with the existing anchor-recovery rule.

**CRITICAL — Role-scope assignments**: Each task below is assigned to the role permitted to modify those files. The coder MUST NOT create or modify `.md` files (blocked by `**/*.md`) or test files (blocked by `**/test_*.py`). The documenter handles `.md` files. The tester handles test files. Each agent should only implement the tasks within their role's file scope.

## Implementation

### Phase 1: Implement

Enrich gateway error messages, add scope-filtered push command, and add agent recovery rule.

**Coder tasks** (source code only — no .md, no test files):
1. **[task-1-1]** In `gateway/gateway.py:929-937`, enrich the push-denied error message for agent-role restrictions to include specific remediation steps — tell the agent to `git reset HEAD~1`, re-add only the allowed files (listed explicitly from the agent pattern's `allowed_patterns`), and re-commit. Add `remediation` and `allowed_patterns` keys to the `details` dict. Preserve existing `blocked_files` key.
2. **[task-1-2]** Add `egg-orch push --scope-filter` subcommand that reads `EGG_AGENT_FILE_PATTERNS` env var (JSON with `allowed` and `blocked` arrays), filters the staged commit to only include files matching the allowed patterns (excluding blocked), and pushes. Handle edge case where no files remain after filtering (exit with clear message).

**Documenter tasks** (.md files only):
3. **[task-1-3]** Create `sandbox/agent-config/rules/push-recovery.md` — a Claude Code rule that teaches agents how to recover from gateway push rejections: detect the rejection, identify blocked files from the error, reset the commit, re-commit with only allowed files, and retry the push. Reference `egg-orch push --scope-filter` as the preferred recovery method.

**Tester tasks** (test files only):
4. **[task-1-4]** Update gateway tests in `gateway/tests/test_agent_restrictions_enforce.py` to verify the enriched error message includes `remediation` and `allowed_patterns` in details, and preserves the existing `blocked_files` structure.
