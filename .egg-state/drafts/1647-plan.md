# Plan: Add source_branch parameter to submit_task

## Summary

Add a `source_branch` parameter to the `submit_task` pipeline so the orchestrator reads large artifacts (plan, analysis) from a git branch server-side rather than requiring inline content. Also relax the branch-exists guard to allow reusing branches when no active pipeline state exists. The approach threads the new parameter through the full stack (MCP schema → REST handler → state store → Pipeline model), then reads artifacts via `git show origin/<source_branch>:<path>` in `_run_pipeline` before the existing contract creation block.

**Risks / edge cases**: If the source branch used a different issue number / pipeline ID, the `.egg-state/` file prefixes won't match — mitigated by falling back to listing available files via `git ls-tree`. Inline `plan`/`analysis` values take precedence over `source_branch` (explicit content wins). The `_sync_worktree_with_remote` fetch at line 7306 should make `origin/<source_branch>` available, but error handling covers missing refs.

## Implementation

### Phase 1: Implement

Add `source_branch` parameter through the full submission stack and implement server-side artifact reading.

**Tasks**:
1. **[task-1-1]** In `orchestrator/models.py`, add `source_branch: str | None = Field(default=None, description="Source branch to read prior-run artifacts from (plan, analysis, contract).")` to the `Pipeline` model after the `plan` field (~line 478). Acceptance: Pipeline model accepts and persists `source_branch`.

2. **[task-1-2]** Thread `source_branch` through the submission stack: add to `submit_task` MCP tool schema in `orchestrator/mcp_tools.py:63-113`; pass through in `_handle_submit_task` at `mcp_tools.py:612-666`; extract from request data in `create_pipeline()` at `pipelines.py:620-765` and pass to `store.create_pipeline()`; accept in `StateStore.create_pipeline()` at `state_store.py:720-818` and pass to Pipeline constructor. Acceptance: `source_branch` reaches the Pipeline model when passed to `submit_task`.

3. **[task-1-3]** In `orchestrator/routes/pipelines.py`, add a `_read_source_branch_artifacts()` helper function and call it right before the contract creation block (~line 7349) inside `_run_pipeline`. The helper: (a) derives the artifact prefix via `_pipeline_identifier(pipeline.issue_number, pipeline_id)`, (b) reads plan from `origin/<source_branch>:.egg-state/drafts/{prefix}-plan.md` via `git show`, (c) reads analysis from `origin/<source_branch>:.egg-state/drafts/{prefix}-analysis.md` via `git show`, (d) if exact prefix doesn't match, falls back to `git ls-tree --name-only origin/<source_branch>:.egg-state/drafts/` to find `*-plan.md` / `*-analysis.md` files and reads the first match, (e) only populates `pipeline.plan` and `pipeline.analysis` when not already set (inline values take precedence), (f) saves updated pipeline state via the store. Uses `git -c core.hooksPath=/dev/null -C <worktree_path>` prefix consistent with `_sync_worktree_with_remote`. Acceptance: `submit_task(source_branch="egg/issue-X-v3")` populates pipeline.plan and pipeline.analysis from the source branch's drafts, and the contract is correctly populated via the existing `_populate_contract_from_plan()` flow.

4. **[task-1-4]** In `orchestrator/routes/pipelines.py:687-715`, relax the branch-exists check in `create_pipeline()`. Move `store = get_state_store(repo_path)` (currently line 751) before the branch-exists check. When `ls_remote_branch` returns True, check if `pipeline_id` has an active (non-terminal) pipeline via `store.pipeline_exists(pipeline_id)` + `store.load_pipeline(pipeline_id).status`. Only return 409 when the branch exists AND an active pipeline exists. If the pipeline is terminal (CANCELLED/FAILED/COMPLETE) or doesn't exist, skip the 409 and allow branch reuse. Acceptance: Resubmitting with the same pipeline_id after a cancelled/failed run no longer 409s on the branch-exists check.

5. **[task-1-5]** Add tests in `orchestrator/tests/` covering: (a) `source_branch` parameter acceptance through MCP → REST → state store — verify it reaches the Pipeline model; (b) `_read_source_branch_artifacts` reads plan and analysis from a source branch with correct prefix, and falls back when prefix doesn't match; (c) inline plan/analysis values take precedence over source_branch; (d) branch-exists relaxation allows reuse when pipeline is terminal but blocks when pipeline is active. Acceptance: All new tests pass.
