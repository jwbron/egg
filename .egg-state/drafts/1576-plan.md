# Plan: Add unresolved-NACK guard to handle_confirmed()

## Summary

Add an unresolved-NACK guard to `handle_confirmed()` that prevents a reviewer from confirming when it has NACKed a producer who hasn't re-proposed since. This blocks the deadlock at its source — the reviewer never enters terminal CONFIRMED state with open review obligations — rather than relying on the `_un_confirm_stale_reviewers` recovery path.

**Risks / edge cases**: Must not block confirmation when the NACKed producer has since re-proposed and the reviewer has re-reviewed (entry would be ACKED at new version, not NACKED). Dual-role agents (tester is both producer and reviewer) must be handled — the producer-side confirmation logic is unaffected since this guard is in the reviewer branch only. The `_un_confirm_stale_reviewers` safety net remains unchanged as defense-in-depth for the ACK case.

## Implementation

### Phase 1: Implement

Add an unresolved-NACK guard in the reviewer confirmation path and comprehensive tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/peer_consensus.py:handle_confirmed()`, add an unresolved-NACK guard after the existing stale-ACK version-match guard (after line 439). For each assigned producer, check if `entry.state == ApprovalState.NACKED` and `current_version > 0`. If found, return `{"status": "pending_acks", "message": f"Reviewer {agent_role} cannot confirm: unresolved NACKs. Wait for these producers to re-propose before confirming: {nacked_producers}", "unresolved_nacks": unresolved_nacks}`. Acceptance: reviewer with unresolved NACK gets `pending_acks` rejection.
2. **[task-1-2]** Add tests in `orchestrator/tests/test_peer_consensus_integration.py` covering: (a) reviewer cannot confirm with unresolved NACK, (b) after producer re-proposes and reviewer ACKs new version, confirm succeeds, (c) full #1576 scenario end-to-end with the multi-producer graph from the issue (coder + tester + reviewer_code + reviewer_contract). Acceptance: all tests pass and the #1576 timeline reaches consensus without deadlock.
