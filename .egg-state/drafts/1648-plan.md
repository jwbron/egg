# Plan: Add global zero-proposal guard to BRC confirm action

## Summary

Add a global zero-proposal guard to `check_confirm_guard()` that prevents any agent (producer or reviewer) from confirming consensus while any producer in the review graph has `proposal_version == 0`. The existing per-reviewer guard only checks assigned producers, which lets reviewers like `reviewer_contract` (who only reviews `coder`) confirm even when `tester` has never proposed. The global guard closes this gap by checking all producers regardless of review assignments.

**Risks / edge cases**: The global guard is strictly more conservative — it blocks confirmations that were previously allowed. This is correct per INV-4 and the protocol design. The per-reviewer guard (Guard 2) is retained for defense-in-depth and its more specific error message, though the global guard fires first when applicable. No existing tests should break because the global guard only rejects states that violate the protocol invariant.

## Implementation

### Phase 1: Implement

Fix the zero-proposal guard bypass by adding a global check that applies to all agents.

**Tasks**:
1. **[task-1-1]** In `orchestrator/action_guards.py:check_confirm_guard()`, add a global zero-proposal guard after the phantom-agent guard (line ~323) and before the producer/reviewer-specific sections. Iterate all producers via `[r for r in graph.all_roles() if graph.is_producer(r)]`, check `matrix.get_proposal_version(p) == 0` for each, and return `GuardResult(allowed=False, reason=..., details={"guard": "global_zero_proposal", "producers": [...]})` if any are found. Acceptance: `check_confirm_guard("reviewer_contract", ...)` returns `allowed=False` with `guard="global_zero_proposal"` when `tester` has `proposal_version == 0`.
2. **[task-1-2]** In `orchestrator/peer_consensus.py:handle_confirmed()`, add explicit handling for the `global_zero_proposal` guard type before the existing `producer_not_fully_acked` handler (~line 474). Log with `"handle_confirmed rejected: global zero-proposal producers"` and return `{"status": "pending_acks", "message": guard.reason, "zero_proposal_producers": guard.details.get("producers")}`. Acceptance: `handle_confirmed` returns structured `zero_proposal_producers` data for the new guard type.
3. **[task-1-3]** In `orchestrator/tests/test_action_guards.py`, add three tests to the `TestCheckConfirmGuard` class: (a) `test_global_zero_proposal_blocks_unassigned_reviewer` — `reviewer_contract` blocked when `tester` has v0, even though `reviewer_contract` doesn't review `tester`; (b) `test_global_zero_proposal_blocks_producer` — `coder` (a producer) blocked when peer producer `tester` has v0; (c) `test_global_zero_proposal_clears_when_all_proposed` — guard passes once all producers have proposed. Use the existing `graph` and `matrix` fixtures. Acceptance: all three tests pass and all existing tests continue to pass.
