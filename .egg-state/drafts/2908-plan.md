# Plan: BRC consensus — deterministic event-pump + durable agent memory (issue #2908)

> Phase: plan | Recommended approach: refine-phase Option B (stateless event-pump + durable distilled memory)

## Approach

The refine-phase analysis (`.egg-state/drafts/2908-analysis.md`) recommends
**Option B**: reframe the consensus agent from a *persistent participant that
holds a wait* into a *stateless per-event handler the wrapper invokes*. The
wrapper (`orchestrator/consensus_wrapper.py`) becomes a deterministic event
pump that blocks on `egg-orch message wait-loop`; on each actionable BRC
event it spawns the agent via `python3 -m egg_agent` (built by
`shared/egg_agent/command.py:build_agent_command` — **not** `claude --print`,
which is an EGG100 anti-pattern); the agent loads its cached prefix + a
distilled memory file + the one event, acts, updates memory, and exits
naturally. The wrapper loops until the orchestrator reports the role
consensus-confirmed and `is_complete`.

The four HITL decisions resolved in refine are load-bearing for this plan:

| HITL | Resolution | Plan impact |
|---|---|---|
| **cq-1** (WS8 scope) | Split MCP→CLI collapse to a follow-up. **This issue ships only the net-new CLI verbs the event-pump consumes** (`brc list-blocking`, `phase get-context`, `brc get-state`, `brc resolve-obligation`, `brc read-peer-artifact`, plus `consensus next-action` / extension of `consensus status`). Do **not** delete any of the 28 agent-facing MCP tools. Do **not** migrate prose-bearing `consensus propose/ack/nack` to CLI (the #2741 stdin/file-path rule is designed in the follow-up). | All new CLI verbs land in slice-2 via `_handler_dispatch` so they share existing handlers (preserves `tests/tools/test_mcp_cli_drift.py` invariant); no MCP deletions. |
| **cq-2** (Qwen cache) | Ship v1 with Qwen route **enabled** on the event-pump (no fallback to old path — cq-4). No keep-warm for v1. WS0 spike must measure cold-read cost across the worst-case ~15-min BRC idle; **only** if material does slice-6 add a bounded keep-warm (Qwen-route only; suppressed during HITL / awaiting-human waits). | slice-1 runs WS0 spike with TTL instrumentation; slice-6 is conditional on slice-1 outcome. |
| **cq-3** (safety budget terminal state) | OVERSEER_ALERT + HITL decision (resume/abort). **Hard requirement: the no-progress safety budget AND parked-HITL state must be persisted DURABLY SERVER-SIDE in the orchestrator** so a restarted SDLC host can resume. | slice-2 lands the durable schema (contract schemaVersion bump + persistence on `.egg-state/contracts/<pid>.json`); slice-4 wires the wrapper-side consumer that survives host death. |
| **cq-4** (old path retention) | **Delete the old capped-restart wrapper path entirely.** No flagged fallback at any point in this issue. | slice-4 deletes `MAX_CONSENSUS_RESTARTS = 3`, `_RECOVERY_SYSTEM_PROMPT`, `_RECOVERY_USER_PROMPT`, the SSE consensus.reached blocking path, and the restart loop in one slice — no intermediate flag. |

Refine open-feedback Q1 (no operator-side hard budget caps for WS0 — instrument
only) and Q2 (brc-memory.md is ephemeral coordination state; recovery must NOT
depend on it; orchestrator message history is the durable backstop) are
honoured: slice-1 emits measurements but no fail thresholds; slice-3 treats
brc-memory.md as ephemeral and slice-4's restart recovery reasons from durable
orchestrator state alone.

`serialized_chain_order` needed.

## Slice rationale — risk-driven

Each slice is anchored to the risks the refine-phase risk_analyst surfaced
(see `.egg-state/agent-outputs/2908-risk_analyst-output.json`). The three
HIGH-severity risks are addressed inside slice-1 and slice-2 before any
production code path changes.

- **slice-1 (WS0 spike)** retires **R2** (Qwen cache TTL ceiling) and **R11** (`claude --print` regression risk). The spike's prototype uses `python3 -m egg_agent` per the refine-phase primitive correction, even though it is throwaway, so the production rewrite in slice-4 inherits a working pattern. The spike also produces the measurement that resolves **R5** (memory shape decision criterion): if Qwen cache survives long idles, rewrite-and-distill dominates; if it lapses, append-only with a tail compaction bounds the cost. The cost-callback acquisition path is documented as a trust-boundary constraint (the data lives in the litellm container, not the agent pod).

- **slice-2 (next-action + CLI + persistence)** retires **R1** (cq-3 durability gap) by landing the durable schema for `pipeline.no_progress_budget` and parked HITL state before any wrapper consumer exists, **R6** (drift-test break) by adding the new CLI shims through `_handler_dispatch` so handler-import parity is preserved, **R9** (next-action scope) by extending the existing `consensus status --json` payload (per the architect's preference) rather than spinning a new endpoint, and **R12** (metadata-only delta) by specifying `changed_artifacts` + version markers + memory-file pointer as the delta contract — never inlined file contents. All slice-2 work is purely additive — no behavior change to the existing `consensus_wrapper.py` or agent prompt.

- **slice-3 (brc-memory.md + handler scaffolding)** retires **R13** (cross-role memory-read allowlist — `.egg-state/agent-outputs/` is already in every role pattern; verified in §Primitives) and codifies the **R5** decision against the slice-1 spike data. The slice intentionally lands the memory writes before the wrapper consumes them so by the time slice-4 ships, the memory file is already populated on the first per-event invocation.

- **slice-4 (event-pump rewrite + WS1 + WS4 + safety-budget + legacy deletion)** is the central control-flow rewrite. It addresses **R1**'s consumer side (the wrapper re-reads durable state after host death), **R3** (cursor pod-restart loss — the wrapper-side wait inherits the persistent `EGG_AGENT_ROLE` and detects stale cursors via the server-side `since_id` reset path), **R4** (gateway credential expiry on long idles — wrapper-side heartbeat + keep-alive emission), **R7** (prior-fix preservation — each named fix has an assertion in the slice-4 test set), **R8** (no-rollback cutover — the wrapper-side smoke test runs against the #2906 reproducer immediately after the deletion lands), and **R14** (SSE silent-failure — the SSE blocking path is deleted; the new wrapper uses `egg-orch consensus check` against the deterministic endpoint instead). The minimal preamble nudge here (drop STAY-ALIVE) is the smallest change that lets the agent exit after one event; full preamble collapse is deferred to slice-5 so slice-4 stays focused on control flow.

- **slice-5 (prompt collapse + delta re-analysis)** retires **R7** (prior-fix-preservation residue — the lean event-handler contract carries the file-write boundary, the stdin/file rule for propose/ack/nack, and the few invariants the agent still owns; the analysis-text references to fix lineage become historical) and **R12** (metadata-only delta — the per-event prompt template explicitly says "evaluate ONLY the named changed_artifacts; do not re-read the codebase / earlier commits / analysis draft"). The slice also addresses **R10** (per-event subprocess latency — by bounding context, the per-event token cost stays small; if latency proves material, the slice tests assert a measurable bound).

- **slice-6 (Qwen bounded keep-warm — conditional)** is the only slice whose shape depends on slice-1 outcome. The three branches (no-keep-warm docs note; bounded keep-warm code; HITL ambiguity decision) are enumerated below as separate tasks; the implementer picks the path based on the slice-1 measurement and marks the unused branches as not-applicable. Anthropic route is explicitly out of scope (1h TTL cleared in WS7 empirical).

# yaml-tasks
pr:
  title: "Replace agent-held BRC waits with deterministic event-pump + durable memory"
  description: |
    Closes #2906 and resolves the structural seam that produced the entire lineage of BRC wait bugs (#2323, #2064/#2482, #2036, #1995, #2451). Today the BRC consensus agent holds a blocking `egg-orch message wait-loop` between each event; every re-entry is a seam at which the model can emit a final assistant message and exit `success=True` instead of looping. Claude usually re-enters; qwen3.7-max does not (#2906) — it exits at ~30–50 of a 1000-turn budget, the wrapper sees no `CONSENSUS_CONFIRMED`, and the 3-restart cap (#2806) burns ~$1 and ~20 min per cycle.

    This PR reframes consensus-agent execution from a *persistent participant that holds a wait* into a *stateless per-event handler the wrapper invokes*, with continuity carried by a durable distilled memory file. Six slices ship sequentially as stacked PRs:

    1. **WS0 spike** (slice-1) — empirically validate the event-pump on the #2906 reproducer (qwen3.7-max) and measure Qwen-route provider-cache TTL against the worst-case ~15-min BRC idle; output is a `docs/spike/2908-event-pump-spike.md` report.
    2. **Foundational primitives** (slice-2) — `consensus next-action` endpoint (extension of `consensus status --json`), five net-new CLI verbs (`egg-orch brc {list-blocking, get-state, resolve-obligation, read-peer-artifact}` + `egg-contract get-context`) that wrap existing MCP handlers via `_handler_dispatch` (preserves drift-test invariant; no MCP retirement per cq-1), and durable contract-store schema for `pipeline.no_progress_budget` + parked-HITL state (cq-3 hard requirement).
    3. **Durable memory artifact** (slice-3) — `.egg-state/agent-outputs/<role>/brc-memory.md` with structured sections plus handler-layer scaffolding in `sandbox/egg_agent_tools/handlers/brc.py` that writes memory entries on every ACK/NACK off the existing `reason` + `files_reviewed` payload.
    4. **Event-pump rewrite + legacy deletion** (slice-4) — rewrite `orchestrator/consensus_wrapper.py` as a deterministic event pump (`build_agent_command` per event, not `claude --print`); delete `MAX_CONSENSUS_RESTARTS=3`, `_RECOVERY_SYSTEM_PROMPT`, `_RECOVERY_USER_PROMPT`, the SSE consensus.reached blocking path, and the restart loop (cq-4 — no flagged fallback); migrate heartbeat + gateway keep-alive ownership from the agent's `_start_wait_loop_heartbeat` to the wrapper; wire the safety-budget consumer against the durable schema landed in slice-2.
    5. **Prompt collapse + delta-scoped re-analysis** (slice-5) — replace STAY-ALIVE / wait-loop / cursor-threading text in `_build_brc_preamble` and `sandbox/agent-config/rules/*.md` with a lean event-handler contract; extend the next-action endpoint to return `changed_artifacts` metadata so per-event context stays metadata-only (no inlined diffs).
    6. **Qwen keep-warm (conditional)** (slice-6) — based on slice-1 measurement, either land a docs note ("no keep-warm needed") or implement a bounded Qwen-route-only keep-warm with HITL suppression and a hard refresh cap, or open a HITL decision if data is ambiguous.

    For operators: pipelines mid-flight on the old capped-restart path at merge time will resume on the new event-pump path on their next phase entry — there is no in-flight migration. The structural seam is gone: a deterministic Bash loop, not the model, drives BRC waits and termination; no model can fall out by exiting between events. The per-cycle restart cost (~$1 / ~20 min) goes to zero on the failure modes #2906 surfaced.
