# Plan: Fix phase gate draft resolution with generic path fallback

## Summary

Add fallback path resolution to `_read_phase_draft` so that when the primary issue-specific draft path doesn't exist on the worktree filesystem, it tries the generic path (`analysis.md` / `plan.md`) before giving up. The canonical write path (`_get_draft_path`) stays unchanged — agents always write to the issue-specific path. Only the read path gains fallback behavior.

**Risks / edge cases**: The `_cleanup_stale_generic_drafts` function removes generic drafts at pipeline start, so the fallback won't help for pipelines that ran cleanup. However, this still helps in cases where: (a) the agent wrote to the generic path, (b) the worktree has stale generic files from a prior run that weren't cleaned up, or (c) the pipeline was started without cleanup running. No existing callers of `_get_draft_path` are affected since only the reader function changes.

## Implementation

### Phase 1: Implement

Add generic fallback path to `_read_phase_draft` and add tests for the new behavior.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py:_read_phase_draft()`, after the primary path lookup fails, construct and try a generic fallback path (`analysis.md` for refine phase, `<phase>.md` for others) without any prefix. Log at debug level when the fallback is used so path mismatches are diagnosable. Acceptance: `_read_phase_draft` returns content from generic path when issue-specific path is missing.
2. **[task-1-2]** In `orchestrator/tests/test_read_phase_draft.py`, add tests: (a) fallback to generic path when issue-specific path missing, (b) primary path still preferred over generic when both exist, (c) returns None when both paths missing. Acceptance: All new tests pass, existing tests unchanged.
