# Plan: Add agent-level and phase-level restart capabilities

## Summary

Add two levels of restart capability to the egg orchestrator: agent-level restart (stop+respawn a single stuck agent while preserving its worktree and resetting its consensus state) and phase-level restart (kill all phase containers, reset all consensus/review cycle state, respawn all agents from scratch while preserving prior phase artifacts). Both levels are exposed via orchestrator REST API endpoints, MCP tools for HITL operators, and as new overseer action types (`restart_agent`, `restart_phase`) so the overseer can auto-restart stuck agents and escalate to phase restarts when agent-level restarts are exhausted.

**Risks / edge cases**: Worktree preservation is critical — restarts must not delete per-agent worktrees containing committed work. Phase restarts must preserve prior phase outputs (refine → plan carry-over). Simultaneous restart requests are guarded by the spawner's existing container name-conflict handling. Agent restart limits (default 2 per phase) prevent infinite restart loops. Phase restart requires HITL approval by default to avoid cascading restarts.

## Implementation

### Phase 1: Implement

Add force-retry at two levels (agent and phase) across the orchestrator API, MCP tools, and overseer.

**Tasks**:
1. **[task-1-1]** In `orchestrator/container_spawner.py`, add `restart_agent_container(pipeline_id, agent_role, ...)` method that stops the existing container (via `stop_agent_container()`), removes it (via `remove_agent_container()`), and respawns with the same parameters using `spawn_agent_container()` — reusing the existing worktree rather than creating a new one. Track restart count. Return the new `SpawnedContainer`. Acceptance: method stops old container, removes it, respawns with same role/phase/env preserving worktree, and returns new SpawnedContainer
2. **[task-1-2]** In `orchestrator/routes/pipelines.py`, add `POST /<pipeline_id>/agents/<role>/restart` endpoint that: validates pipeline/role, calls `PeerConsensusTracker.remove_agent()` and `ConsensusEvaluator.remove_agent()` to reset consensus state, calls the new spawner method to respawn the agent, updates the pipeline's `PhaseExecution` state (new container/agent entries), and returns success with the new container ID. Accept optional `reason` in request body. Acceptance: endpoint returns 200 with new container ID, old container is stopped, consensus state is reset for the agent
3. **[task-1-3]** In `orchestrator/routes/pipelines.py`, add `POST /<pipeline_id>/phases/<phase>/restart` endpoint that: validates pipeline/phase, stops and removes all containers for the phase, calls `PeerConsensusTracker.clear()` to reset all consensus state, resets the phase's review cycle counter in `PhaseExecution`, respawns all agents for the phase, and returns success. Accept optional `reason` and `context` in request body. Acceptance: endpoint returns 200, all phase containers are stopped, consensus and review cycles are reset, all agents are respawned
4. **[task-1-4]** In `orchestrator/mcp_tools.py`, add `restart_agent` tool (params: `task_id`, `agent_role`, `reason`) and `restart_phase` tool (params: `task_id`, `phase`, `reason`, `context`) to `PIPELINE_TOOLS`, with handlers `_handle_restart_agent()` and `_handle_restart_phase()` that proxy to the new API endpoints. Acceptance: both MCP tools call the correct API endpoints and return success/error responses
5. **[task-1-5]** In `orchestrator/overseer/decision_maker.py`, add `restart_agent` and `restart_phase` to the available actions in the `decide_corrective_action()` prompt (line 68-81). In `orchestrator/overseer/monitor.py`, add handling for both actions in `_execute_action()` (line 544): `restart_agent` calls the restart API endpoint directly; `restart_phase` creates an HITL decision by default (configurable to auto-approve). Track restart counts per agent per phase; escalate from agent to phase restart when agent restarts exhausted for 2+ agents. Acceptance: overseer can decide and execute restart_agent actions automatically; restart_phase escalates to HITL by default; restart counts are tracked and limit enforcement works
6. **[task-1-6]** Add tests for the new restart endpoints, spawner method, MCP tools, and overseer actions in `orchestrator/tests/`. Acceptance: tests cover happy path and edge cases (missing pipeline, missing agent, restart limit exceeded, consensus reset, phase artifact preservation)
