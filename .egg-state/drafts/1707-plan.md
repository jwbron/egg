# Plan: Render structured log fields inline in ConsoleFormatter

## Summary

Modify `ConsoleFormatter.format()` to render all structured context fields inline on the same log line as `key=value` pairs, instead of on separate newlines. This ensures `grep` and `docker logs | grep` can filter by any field. The hardcoded context section (`task_id`, `repository`, `pr_number` in parentheses) is merged into the general inline extras for a uniform format. Long values are truncated to keep lines manageable.

**Risks / edge cases**: Values containing spaces, newlines, or exceeding ~80 characters need truncation/quoting to keep lines grep-friendly. Exception tracebacks (already handled separately) must remain multi-line. Existing tests assert the old multi-line and parenthesized-context formats and must be updated.

## Implementation

### Phase 1: Implement

Modify the ConsoleFormatter to render extras inline and update tests.

**Tasks**:
1. **[task-1-1]** In `shared/egg_logging/formatters.py:ConsoleFormatter.format()`, replace the multi-line extras block (lines 307-321) and the separate context section (lines 278-293) with a single inline `key=value` rendering that appends all structured fields to the main log line before the source location. Truncate values longer than 80 chars. Quote values containing spaces. Acceptance: A log record with `pipeline_id="issue-1702"` produces single-line output with `pipeline_id=issue-1702` on the same line as the message.

Add a new test verifying that extra fields (like `pipeline_id`) appear inline on the same line as the message. Add a test for value truncation.
