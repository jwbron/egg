# Implementation Plan: Overseer should escalate infrastructure errors to human

> Issue: #1489 | Phase: plan | Agent: task_planner

## Approach

The analysis recommends **Option D (Combined approach)**: a Tier 1 deterministic
tripwire in the orchestrator's `health_monitor.py` for clear-cut infrastructure
errors, plus enhanced Tier 2 LLM classification in the overseer for ambiguous
cases. This plan decomposes that into three implementation phases within a single
PR.

The key insight from the observed incident (pipeline `issue-1481`) is that the
existing system has no code path to distinguish "agent is slow" from "agent hit
an infrastructure error." Both flow through the generic stall-detection pipeline.
The fix adds infrastructure-error awareness at both tiers of the health
monitoring stack.

### Phasing Strategy

- **Phase 1 (Tier 1 — Orchestrator tripwire)**: Add deterministic detection of
  `blocked` progress events with infrastructure-related blocker keywords. This
  provides instant, zero-LLM-cost detection for agents that emit structured
  progress events.
- **Phase 2 (Tier 2 — Overseer enhancement)**: Enhance the classifier to
  recognize infrastructure error patterns and the decision maker to auto-escalate
  them. This catches ambiguous cases and agents that don't emit structured
  blocked events.
- **Phase 3 (Integration & deduplication)**: Add deduplication between tiers,
  end-to-end integration tests, and documentation.

### Dependencies

Phase 2 can start in parallel with Phase 1 since they touch different files.
Phase 3 depends on both Phase 1 and Phase 2 being complete.

## Phase 1: Tier 1 — Orchestrator Infrastructure Error Tripwire

### Goal
Add a new deterministic tripwire rule in `health_monitor.py` that detects
`blocked` progress events with infrastructure-related blocker text and creates
a high-severity alert for immediate HITL escalation.

### Tasks

**TASK-1-1: Add infrastructure error detection to HealthMonitor**

Update `orchestrator/health_monitor.py` to:

1. Define an `INFRA_ERROR_PATTERNS` constant — a list of regex patterns matching
   common infrastructure errors (e.g., `git add failed`, `permission denied`,
   `EROFS`, `403 Forbidden`, `gateway.*error`, `.gitignore`).
2. Add an `infra_error_escalated` flag to `AgentState` (like existing
   `heartbeat_escalated`) for deduplication.
3. Add a `_check_infra_errors()` method that inspects recent progress events
   for `state=blocked` with blocker text matching any `INFRA_ERROR_PATTERNS`.
4. When detected, create an alert with `severity=critical`,
   `type=infrastructure_error`, including the agent ID, blocker text, and
   timestamp.
5. Wire `_check_infra_errors()` into `check_tripwires()`.

**Acceptance criteria**:
- `_check_infra_errors()` exists and is called from `check_tripwires()`
- A progress event with `state=blocked, blocker="git add failed: .gitignore"`
  triggers a `critical` severity alert with `type=infrastructure_error`
- A progress event with `state=blocked, blocker="waiting for reviewer"` does
  NOT trigger (it's not infrastructure-related)
- Repeat detection for the same agent is suppressed via `infra_error_escalated`
- The `infra_error_escalated` flag resets when the agent emits a non-blocked
  progress event

**TASK-1-2: Add unit tests for infrastructure error tripwire**

Add tests to `tests/test_health_monitor.py`:

1. Test that a blocked progress event with infrastructure keywords triggers an
   `infrastructure_error` alert
2. Test that non-infrastructure blocked events are ignored
3. Test deduplication — second identical infra error doesn't create duplicate alert
4. Test flag reset — agent emits `working` progress, then hits infra error again
5. Test multiple pattern matching — various infrastructure error strings

**Acceptance criteria**:
- All new tests pass
- Existing tests continue to pass
- Tests cover positive detection, negative (non-infra), dedup, and flag reset

## Phase 2: Tier 2 — Overseer Infrastructure Error Classification

### Goal
Enhance the overseer's classifier and decision maker to recognize infrastructure
errors and auto-escalate them to HITL, catching cases where agents don't emit
structured blocked events.

### Tasks

**TASK-2-1: Add `infrastructure_error` classification to classifier**

Update `orchestrator/overseer/classifier.py`:

1. Update the `classify_stall()` prompt to include infrastructure error patterns
   as a distinct classification output (e.g., `infrastructure_error` alongside
   `stuck`, `working`, `needs_help`).
2. Update the `classify_error()` prompt to recognize infrastructure errors as a
   distinct `error_type` category with recommended action `escalate_hitl`.
3. Both classifiers should look for keywords: git failures, gateway errors,
   permission denied, EROFS, .gitignore, 403/500 HTTP errors in the context
   provided to them.

**Acceptance criteria**:
- `classify_stall()` can return `infrastructure_error` classification
- `classify_error()` can return `error_type=infrastructure_error` with
  `recommended_action=escalate_hitl`
- Existing classification categories remain unchanged (backward compatible)

**TASK-2-2: Update decision maker to auto-escalate infrastructure errors**

Update `orchestrator/overseer/decision_maker.py`:

1. In `decide_corrective_action()`, add a fast-path: if the classification is
   `infrastructure_error`, return action `hitl` with high priority, bypassing
   the nudge/redirect ladder.
2. In `decide_escalation_level()`, treat `infrastructure_error` classifications
   as always requiring `hitl` level regardless of redirect count.
3. Include the original error details in the HITL escalation message.

**Acceptance criteria**:
- An `infrastructure_error` classification results in `hitl` action with high
  priority
- The escalation message includes the infrastructure error details
- Non-infrastructure classifications still follow the normal ladder

**TASK-2-3: Update overseer monitor to route infrastructure errors**

Update `orchestrator/overseer/monitor.py`:

1. In the poll cycle, when processing health alerts of type
   `infrastructure_error` (from Tier 1), route them directly to the decision
   maker with the infrastructure error classification pre-set, avoiding
   redundant LLM classification.
2. For stall detections that the classifier identifies as
   `infrastructure_error`, route through the decision maker's fast-path.
3. Add logging to distinguish infrastructure error escalations from generic
   stall escalations.

**Acceptance criteria**:
- Tier 1 `infrastructure_error` alerts are processed without redundant LLM calls
- Classifier-detected infrastructure errors reach the HITL fast-path
- Logs clearly indicate infrastructure error escalation vs. generic stall

**TASK-2-4: Add unit tests for Tier 2 infrastructure error handling**

Add/update tests in:
- `tests/test_overseer_classifier.py`: Test `infrastructure_error` classification
- `tests/test_overseer_decision_maker.py`: Test auto-escalation fast-path
- `tests/test_overseer_monitor.py`: Test Tier 1 alert routing and classifier routing

**Acceptance criteria**:
- All new tests pass
- Existing tests continue to pass
- Tests cover the classification, decision-making fast-path, and monitor routing

## Phase 3: Integration, Deduplication & Documentation

### Goal
Ensure Tier 1 and Tier 2 work together without duplicate escalations, add
end-to-end integration tests, and update documentation.

### Tasks

**TASK-3-1: Add deduplication between Tier 1 and Tier 2**

Update `orchestrator/overseer/monitor.py`:

1. When the overseer processes a Tier 1 `infrastructure_error` alert, record it
   in a per-agent deduplication set (agent_id + error_hash + timestamp window).
2. When the classifier independently detects an infrastructure error for the
   same agent within the dedup window (e.g., 5 minutes), skip creating a
   duplicate HITL escalation.
3. The dedup window should be configurable via overseer settings.

**Acceptance criteria**:
- A Tier 1 alert followed by a Tier 2 classification for the same error within
  the dedup window produces only one HITL escalation
- Distinct errors for the same agent are NOT deduplicated
- The dedup window is configurable (default 5 minutes)

**TASK-3-2: Add integration test for infrastructure error escalation**

Add a test to `integration_tests/` that:

1. Simulates an agent emitting a `blocked` progress event with infrastructure
   error details
2. Verifies the Tier 1 tripwire fires and creates an alert
3. Verifies the overseer processes the alert and creates a HITL escalation
4. Verifies no duplicate HITL escalation from Tier 2

**Acceptance criteria**:
- End-to-end test passes demonstrating the full Tier 1 → overseer → HITL flow
- Deduplication verified in integration context

**TASK-3-3: Run full test suite and fix regressions**

1. Run `make test` to verify all existing tests pass
2. Run `make lint` to verify code quality
3. Fix any regressions introduced by the changes

**Acceptance criteria**:
- `make test` passes (zero failures)
- `make lint` passes (zero errors)
- No pre-existing test failures introduced

- Reviewer should verify the dedup window default (5 min) is reasonable for
  the 30-second overseer poll cycle

## Open Questions (from analysis)

The analysis raised several open questions. The plan proceeds with these defaults
but they may be adjusted based on HITL decisions:

1. **Detection approach**: Plan implements Option D (combined) as recommended
2. **Escalation behavior**: Plan implements direct HITL (no nudge/redirect for
   infra errors) as the default — this can be made configurable later
3. **Agent progress emission**: Plan does NOT modify agent prompts/rules in this
   PR — that's a separate concern. The Tier 2 enhancement covers agents that
   don't emit structured blocked events.
4. **Alert type naming**: Plan uses a single `infrastructure_error` type for
   simplicity
5. **Dedup window**: Plan defaults to 5 minutes, configurable
