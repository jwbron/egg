# Plan: Fix missing phase on BRC consensus messages

## Summary

All 8 `Message()` creations in the consensus signal handlers (`orchestrator/routes/signals.py`) omit the `phase` field, which defaults to `None`. This causes both the phantom "unknown" phase in the BRC summary and the empty BRC history files. The fix adds a small helper to resolve the current pipeline phase and passes it to every BRC message creation.

**Risks / edge cases**: Each consensus handler already has access to `pipeline_id` and `repo_path`. The `handle_consensus_confirmed_signal` fallback path already resolves `_phase` locally but doesn't pass it to the Message — we'll use that existing value. If pipeline loading fails (shouldn't happen since the pipeline must exist for signals to arrive), the helper falls back to `"implement"` which is the most common phase for BRC.

## Implementation

### Phase 1: Implement

Fix the missing phase field on BRC consensus messages and add regression tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/signals.py`, add a helper `_resolve_pipeline_phase(pipeline_id, repo_path)` that loads the pipeline via `get_state_store(repo_path).load_pipeline(pipeline_id)` and returns `pipeline.current_phase.value`, with `"implement"` fallback on any exception. Place it near the other consensus helpers (around line 839). Acceptance: helper exists, returns phase string, handles errors gracefully.
2. **[task-1-2]** In `orchestrator/routes/signals.py`, add `phase=_resolve_pipeline_phase(pipeline_id, repo_path)` to all 8 `Message()` creations across the 5 consensus signal handlers: `handle_consensus_propose_signal` (lines 916, 936), `handle_consensus_ack_signal` (lines 1000, 1014), `handle_consensus_nack_signal` (line 1072), `handle_consensus_withdraw_signal` (line 1124), `handle_consensus_confirmed_signal` (lines 1233, 1277). For the confirmed handler's fallback path (line 1233), use the already-resolved `_phase` local variable instead of calling the helper again. Acceptance: every BRC Message creation includes a non-None phase value.
3. **[task-1-3]** In `orchestrator/tests/test_brc_history.py`, add regression tests: (a) `test_write_brc_history_skips_none_phase` — verifies `_write_brc_history` writes no file when messages have `phase=None` (documents the pre-fix behavior), (b) `test_build_brc_summary_no_unknown_phase` — verifies `_build_brc_consensus_summary` does not produce "unknown" when all messages have a valid phase set. Acceptance: both tests pass and would have caught the original bug.
