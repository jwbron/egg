# Plan: Exclude base-branch commits from re-review deltas

## Summary

Re-review prompts currently use `git diff ${LAST_REVIEW_COMMIT}..HEAD`, a two-dot snapshot diff that includes any base-branch merge that landed between the last review and HEAD. This causes automated reviewers to attribute merged-in work to the PR author.

The fix replaces the two-dot diff with `git log ${LAST_REVIEW_COMMIT}..HEAD --not origin/${BASE_REF} -p` at all five affected call sites (three GHA prompt-builder shell scripts + two spots in `orchestrator/routes/pipelines.py:_build_review_prompt`). Shell scripts accept a new `BASE_REF` env var (default `main`); `reusable-review.yml` plumbs the real base ref from its existing `pr-meta` step. Cycle-1 full-PR reviews are unchanged.

**Risks / edge cases**: `origin/${BASE_REF}` must be fetched before the command runs — GHA PR-code checkouts are shallow, so updated prompts include a `git fetch origin ${BASE_REF}` nudge first. Orchestrator worktrees already maintain `origin/${base}`. Non-default base branches are plumbed through `reusable-review.yml`'s existing `pr-meta` step — internal change, no consumer workflow edits. `git log … -p` produces a per-commit patch series; LLM reviewers handle both formats.

## Implementation

### Phase 1: Implement

Fix all five call sites, thread `BASE_REF` through the GHA workflow, and update tests.

Leave the cycle-1 three-dot `git diff {_base_ref}...HEAD` branch unchanged. Acceptance: Cycle > 1 with `last_reviewed_commit` set produces `git log <sha>..HEAD --not origin/<base> -p`; cycle 1 still produces the three-dot `git diff origin/<base>...HEAD`.

2. **[task-1-2]** In `orchestrator/routes/pipelines.py` around lines 3408-3413, update the "Delta Review" directive text to reference the new `git log … --not {_base_ref} -p` command (using the already-resolved `_base_ref`) and add a `git fetch origin {base_branch}` nudge before it. Acceptance: The "Delta Review" section of the generated prompt names the new command form and includes a `git fetch origin <base>` instruction.

3. **[task-1-3]** In each of `action/build-review-prompt.sh` (line ~142), `action/build-agent-mode-design-review-prompt.sh` (line ~92), and `action/build-contract-verification-prompt.sh` (line ~106): accept a new `BASE_REF` env var defaulting to `main` (`local base_ref="${BASE_REF:-main}"`); replace the `git diff ${LAST_REVIEW_COMMIT}..HEAD` instruction with a two-part instruction (first `git fetch origin ${base_ref}`, then `git log ${LAST_REVIEW_COMMIT}..HEAD --not origin/${base_ref} -p`); document `BASE_REF` in the file header comment block. The initial-review (no `LAST_REVIEW_COMMIT`) branch is not touched. Acceptance: Running any of the three scripts with `LAST_REVIEW_COMMIT=abc123 BASE_REF=main` produces a prompt that includes `git fetch origin main` and `git log abc123..HEAD --not origin/main -p`, and does not contain `git diff abc123..HEAD`.

4. **[task-1-4]** In `.github/workflows/reusable-review.yml`, extend the `pr-meta` step (around line 344-365) to emit a `base-ref` output from the existing `pr_json` jq pipeline: add `echo "base-ref=$(echo "$pr_json" | jq -r '.base.ref')"` alongside the existing `head-ref`, `head-repo`, `head-sha` lines. Then in the "Build review prompt from trusted main branch" step (around line 487-494), add `BASE_REF: ${{ steps.pr-meta.outputs.base-ref }}` to the `env:` block. No changes needed to consumer workflows. Acceptance: A workflow run of `reusable-review.yml` sets `BASE_REF` to the PR's actual base branch when invoking the prompt-builder step. For a PR targeting main, `BASE_REF=main`. For a PR targeting a non-main branch, `BASE_REF` is that branch name.

5. **[task-1-5]** Update `tests/action/test_build_review_prompt.py`, `tests/action/test_build_agent_mode_design_review_prompt.py`, and `tests/action/test_build_contract_verification_prompt.py`: replace existing re-review assertions that check for `git diff <sha>..HEAD` (e.g. `test_build_review_prompt.py:169`) with assertions that look for `git log <sha>..HEAD --not origin/main -p` and `git fetch origin main`; extend the test helpers (`run_build_*_prompt`) to accept a `base_ref` kwarg that sets `BASE_REF` in the env; add one new test per file that passes `base_ref="develop"` and asserts the generated prompt contains `git fetch origin develop` and `git log <sha>..HEAD --not origin/develop -p`; ensure no test still asserts the old two-dot `git diff` form on the re-review path. Initial-review tests stay as-is. Acceptance: The three test files pass under `pytest tests/action/`. No test still asserts `git diff <sha>..HEAD` on the re-review path.

6. **[task-1-6]** Update `orchestrator/tests/test_pipeline_prompts.py` wherever it asserts the content of `_build_review_prompt`'s delta branch (cycle > 1 with `last_reviewed_commit` set): replace `git diff <sha>..HEAD` assertions with `git log <sha>..HEAD --not origin/<base> -p` and assert the Delta Review directive references the new command plus the `git fetch origin <base>` nudge. Add a test that calls `_build_review_prompt(..., review_cycle=2, last_reviewed_commit="<sha>", base_branch="develop", ...)` and asserts the emitted command uses `origin/develop`, not `origin/main`. Cycle-1 tests asserting `git diff origin/main...HEAD` stay unchanged. Acceptance: `pytest orchestrator/tests/test_pipeline_prompts.py` passes and the new non-default-base test fails if `base_branch` isn't correctly threaded through.
