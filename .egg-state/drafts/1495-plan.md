# Plan: Fix consensus-complete pipelines reporting as failed

## Summary

Fix the two compounding bugs that cause successful BRC consensus to be reported as pipeline failure. The consensus wrapper needs a final consensus check before its exit-1 fallback, and the orchestrator needs to trust `is_complete=True` as the authoritative success signal rather than propagating stale `has_failures` flags from container exit codes.

**Risks / edge cases**: Safe because `is_complete=True` requires ALL agents to have confirmed.

## Implementation

### Phase 1: Implement

**Tasks**:
1. **[task-1-1]** In `orchestrator/consensus_wrapper.py` (lines 331-333), add a final consensus status check before the `exit 1`. Poll `egg-orch pipeline status --json`, extract `is_complete`, and if True, log "Consensus reached on final check" and exit 0.
2. **[task-1-2]** In `orchestrator/routes/pipelines.py` (lines 4713-4718), when consensus is complete (`is_complete=True`), log a warning if `has_failures[0]` was set but return 0 instead of 1.
3. **[task-1-3]** Add tests for both fixes.
