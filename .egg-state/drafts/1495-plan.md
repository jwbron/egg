# Plan: Fix consensus-complete pipelines reporting as failed

## Summary

Fix the two compounding bugs that cause successful BRC consensus to be reported as pipeline failure. The consensus wrapper needs a final consensus check before its exit-1 fallback, and the orchestrator needs to trust `is_complete=True` as the authoritative success signal rather than propagating stale `has_failures` flags from container exit codes.

**Risks / edge cases**: Safe because `is_complete=True` requires ALL agents to have confirmed — it's the strongest possible success signal. An OOM-killed agent wouldn't confirm, so `is_complete` would remain False and the existing failure path still triggers. `_update_agents_complete()` already overwrites FAILED status for the consensus path.

## Implementation

### Phase 1: Implement

Fix both the consensus wrapper exit code and the orchestrator's consensus-complete failure propagation.

**Tasks**:
1. **[task-1-1]** In `orchestrator/consensus_wrapper.py` (lines 331-333), add a final consensus status check before the `exit 1`. Poll `egg-orch pipeline status --json`, extract `is_complete`, and if True, log "Consensus reached on final check" and exit 0. This catches the timing race where consensus completes during or after the last restart. Acceptance: consensus wrapper exits 0 when consensus is complete, even after exhausting max restarts.
2. **[task-1-2]** In `orchestrator/routes/pipelines.py` (lines 4713-4718), when consensus is complete (`is_complete=True` from the consensus check), log a warning if `has_failures[0]` was set (noting the exit codes are being overridden by consensus success) but return 0 instead of 1. Update the comment to reflect that `is_complete=True` means ALL agents confirmed, so container exit codes are not meaningful. Acceptance: orchestrator returns success (0) when consensus is complete, regardless of container exit codes.
3. **[task-1-3]** Add/update tests: (a) test that the consensus wrapper template includes the final consensus check before exit 1, (b) test that `_wait_for_consensus` returns 0 when consensus is complete even when `has_failures` is True. Acceptance: tests pass and cover both fix paths.
