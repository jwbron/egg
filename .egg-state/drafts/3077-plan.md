# Plan: Coordination state is served, not replicated — retire git/prompt choreography for agent state exchange

> Issue: #3077 | Phase: plan | Pipeline: issue-3077
> Scope: HITL-approved **Option C** (full remaining scope), strict endpoint resolution (Q2), fail-loud durability bound (Q3).
> Slice DAG follows the architect's 6-slice design (`.egg-state/agent-outputs/3077-architect-slices.yaml`).

## Goal

Land the remaining scope of #3077 after phase 1 (PRs #3078/#3083):

1. **R1 residual** — `sync_to_proposals()` failures must surface in the agent-visible
   event prompt instead of dying in a log line (the non-silence rule extended to
   clause-2 harness sync).
2. **Phase 2** — a single declarative **artifact spec** (name, path template,
   phase, producer, consumers) from which propose-time validation for **all**
   refine/plan producers and a **gateway artifact-read endpoint** (strict,
   spec-registered names only) both derive. The endpoint is the blocking
   prerequisite of #3002.
3. **Phase 3** — delete/demote prompt-prose sync mechanics (REVIEWER-SYNC fetch
   prose, event-prompt self-fetch fallback), add the `docs/architecture`
   invariant entry, and add a **ratchet test** so the prose channel cannot
   drift back.
4. **Bounded durability** — fail-loud (error-level log + degraded health flag)
   when BRC consensus runs on the in-memory message-store backend; restart-
   semantics test for the Redis Streams path. No behavioral change to `auto`
   (HITL Q3); deeper work stays in the #3070 lineage.

## Slice DAG (architect's design)

```
slice 1 (R1 sync banner)
   └─> slice 2 (artifact spec)
          └─> slice 3 (spec-derived validation)
                 └─> slice 4 (gateway read endpoint + sandbox helper)
                        └─> slice 5 (prose cleanup + docs + ratchet)
slice 6 (bounded durability)            ← parallel root, disjoint file set
```

Slices 1-5 are a serialized chain: the spec must exist before validation
derives from it; the endpoint must exist before its prose fallback is deleted
(refine risk 3). Slice 5 has a hard file-overlap with slice 1 on
`event_prompt.py` (#3046) — acceptable because the chain is strictly
serialized. Slice 6 touches only `message_store.py` + its tests and can run
in parallel.

## Slice 1 — R1 non-silent sync

`sync_to_proposals()` records a per-SHA outcome — `merged`,
`already-ancestor`, `unresolvable`, `merge-failed` — and the **wrapper**
prepends a banner to the fetched event prompt on any failure, before the agent
is invoked: *"worktree NOT synced to `<sha>` (`<reason>`); treat your local
diff as unreliable — use the `git show` commands below."* The empty-delta
caution in `event_prompt.py` (≈266-281) is updated to cross-reference the
banner. Sync behavior itself is unchanged; only reporting is new. Prompt
visibility stops being orthogonal to sync success.

## Slice 2 — Artifact spec module (no consumer behavior change)

`shared/egg_contracts/artifact_spec.py` (NEW): frozen `ArtifactSpec` rows —
`name`, `path_template` keyed on `{identifier}`, `phase`, `producer_role`,
`consumer_roles` — covering `analysis-draft`, `plan-draft`,
`architect-output`, `architect-slices`, `risk-analyst-output`; helpers
`resolve_artifact_path` / `specs_for` / `spec_by_name`. **Mandatory in-slice
consistency tests** (refine risk 1 — the spec must not become a fourth
replica): every spec path is admitted by the matching `gateway/phase_filter.py`
phase gate and the `phase_patterns.py` mirror; `_get_draft_path` output equals
spec resolution for both identifier shapes; prompt f-string literals in
`orchestrator/routes/pipelines.py` match the spec. No consumer is rewired yet.

## Slice 3 — Spec-derived propose validation for all refine/plan producers

`orchestrator/routes/signals.py`: for every CONSENSUS_PROPOSE carrying a
`commit_sha`, resolve `specs_for(phase, producer_role)` and run the existing
`git show` presence check per artifact — reusing the single helper and the
#3081 `branch_verified` graceful-degradation semantics, no fork. Plan-draft
keeps its `parse_plan` (#3026) and role-alignment (#2527/#2528) extensions.
`_validate_producer_draft_present` (refine) is subsumed and deleted.
Orchestrator prompt/validation path construction is re-derived from the spec,
replacing the literals slice 2 merely asserted against. Roles with no
registered artifact validate nothing; `no_changes_needed` skips.

## Slice 4 — Gateway artifact-read endpoint (strict) + sandbox helper

`POST /api/v1/artifact/get`: a new gateway blueprint modeled on
`gateway/contract_api.py` (session auth, role from session, forward to the
orchestrator); a new `orchestrator/routes/artifacts.py` resolves
spec-registered name + hex-validated committed ref via `git show` against the
authoritative repo, with existing output caps and a `truncated` flag.
**STRICT per HITL Q2**: no path field exists in the request schema;
unregistered names get a 400 listing registered names. A small sandbox-side
helper (`sandbox/scripts/egg-artifact`) gives agents one verb instead of
hand-built curl. Cross-linked as unblocking #3002.

## Slice 5 — Prose cleanup, docs invariant, ratchet

Delete the agent-facing fetch/log sync prose: the REVIEWER-SYNC.md
delta-command row (replaced with served-reads wording — documenter-owned per
`shared/egg_restrictions/patterns.py`) and the `event_prompt.py` "fetch and
read the diffs yourself" fallback prose (≈850-880). Add the
`docs/architecture` served-coordination-state invariant entry (three clauses +
incident lineage). Add the ratchet pytest scanning agent-facing prompt sources
(`shared/prompts/*.md`, prompt-constructing template strings) for
`git fetch`/`git merge`/`git pull` imperatives and brc-history paths, with a
justified allowlist for harness-internal code. Ordered last so every
replacement mechanism (banner, spec, validation, endpoint) is live before its
prose predecessor is deleted.

## Slice 6 — Bounded durability (parallel root)

Per HITL Q3 (fail-loud only, no refusal): in
`orchestrator/message_store.py` `_create_message_store()`, an `auto`→memory
fallback emits an **error-level** structured log with a stable marker and sets
a health-visible degraded flag; explicit `EGG_MESSAGE_STORE_BACKEND=memory`
stays a **warning**. Redis-path restart-semantics test: mid-phase messages
survive store re-instantiation against the same Redis, while the designed
`_clear_concurrent_state()` phase-boundary wipe still occurs. Touches only
`message_store.py` + tests — disjoint from the main chain.

## Risks and mitigations (planner view; risk_analyst owns the register)

- **Spec becomes a fourth replica** — slice-2 consistency tests are mandatory
  and in-slice (TASK-2-2); slice 3 then re-derives the asserted literals.
- **Endpoint policy surface creep** — strict name-only schema (no path field),
  hex-validated committed refs, reused output caps + `truncated` flag.
- **Prose deletion regression** — chain strictly serialized; reviewers keep
  rendered `git show` delta commands and gain the served endpoint before the
  fetch fallback is removed.
- **Validation generalization breaking no-op proposes** — explicit
  pass-through acceptance in TASK-3-1 (`no_changes_needed`, artifact-less
  roles).
- **event_prompt.py file overlap (slices 1 and 5, #3046)** — serialized chain;
  slice-5 task rebases on the slice-1 state of the file.
- **Wipe-semantics conflation** — TASK-6-2 asserts the designed
  `_clear_concurrent_state()` wipe and accidental mid-phase loss separately.
