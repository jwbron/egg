# Plan: Coordination state is served, not replicated — retire git/prompt choreography for agent state exchange

> Issue: #3077 | Phase: plan | Pipeline: issue-3077
> Scope: HITL-approved **Option C** (full remaining scope), strict endpoint resolution (Q2), fail-loud durability bound (Q3).

## Goal

Land the remaining scope of #3077 after phase 1 (PRs #3078/#3083):

1. **R1 residual** — `sync_to_proposals()` failures must surface in the reviewer's
   event prompt instead of dying in a log line (the non-silence rule extended to
   clause-2 harness sync).
2. **Phase 2** — a single declarative **artifact spec** (name, path template,
   phase, producer, consumers) from which propose-time validation for **all**
   producers and a **gateway artifact-read endpoint** (strict, spec-registered
   names only) both derive. The endpoint is the blocking prerequisite of #3002.
3. **Phase 3** — delete/demote prompt-prose sync mechanics (REVIEWER-SYNC fetch
   instructions, event-prompt fallback prose), add the `docs/architecture`
   invariant entry, and add a **ratchet test** so the prose channel cannot drift
   back.
4. **Bounded durability** — fail-loud (startup warning + health signal) when BRC
   consensus runs on the in-memory message-store backend; restart-semantics test
   for the Redis Streams path. No behavioral change to `auto` (HITL Q3); deeper
   work stays in the #3070 lineage.

## Slice 1 — Served-read foundations: non-silent sync, artifact spec, fail-loud durability

The three independent pieces everything else consumes. The artifact spec module
is the single source of truth; the R1 fix closes the last silent channel from
phase 1; the durability bound makes memory-backend loss attributable.

Key decisions:

- **Sync outcome plumbing (R1):** `sync_to_proposals()` records a per-SHA
  outcome (`synced` / `sha-unresolvable` / `merge-failed`) into the wrapper's
  existing durable state surface consumed by event-prompt composition. The
  prompt renderer prepends a prominent warning on any non-`synced` outcome:
  *"worktree NOT synced to `<sha>`; treat your local diff as unreliable — use
  the `git show` commands below."* Prompt construction stops being orthogonal
  to sync success.
- **Spec shape:** a declarative table in `shared/egg_contracts/artifact_spec.py`
  — one entry per artifact: `name` (stable id, e.g. `refine-analysis`,
  `plan-draft`), `path_template` (e.g. `.egg-state/drafts/{issue}-plan.md`),
  `phase`, `producer_role`, `consumer_roles`. Pure-Python registry with a
  `resolve_path(name, issue|pipeline_id)` function and reverse lookup
  (`match_path`). No new config file format — #3017 consumes this later
  (decoupled, per the revised issue).
- **Adoption is mandatory, not optional** (refine risk 1): existing hardcodings
  are re-derived from the spec where cheap (`_get_draft_path`) and
  asserted-consistent by test where re-derivation would destabilize
  (gateway phase gates), so the spec cannot become a fourth replica.
- **Durability bound:** when the resolved backend is `memory` and BRC consensus
  is in play, emit a prominent startup warning and expose it on the existing
  health surface. No refusal-to-run (HITL Q3).

## Slice 2 — Spec consumers: all-producer propose validation + gateway artifact-read endpoint

Depends on slice 1 (needs the spec module).

Key decisions:

- **Validation generalization:** `signals.py` propose validation derives the
  expected draft path from the spec for **every** producer role with a
  registered artifact, replacing both the plan-only branch and
  `_validate_producer_draft_present`. Plan-specific extensions (parse_plan
  parseability #3026, role↔files alignment #2527/#2528) remain layered on top
  for the plan artifact only. Producers with no registered artifact (pure
  reviewers / no-op proposes) are unaffected.
- **Endpoint:** `POST /api/v1/artifact/get` on the gateway, modeled on
  `contract_api.py` forwarding. Request: artifact `name` + `ref` (commit SHA) +
  issue/pipeline binding; the server resolves the path via the spec and reads
  `git show <ref>:<path>` from the authoritative repo. **Strict**: raw repo
  paths are rejected (HITL Q2). Output caps consistent with existing handlers.
  This removes the shared-object-store assumption and unblocks #3002.
- **Sandbox helper:** a thin read CLI (`sandbox/scripts/egg-artifact`) so agents
  consume the served read without hand-rolling HTTP; prompt templates can later
  reference one verb instead of path prose.

## Slice 3 — Prose retirement, invariant entry, ratchet

Depends on slice 2 (the served read must exist before its prose fallback is
deleted — refine risk 3 sequencing).

Key decisions:

- Delete the `git fetch origin ${BASE_REF}` / `git log` instructions from
  `shared/prompts/REVIEWER-SYNC.md` (≈109-111) and the "fetch and read the
  diffs yourself" fallback prose around `_render_producer_delta_section()` /
  `_run_git_log()` in `event_prompt.py` (≈207-298, 676-735). Residual per-role
  "write your analysis to <path>" prose is demoted to referencing the spec.
  Role split: `shared/prompts/` templates are documenter-owned per
  `shared/egg_restrictions/patterns.py`, so the template prose (TASK-3-4) is
  separated from the event-prompt code prose (TASK-3-1, coder).
- `docs/architecture` gains the three-clause invariant entry (served reads /
  harness-performed sync / one artifact spec) with the incident lineage, linked
  from `docs/index.md`.
- **Ratchet test:** scans agent-facing prompt templates (and static prompt
  prose in `event_prompt.py`) for sync mechanics — `git fetch` / `git merge` /
  `git pull` instructions and `brc-history` path references — and fails on any
  reintroduction. Writable only now because slice 3 deleted the legitimate
  occurrences (refine Option A's noted awkwardness).

## Slice DAG

```
slice 1 (foundations) ──> slice 2 (spec consumers) ──> slice 3 (prose + ratchet)
```

Strictly serialized: slice 2 imports the slice-1 spec; slice 3 deletes prose
whose replacement ships in slice 2.

## Risks and mitigations (planner view; risk_analyst owns the register)

- **Spec becomes a fourth replica** — mitigated by TASK-1-7's mandatory
  consistency tests and TASK-1-4's re-derivation of `_get_draft_path`.
- **Endpoint policy surface creep** — strict name-only resolution (HITL Q2),
  committed refs only, existing output caps reused (TASK-2-2 acceptance).
- **Prose deletion regression** — slices serialized; reviewers keep `git show`
  delta commands (which remain rendered) and gain the served endpoint before
  the fetch fallback is removed.
- **Validation generalization breaking no-op proposes** — TASK-2-1 acceptance
  explicitly preserves `no_changes_needed` and reviewer-role propose paths.
