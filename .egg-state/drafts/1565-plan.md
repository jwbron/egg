# Plan: Give SDLC reviewers full changeset context matching PR review bots

## Summary

Close the context gap between SDLC reviewers and PR review bots by fixing three things: (1) explicit fetch+merge step in BRC lifecycle so reviewers have the producer's commits, (2) correct diff command using `origin/{base_branch}...HEAD` for the full changeset, (3) stronger "find ALL issues" emphasis matching the PR bot's prompt. All changes are prompt-level in `pipelines.py`.

**Risks / edge cases**: None significant. All three changes are prompt-level. The `base_branch` is always available via `pipeline.base_branch` or `get_default_branch()`. Agents already fetch implicitly — we're making it explicit.

## Implementation

### Phase 1: Implement

Fix reviewer context to match PR review bot thoroughness.

**Tasks**:
1. **[task-1-1]** In `_build_brc_preamble()` (pipelines.py:3515), add a sync step to the reviewer lifecycle between POLL (step 2) and REVIEW (step 3): "Before reviewing, sync your worktree: `git fetch origin && git merge origin/{branch} --no-edit`". Thread `branch` (the pipeline branch, e.g. `egg/issue-1565`) into this function via a new parameter. Add the same sync step to the producer lifecycle for dual-role agents (like tester) that also review other producers — add it before step 4 "RESPOND TO REVIEWS" isn't right; instead add a note in the ORIENT step that they should sync before reviewing proposals. Acceptance: BRC preamble for reviewers includes fetch+merge with the actual branch name.

2. **[task-1-2]** Thread `base_branch` and `branch` through the call chain. In `_run_concurrent_phase()` (line 4443), add `base_branch: str | None = None` and `branch: str | None = None` parameters. Pass them through to `_build_agent_prompt()` (line 3888) which passes them to `_build_review_prompt()` (line 1925) and `_build_brc_preamble()` (line 3515). At the call site in `_run_pipeline()` (line 6590), pass `base_branch=pipeline.base_branch or get_default_branch(worktree_repo_path)` and `branch=pipeline.branch`. Acceptance: Parameters flow through the entire call chain.

3. **[task-1-3]** In `_build_review_prompt()`, replace `"git diff HEAD~10..HEAD"` (line 1969) with `f"git diff origin/{base_branch}...HEAD"` (three-dot syntax for merge-base diff). When `base_branch` is None, fall back to `"origin/main"`. In the producer context pointer `_build_role_context()` (line 1870), replace `"git diff HEAD~10..HEAD"` with the same `origin/{base_branch}...HEAD` pattern. Add "**Find ALL issues on the first pass** — do not stop after identifying a few problems." to the code reviewer's task preamble (near line 1981, before the systematic review steps), matching the emphasis from `action/build-review-prompt.sh:165`. Acceptance: No `HEAD~10` remains in any prompt; code reviewer gets "Find ALL issues" emphasis.

4. **[task-1-4]** Add tests in `orchestrator/tests/test_pipeline_prompts.py`: (a) `_build_review_prompt` with `base_branch="main"` produces `origin/main...HEAD` and does not contain `HEAD~10`, (b) `_build_review_prompt` without `base_branch` falls back to `origin/main`, (c) `_build_brc_preamble` with reviewer role and `branch="egg/issue-123"` includes `git fetch origin && git merge origin/egg/issue-123`, (d) code reviewer prompt includes "Find ALL issues". Acceptance: All tests pass.
