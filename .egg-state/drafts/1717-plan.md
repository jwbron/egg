# Plan: Losslessly persist BRC message context to the PR

## Summary

Rewrite the three lossy rendering functions in `orchestrator/routes/pipelines.py` and the `BRC_MESSAGE_TYPES` filter so BRC message context reaches the PR losslessly. The `Message` model already carries every field we need (`id`, `to_role`, full `metadata`, `phase`) — this is purely a rendering change plus a new JSON companion artifact. We split `BRC_MESSAGE_TYPES` into two sets: a narrower set for PR-body summary counts (so tallies stay comparable) and a wider set for the committed history file (so humans and tools get the full flow). The PR body summary gains inline content with `<details>` collapsing older rounds and links to the committed artifacts for the authoritative full record.

**Risks / edge cases**: (1) Non-JSON-serializable metadata values — the JSON companion must use `default=str` fallback. (2) PR body size — GitHub's 65k-char cap requires conservative truncation of individual message bodies with a pointer to the history file, never dropping messages. (3) Existing tests in `test_brc_history.py`, `test_pr_phase_brc_rewrite.py`, and `test_diagnostic_logging_1633.py` assert exact markdown shape and need updating. (4) The history file format is externally observable (committed to the PR branch), but it is always regenerated by `_rewrite_brc_history_for_pr` at PR-creation time, so changing the format is safe for new PRs.

## Implementation

### Phase 1: Implement

Rewrite the three renderers and add a JSON companion artifact, then update and extend tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py`, split `BRC_MESSAGE_TYPES` into `BRC_SUMMARY_TYPES` (the six existing `CONSENSUS_*` types, used by `_build_brc_consensus_summary` for counts) and `BRC_HISTORY_TYPES` (the six `CONSENSUS_*` types plus `STATUS`, `HANDOFF`, `QUESTION`, `AGENT_FAILED`, `NUDGE`, `OVERSEER_ALERT`, used by `_write_brc_history`). Keep `BRC_MESSAGE_TYPES` as an alias of `BRC_SUMMARY_TYPES` for any external callers, or update call sites if there are none. Acceptance: `_build_brc_consensus_summary` only counts CONSENSUS_* types; `_write_brc_history` filters using the wider set.
2. **[task-1-2]** Rewrite `_write_brc_history` (`pipelines.py:4196-4290`) to losslessly project messages. For each filtered message, render `### [ts] {from_role} → {to_role if not "all"} ({type}): {subject}`, then the body, then a fenced ```yaml``` block containing `id`, `phase`, and the full `metadata` dict (only when non-empty). YAML-dump with `sort_keys=False, default_flow_style=False` for readability and grep-ability. Filter using `BRC_HISTORY_TYPES`. Acceptance: the markdown contains a YAML metadata block per message with all populated metadata fields (`artifact_references`, `ack_version`, `commit_sha`, `revision_count`, `version`), and `to_role` appears on directed messages.
3. **[task-1-3]** In `_write_brc_history`, additionally emit a companion `.egg-state/brc-history/{identifier}-{phase}.json` containing a list of `msg.to_dict()` for every filtered message. Use `json.dumps(..., indent=2, default=str)` to tolerate non-serializable metadata values. Wrap the JSON write in its own try/except that logs at `warning` level so a JSON failure does not block the markdown write (and vice versa). Acceptance: the JSON file exists on the PR branch, round-trips through `json.loads` to a list of dicts matching `Message.to_dict()` output, and includes HANDOFF/AGENT_FAILED/OVERSEER_ALERT/STATUS/NUDGE/QUESTION messages.
4. **[task-1-4]** Rewrite `_build_brc_consensus_summary` (`pipelines.py:4515-4591`) to inline content. Preserve the per-phase header with roles, count line, and ✅/⏳ marker, but after the counts emit the final round's `CONSENSUS_PROPOSE` body plus all final-round ACK/NACK rationales inline (using `msg.body` or `msg.metadata.get("payload", {}).get("reason")` as appropriate). Wrap older/earlier-round messages in `<details><summary>Earlier rounds</summary>…</details>`. Append per phase a line: `Full record: [.egg-state/brc-history/{identifier}-{phase}.md](./.egg-state/brc-history/{identifier}-{phase}.md) · [.json](./.egg-state/brc-history/{identifier}-{phase}.json)`. Raise the total summary cap to ~40000 chars. When truncating an individual body, replace the tail with `… _(full content in brc-history/*.md)_` — never drop whole messages. The `_build_brc_consensus_summary` function signature currently takes only `pipeline_id`; extend to also take `identifier` (or look it up via the pipeline) so the link lines can reference the correct file names, and update the call site in `_build_pr_body` at line 4671. Acceptance: PR body per phase contains final-round proposal body and NACK rationale inline, older rounds wrapped in `<details>`, artifact links present.
5. **[task-1-5]** Update existing tests (`orchestrator/tests/test_brc_history.py`, `orchestrator/tests/test_pr_phase_brc_rewrite.py`, `orchestrator/tests/test_diagnostic_logging_1633.py`, `orchestrator/tests/test_brc_phase_propagation.py` if affected) to match new output shapes. Add new tests covering: (a) ACK `artifact_references` and `ack_version` metadata round-trip into the YAML block, (b) NACK `metadata.payload.reason` and `revision_count` round-trip, (c) PROPOSE `commit_sha` appears, (d) `HANDOFF` and `OVERSEER_ALERT` are included in the history file but NOT counted in the summary, (e) JSON companion file is written and deserializes back to message dicts with all fields, (f) `to_role` is shown for directed messages and omitted for broadcasts, (g) PR body summary contains final-round proposal body and final-round ACK/NACK rationale inline, (h) older rounds are wrapped in `<details>`, (i) artifact links appear in the PR body summary. Acceptance: `make test` passes; new tests cover each listed behavior.
