# Plan: Decompose 17 oversize Python source files to empty the file-size allowlist

> Issue: #2817 | Phase: plan | Pipeline: issue-2817 | Refresh of #2261

## Overview

This plan decomposes the 17 files in `scripts/file-size-allowlist.yaml`'s `files:` map so the global 1500-line / 100 KB file-size lint cap holds without any grandfathering. The acceptance contract is binary: every file in the allowlist drops under the cap, the `files:` map empties, `make lint` and `make test-all` are green at every PR boundary, and the seam tables in `orchestrator/CLAUDE.md`, `gateway/CLAUDE.md`, the new `sandbox/CLAUDE.md` table, and the net-new `shared/CLAUDE.md` carry concrete submodule layouts.

The pattern is already locked: sub-package + explicit per-symbol re-export barrel + underscore-prefixed private submodules, documented in `docs/guides/decomposition-pattern.md` (already-merged via #2335). `scripts/select_tests/` is the worked reference. Six prior pipeline attempts (#2261-v3 through v10) failed to land any follow-up slice — the dominant program risk is reviewer-bandwidth + slice-DAG discipline, not novel technical risk.

I adopt the architect's 28-slice DAG verbatim (`.egg-state/agent-outputs/2817-architect-slices.yaml`); my role here is to enumerate `tasks:` within each slice with TASK-<slice>-<n> IDs, acceptance criteria, and role assignments. Slice composition is the architect's call (#2809).

## Approach

**Slice family layout.**

- **Slice-1 (root, docs/scaffolding)**: refreshes `docs/guides/decomposition-pattern.md` for cq-4, retags stale `#2261` references to `#2817` (cq-6), creates `sandbox/CLAUDE.md` seam table and the net-new `shared/CLAUDE.md` (cq-2), adds TBD rows for `kubernetes_spawner.py` + `routes/phases.py`, and retags the two allowlist comment blocks (cq-5). No source decomposition lands in slice-1.
- **Slices 2–7 (pipelines.py chain)**: linear stack, slice-N depends on slice-(N-1). Slice-2 lands step-0 baseline + five flat clusters. Slices 3-6 each extract one sub-sub-package (`_prompt_building/`, `_pr_lifecycle/`, `_worktree_ops/`, `_concurrent_phase/`). Slice-7 is terminal: per-phase carve-out of `_run_pipeline` (TASK-7-3..7-7) + allowlist drop + seam table.
- **Slices 8–12 (gateway.py chain)**: linear stack, slice-N depends on slice-(N-1), root at slice-8 (depends on slice-1 for docs scaffolding). Slice-8 lands step-0 baseline + flat clusters + `_app_factory`/`_auth`/`_checkpoint_routes`/`_gh_routes`. Slices 9-11 each extract one sub-sub-package (`_git_routes/`, `_jira_routes/`, `_confluence_routes/`/`_worktree_routes`/`_anthropic_proxy`). Slice-12 is terminal: `_sessions` + allowlist drop + seam table.
- **Slices 13–28 (independent per-file decompositions)**: all root at slice-1. Each is a single file → sub-package conversion + cluster carve-outs + allowlist drop + seam-table fill-in. Slice-22 → slice-23 is a chained pair (monitor.py PREP → TERMINAL) because the 885-LOC `write_health_summary` method needs in-place named-helper breakup first.

**Concurrency strategy.** Concurrency cap stays at `EGG_ORCH_MAX_PARALLEL_SLICES=2` per-pipeline (orchestrator/CLAUDE.md:688) / `EGG_ORCH_GLOBAL_MAX_PARALLEL_SLICES=4` global (orchestrator/CLAUDE.md:689). The DAG has a single root (slice-1), so the scheduler will not admit slice-2 / slice-8 / slice-13+ until slice-1 lands. Within the leaf set, the SliceScheduler will admit up to 2 parallel slices. Per RISK-3, `scripts/file-size-allowlist.yaml` is a serialization bottleneck — concurrent slices will rebase-conflict on neighbouring `files:` entries. The pattern-doc rebase recipe at `docs/guides/decomposition-pattern.md:186-214` is the canonical resolution.

**Allowlist serialization.** Each decomposition slice removes exactly one entry from `scripts/file-size-allowlist.yaml`. The 9-line comment block for `plan_parser.py` and `phases.py` is removed entirely when those files decompose; the 15 single-line entries shrink to nothing. Slice-1 retags the two comment blocks up-front (cq-5), so subsequent slices see a coherent allowlist file.

**`_run_pipeline` per-phase strategy.** Slice-7 lands two stages inside the same slice (per architect TASK-7-3..7-7): (1) introduce a `PHASE_HANDLERS` dispatch table with bodies as local closures (bisectable indirection, no size win), then (2) lift each per-phase body into its own module under `_run_loop/_run_refine.py`, `_run_plan.py`, `_run_implement.py`, `_run_pr.py`, with a thin `_orchestration.py` `_run_pipeline` <300 LOC and a `_PipelineRunContext` dataclass. Per-phase handler unit tests are tracked separately under #2319.

**Test strategy.** Existing tests use the barrel surface (`patch("routes.pipelines._foo")` etc.) and continue resolving through `__init__.py` re-exports — no test file moves are required for the non-pipelines slices. For slices 2–7, tests in `tests/orchestrator/routes/test_pipelines*.py` keep using the same 49-symbol patch-target surface (verified: 144 raw matches across `routes.pipelines.<sym>`; 6 across `gateway.gateway.<sym>`; 0 across `mcp_tools.<sym>`). Non-negotiable #10 is relaxed per cq-4 — scenario-organized test suites may stay topical; the `select_tests/` reference is intentionally not retrofit. **Manual smoke test on slice-7**: run a refine→plan→implement→pr pipeline end-to-end (a small documentation-only issue is enough) to verify the per-phase carve-out preserved BRC consensus + signal handling + slice-DAG admission sequencing.

### Primitive trust-boundary notes (for plan reviewer §10)

- `scripts/file-size-allowlist.yaml` runs in **trusted-CI-runner** context (`make lint` invoked by GitHub Actions and pre-commit-equivalent local). The lint operates on the working-tree file and the file's mtime; no agent privileges required.
- `gateway/gateway.py` Flask routes execute in **trusted-gateway-sidecar** context with credential-injection middleware. The decomposition preserves decorator placement (non-negotiable #8) so route-registration order and credential-injection middleware scope are unchanged.
- `orchestrator/routes/*.py` Flask blueprints execute in **trusted-orchestrator-pod** context. Blueprint registration happens at module import; preserving thin-wrapper decorator placement in `__init__.py` keeps URL→handler mapping stable.
- Test files run in **trusted-CI-runner** under `pytest`. Patch targets like `patch("routes.pipelines._foo")` resolve through the barrel `__init__.py` and depend only on Python's import resolution — no privileged execution surface is touched.
- No in-sandbox-agent test fixture is touched. The plan does not introduce any `gateway_url` / `orchestrator_url` pytest fixture references — all fixtures stay in `integration_tests/local_pipeline/conftest.py` and are not used by the decomposition slices.

## Test Strategy

Automated test coverage is the existing `make test-all` gate (full pytest suite + mypy + ruff + custom checks via `lint-custom`). Each slice must be green at every commit boundary; the size lint (`scripts/check-file-sizes.py`) is part of `make lint` and gates each PR for "this file shrank vs. baseline" ratchet semantics. For the `pipelines.py` and `gateway.py` slice chains, the canonical test loop is:

1. Author runs `make lint` locally → confirms `check-file-sizes.py` shows strict decrease on the touched file.
2. Author runs `make test` locally → confirms changeset-aware narrowing selects tests for the touched module.
3. CI runs `make test-all` on the PR → full-suite green gate.

For the terminal slices (slice-7 for pipelines.py, slice-12 for gateway.py), an additional **manual smoke test** is required: run a small refine→plan→implement→pr SDLC pipeline against a doc-only issue and verify no behaviour change in BRC consensus, signal handling, or slice-DAG admission. This is the safety net for RISK-2 (the per-phase carve-out is the highest-risk extraction).

For each per-file slice, the producer runs the **external-importer audit** recipe from `docs/guides/decomposition-pattern.md:160-178` BEFORE extracting clusters: `git grep -nE "(<module>\.|from .* import .*\b<symbol>\b)" -- '*.py'`. The audit deliverable is a comment in the slice PR description listing every external-referenced symbol and confirming each is re-exported from `__init__.py`. The audit grep MUST be unanchored (per blocker-4) so in-function lazy imports are caught.
