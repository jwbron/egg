# Plan: Fix Delphi filter deadlock — redact instead of withhold

## Summary

Replace the Delphi filter's full message withholding with a redacted pass-through. When a reviewer hasn't yet evaluated a producer, send the `CONSENSUS_PROPOSE` message with `body` cleared and `metadata.payload.summary` stripped, but preserve the message header (`from_role`, `message_type`, `subject`, `metadata.version`, `metadata.commit_sha`). This lets reviewers discover that a proposal exists — unblocking the "poll for proposals" workflow — without exposing the producer's self-assessment before independent review.

**Risks / edge cases**: Agents that already work around the filter (by checking consensus status) will simply receive an additional notification — additive, not breaking. The `subject` field ("Proposal from <role>") is structural metadata, not producer rationale, so it's safe to keep. After the reviewer ACKs/NACKs, subsequent polls return the full unredacted message as before.

## Implementation

### Phase 1: Implement

Fix the Delphi visibility filter to redact CONSENSUS_PROPOSE messages instead of dropping them entirely, and update tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/messages.py:poll_messages()`, replace the `continue` (line 191) that drops withheld PROPOSE messages with logic that appends a redacted copy — clear `msg.body` and strip `metadata.payload` keys except `version` and `commit_sha`, and add `metadata.delphi_redacted = True`. Acceptance: reviewer polling before ACK/NACK receives CONSENSUS_PROPOSE with empty body, stripped payload, and delphi_redacted flag.

Add a new test `test_propose_redacted_preserves_header` verifying `from_role`, `subject`, `version`, and `commit_sha` survive redaction while `body` and `payload.summary` are stripped.
