# Plan: Event-driven BRC wait primitives + heartbeats — Issue #1897

> Issue: #1897 | Phase: plan | Single PR

## Approach

This plan implements the **full Option C** scope confirmed at the refine phase
gate (decision-1 = "all five items"). All work lands in one branch
(`egg/issue-1897`) and one PR. Inside that PR the work is organised into
**eight phases** (Phase 1 → Phase 8) that should land as separate commits so
reviewers can step through them.

### Strategy rationale

The architecture splits along **two natural seams** that let us land code in a
safe order:

1. **Server-side primitives first, client-side consumers second.** Phases 1–2
   add the new APIs (typed `XREAD BLOCK`, env-configurable cap, condition
   variable on the in-memory store, `GET /messages/wait`, `egg-orch message
   wait`) without changing any agent behaviour. Phase 4 (consensus_wrapper)
   and Phase 5 (agent prompts) are the consumers that *only become correct*
   once the primitives exist.
2. **Additive evolution before subtractive cleanup.** Phase 3 adds the new
   `HEARTBEAT` message type. Phase 6 removes the `QUESTION` type. Doing them
   in that order means there is no window where the bus has *neither* type,
   and old contract files / mid-flight pipelines never see an unknown enum.

The HITL Q1 answer confirms PR #1896 already closes the consensus-confirmed
dedup symptom in the issue — Phase 7 adds a regression test but no new
production code is needed for that bullet of the original report.

### Test strategy

Each backend change ships with unit tests in `orchestrator/tests/`. The
prompt-builder changes update locked-in fixtures in
`orchestrator/tests/test_pipeline_prompts.py`. The new `egg-orch message
wait` CLI gets contract tests in `sandbox/tests/`. Phase 8 wires up an
end-to-end concurrent-integration smoke test that asserts an agent reacts
to a CONSENSUS_REACHED in <2s rather than the previous multi-minute window.

Manual verification: a reviewer should run a synthetic two-agent pipeline
locally with `EGG_MESSAGE_STORE_BACKEND=memory` and confirm `egg-orch
message wait --for CONSENSUS_REACHED --timeout 30` actually blocks (i.e. the
in-memory condition variable works) and that no `for i in 1..N; do …; done`
or `sleep N &&` patterns appear in agent output (grep the agent transcripts
in `.egg-state/brc-history/`).

### Risk-mitigation cross-references

- **Container shutdown / SIGTERM** (decision-8 constraint): Phase 4's
  consensus_wrapper rewrite must respect the orchestrator graceful-shutdown
  grace period. A blocked Redis XREAD must unblock on SIGTERM and exit 0
  (the wrapper's existing exit-code classification is preserved).
- **Gateway HTTP_PROXY idle timeout** (decision-3 constraint): the env var
  `EGG_MESSAGE_POLL_MAX_WAIT` defaults to 60s so the cap doesn't change
  unless the operator also raises the gateway proxy timeout in lockstep.
  Phase 1 documents that coupling in the env-var docstring.
- **In-memory store false-green CI risk** (decision-1 × decision-4 coupling):
  Phase 1 ships the condition-variable blocking *before* Phase 2 adds the
  typed wait, so all CI tests automatically exercise true blocking
  semantics — no `EGG_MESSAGE_STORE_BACKEND=memory` test path silently
  short-circuits.
- **QUESTION removal blast radius**: Phase 6 first deletes
  fixture-only call sites (3 test files), then removes the enum member.
  Backward-compat for in-flight pipelines is handled by serialising
  unknown types as `PROGRESS` in `MessageStore._deserialize` (already the
  fallback today).
- **HEARTBEAT bus volume**: agents emit on **state transitions only**, not
  on a wall-clock interval. Phase 3 includes a unit test that asserts a
  no-op transition (e.g. WORKING → WORKING) does not emit.

### Manual pre-merge / post-merge steps

Pre-merge: none — all changes land via the PR. Post-merge: operators who
want to raise `EGG_MESSAGE_POLL_MAX_WAIT` above 60s must also raise the
gateway HTTP_PROXY idle timeout to match (documented in Phase 8 docs).

## Phase plan

### Phase 1 — Backend message-store primitives

**Goal**: extend `MessageStore` so callers can long-block on a typed event,
respect an env-configurable `--wait` cap, and have the in-memory store
behave identically to Redis for blocking semantics.

Changes are **additive only** — existing methods keep their signatures.

### Phase 2 — HTTP route + CLI for typed wait

**Goal**: expose Phase 1's primitives via `GET /messages/wait` (server-side
XREAD BLOCK with type filter) and `egg-orch message wait --for TYPE
[--from ROLE] [--timeout N]`.

### Phase 3 — HEARTBEAT message type + emission helpers

**Goal**: add the `HEARTBEAT` enum member with a structured `state` field
(`WORKING | WAITING_ON_ROLE | PROPOSED | IDLE`) and helper functions agents
call on state transitions.

### Phase 4 — Replace consensus_wrapper shell sleep loop

**Goal**: rewrite `check_confirmed_and_wait` so it event-blocks on
`CONSENSUS_REACHED` (or `is_complete=True` polled state) via the new
primitive instead of `sleep` + N-iteration polling.

### Phase 5 — Agent prompt audit + canonical wait idiom

**Goal**: rewrite the producer + reviewer "STAY ALIVE" lifecycle blocks in
`pipelines.py` and the corresponding mission-rule line so agents are taught
the single canonical idiom and the explicit Don'ts (per decision-7).

### Phase 6 — Remove QUESTION message type (decision-5)

**Goal**: delete the `QUESTION` enum member, the only-in-tests fixture
references, and the references in inter-agent test files. Backward-compat
fallback in `_deserialize` covers in-flight pipelines.

### Phase 7 — Concurrent-integration tests + dedup regression

**Goal**: add an integration test that a synthetic agent reacts to
`CONSENSUS_REACHED` in <2s, plus a regression test for #1896's
`_existing_confirmed_for_role` dedup (HITL Q1 follow-up).

### Phase 8 — Documentation

**Goal**: create `docs/reference/agent-wait-patterns.md` with the canonical
idiom and the anti-patterns; add a "How to wait" section to
`docs/guides/concurrent-execution.md`; update mission.md if not already
touched in Phase 5; document the `EGG_MESSAGE_POLL_MAX_WAIT` /
HTTP_PROXY-idle-timeout coupling.
