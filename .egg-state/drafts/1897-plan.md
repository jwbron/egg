# Plan: Event-driven BRC wait primitives + heartbeats — Issue #1897

> Issue: #1897 | Phase: plan | Single PR

## Approach

This plan implements the **full Option C** scope confirmed at the refine
phase gate (decision-1 = "all five items"). All work lands in one branch
(`egg/issue-1897`) and one PR. Inside that PR the work is organised into
**nine phases** (Phase 1 → Phase 9) that should land as separate commits
so reviewers can step through them.

### Strategy rationale

The architecture splits along **three natural seams** that let us land
code in a safe order:

1. **Server-side primitives first, client-side consumers second.**
   Phases 1–2 add the new APIs (typed `XREAD BLOCK`, env-configurable
   cap, condition variable on the in-memory store, `GET /messages/wait`,
   `egg-orch message wait`) without changing any agent behaviour.
   Phase 5 (consensus_wrapper) and Phase 6 (agent prompts) are the
   consumers that *only become correct* once the primitives exist.
2. **Operational guard-rails before observable behaviour change.**
   Phase 4 sizes the WSGI worker pool for the new long-poll volume
   *before* Phase 6's prompt change tells agents to actually use it.
   Otherwise the rollout would saturate workers under load
   (RISK-3) and trigger a readiness-probe restart storm.
3. **Additive evolution before subtractive cleanup.** Phase 3 adds the
   `HEARTBEAT` message type and wires it into HealthMonitor. Phase 7
   removes the `QUESTION` type in a strict commit order
   (prompt → `BRC_HISTORY_TYPES` → tests → enum) so the test suite
   stays green at every commit boundary (RISK-10).

The HITL Q1 answer confirms PR #1896 already closes the
consensus-confirmed dedup symptom in the issue — Phase 8 adds a
regression test but no new production code is needed for that bullet
of the original report.

### How this plan answers the risk_analyst open questions

- **Q1 (defer QUESTION removal?)** — Keep in scope. decision-5 was
  resolved as "remove" at the refine gate. Phase 7 stages the work
  in the prompt-→-BRC_HISTORY-→-tests-→-enum order to keep CI green
  at every commit; the new follow-up issue for the structured
  REQUEST/REPLY peer-Q&A subsystem is filed as a *post-merge* manual
  step (see `manual_steps`).
- **Q2 (SSE vs XREAD for consensus_wrapper)** — **SSE.** The
  orchestrator already serves SSE at `orchestrator/sse.py` with a 15s
  HEARTBEAT_INTERVAL. SSE adds zero new runtime dependencies to the
  wrapper, works without Redis (load-bearing for local dev per Q2),
  and SIGTERM cleanly closes the curl socket (mitigates RISK-7).
- **Q3 (exit-code contract for `message wait`)** — Specified in
  TASK-2-2 below: **0** = matched, **1** = timeout, **2** = transient
  orchestrator/network error (5xx, ECONNRESET — safe to retry), **3**
  = permanent (bad pipeline id, auth failure, bad CLI args). Documented
  in `--help` text AND in `docs/reference/agent-wait-patterns.md`.
- **Q4 (WSGI worker model)** — Phase 4 adds an explicit task to switch
  the orchestrator Gunicorn config to an async worker class
  (`gevent`); raises `--timeout` to `2 × EGG_MESSAGE_POLL_MAX_WAIT`;
  moves the readiness probe to a dedicated lightweight endpoint; adds
  an in-flight-long-polls metric.
- **Q5 (warn on raised cap)** — Yes. TASK-2-3 adds a startup log line
  that prints the effective cap and emits a `warnings.warn` (and a
  WARNING-level log) when it exceeds 90s, naming the gateway Squid
  ConfigMap key the operator must also raise.

### Test strategy

Each backend change ships with unit tests in `orchestrator/tests/`. The
prompt-builder changes update locked-in fixtures in
`orchestrator/tests/test_pipeline_prompts.py`. The new `egg-orch message
wait` CLI gets contract tests in `sandbox/tests/`. Phase 8 wires up an
end-to-end concurrent-integration smoke test that asserts an agent
reacts to a `CONSENSUS_CONFIRMED` (final flavour) within 2 seconds
rather than the previous multi-minute window.

Manual verification: a reviewer should run a synthetic two-agent
pipeline locally with `EGG_MESSAGE_STORE_BACKEND=memory` and confirm
`egg-orch message wait --for CONSENSUS_CONFIRMED --timeout 30` actually
blocks (i.e. the in-memory condition variable works) and that no
`for i in 1..N; do …; done` or `sleep N &&` patterns appear in agent
output (grep the agent transcripts in `.egg-state/brc-history/`).

### Risk-mitigation cross-references

- **RISK-1, RISK-10 (QUESTION removal blast radius):** Phase 7
  enumerates every QUESTION reference (prompt preamble at
  `pipelines.py:6062-6074`, `BRC_HISTORY_TYPES` at `pipelines.py:4775`,
  `test_brc_history.py:816,871,893,974-985,1261-1281`,
  `test_concurrent_integration.py:165-174`,
  `gateway/tests/test_checkpoint_inter_agent.py`,
  `tests/shared/egg_contracts/test_checkpoint_cli_inter_agent.py:77,120`,
  `sandbox/tests/test_brc_cli_args.py`) and stages them as separate
  commits in dependency order. The prompt change includes a forward
  pointer to a follow-up issue for the structured REQUEST/REPLY
  subsystem.
- **RISK-2 (HEARTBEAT vs PROGRESS-heartbeat collision):** Phase 3
  adds an explicit `MESSAGE_SENT` subscription in
  `health_monitor.py` that resets `last_heartbeat` when
  `message_type == 'HEARTBEAT'`. The PROGRESS-heartbeat path is
  **not removed** in this PR — it remains the legacy path with a
  TODO comment pointing at a follow-up issue. The HEARTBEAT body
  schema (`{state, waiting_on?, since?}`) is validated server-side
  in `routes/messages.py` so a malformed HEARTBEAT is rejected.
- **RISK-3 (WSGI worker starvation):** Phase 4 switches Gunicorn to
  the `gevent` async worker class, raises `--timeout` to
  `2 × EGG_MESSAGE_POLL_MAX_WAIT`, moves the readiness probe to a
  dedicated `/healthz` endpoint that does not touch the message
  store, and exports an `egg_inflight_long_polls` Prometheus
  counter.
- **RISK-4 (gateway Squid timeout coupling):** Phase 2 adds a
  startup log line + `warnings.warn` when
  `EGG_MESSAGE_POLL_MAX_WAIT > 90`; Phase 9 docs include an explicit
  "if you raise this cap, you MUST also raise the gateway Squid
  ConfigMap key" block; Phase 8 adds a deliberately-misconfigured
  integration test that asserts the resulting 504 is named.
- **RISK-5 (cv blocking + clear() race):** Phase 1 specifies a
  per-pipeline `threading.Condition` (not global). `MessageStore.clear()`
  must call `cv.notify_all()` after popping the list. Blocking-read
  loops re-check `pipeline_id in self._messages` after each wake-up
  and return an empty list if the pipeline is gone. The silent
  non-blocking fallback at `routes/messages.py:181-184` is **removed**
  so non-blocking misconfiguration fails loudly in CI.
- **RISK-6, RISK-7 (consensus_wrapper SIGTERM):** Phase 5 uses
  **SSE** (curl `--no-buffer` against the existing
  `orchestrator/sse.py` endpoint) instead of XREAD BLOCK. Curl honours
  SIGTERM via standard socket close. A new sandbox test spawns the
  wrapper, sends SIGTERM mid-block, and asserts exit within the
  graceful-shutdown grace period. The wrapper falls back to the
  current shell sleep loop if the SSE endpoint is unavailable
  (preserves zero-Redis local-dev path).
- **RISK-9 (exit-code contract):** TASK-2-2 codifies 0/1/2/3
  semantics; TASK-6-1 wires the canonical idiom to that contract:
  `while true; do egg-orch message wait --for TYPE; rc=$?; case $rc
  in 0|2) continue;; 1) break;; *) exit 1;; esac; done`. The
  `egg-orch message wait-loop` convenience command in TASK-2-4
  encapsulates this so the prompt can show a one-liner.
- **RISK-12 (scope creep / reviewer fatigue):** Each phase corresponds
  to one commit on the PR branch; the PR description explicitly calls
  out the four HIGH-severity risks (1, 2, 3, 5) for the reviewer to
  spot-check.

### Manual pre-merge / post-merge steps

Pre-merge: none — all changes land via the PR.

Post-merge:

- Operators who want to raise `EGG_MESSAGE_POLL_MAX_WAIT` above 60s
  must raise the gateway Squid idle timeout ConfigMap key in
  `k8s/base/gateway-deployment.yaml` in lockstep, or long-poll
  requests will return 504 (this is documented in Phase 9 docs and
  asserted by the deliberately-misconfigured integration test).
- File a follow-up issue for the structured REQUEST/REPLY peer-Q&A
  subsystem (decision-5 resolution) and reference it from
  `pipelines.py` where the QUESTION example used to live.
- File a follow-up issue to deprecate the legacy PROGRESS-heartbeat
  path in `health_monitor.py:248-257` once HEARTBEAT adoption is
  100%.

## Phase plan

### Phase 1 — Backend message-store primitives

**Goal**: extend `MessageStore` so callers can long-block on a typed
event, respect an env-configurable `--wait` cap, and have the in-memory
store behave identically to Redis for blocking semantics — including
clean wake-up on `clear()`.

### Phase 2 — HTTP route + CLI for typed wait

**Goal**: expose Phase 1's primitives via `GET /messages/wait`
(server-side blocking with type filter) and `egg-orch message wait
--for TYPE [--from ROLE] [--timeout N]`. Codify the exit-code contract
and emit the gateway-coupling warning at startup.

### Phase 3 — HEARTBEAT message type + HealthMonitor wiring

**Goal**: add the `HEARTBEAT` enum member with a structured `state`
field; wire `health_monitor.py` so HEARTBEAT also resets
`last_heartbeat`; validate body schema server-side.

### Phase 4 — WSGI worker pool sizing for long polls

**Goal**: switch the orchestrator Gunicorn config to async workers,
raise the per-request timeout, move the readiness probe off the
worker pool, and export an in-flight long-poll counter.

### Phase 5 — consensus_wrapper SSE rewrite

**Goal**: rewrite `consensus_wrapper.py:322-351` to event-block via
SSE on the existing orchestrator `/api/v1/pipelines/{id}/events`
endpoint instead of sleep-looping; preserve fallback to shell sleep
loop if SSE unavailable.

### Phase 6 — Agent prompt audit + canonical idiom + Don'ts

**Goal**: rewrite the producer + reviewer "STAY ALIVE" lifecycle
blocks in `pipelines.py` (lines 5959, 6020) and the corresponding
mission rule line so agents are taught the single canonical idiom
keyed off the new exit-code contract, plus the explicit Don'ts.

### Phase 7 — Remove QUESTION message type (in safe commit order)

**Goal**: delete the `QUESTION` enum member following the
prompt-→-`BRC_HISTORY_TYPES`-→-tests-→-enum dependency order so the
test suite is green at every commit boundary. Forward-link to the
follow-up REQUEST/REPLY issue from the prompt.

### Phase 8 — Tests + dedup regression + 504 mode test

**Goal**: integration test that the new primitive delivers sub-2s
reaction time; regression test for PR #1896's
`_existing_confirmed_for_role` dedup (HITL Q1); a deliberately
misconfigured-cap test that asserts the gateway 504 (RISK-4 named
failure mode).

### Phase 9 — Documentation

**Goal**: create `docs/reference/agent-wait-patterns.md` with the
canonical idiom, the four anti-patterns, the exit-code contract, the
HEARTBEAT schema, and the explicit
`EGG_MESSAGE_POLL_MAX_WAIT` ↔ Squid-timeout coupling block. Add a
"How to wait" section to `docs/guides/concurrent-execution.md`.
