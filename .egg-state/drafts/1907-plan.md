# Plan: Fix #1907 — Gateway retry/graceful-close on upstream ECONNRESET

## Summary

Harden `gateway/gateway.py:proxy_anthropic_messages()` against upstream TCP resets on streaming `/v1/messages` requests by adding two complementary defenses: **(A)** a bounded retry when `httpx.ReadError` / `httpx.RemoteProtocolError` fires *before* any byte has been yielded downstream (covers stale keepalive connections and early edge resets — agent never sees the blip); **(B)** a synthetic terminating SSE `event: error` envelope when the reset fires *after* bytes have flowed (agent sees a clean error instead of a truncated stream + `aclose()` bug). Retry is only safe pre-stream because mid-stream re-issue would produce duplicate partial output with no resume semantics.

**Root cause**: The streaming branch of `proxy_anthropic_messages` catches only `ConnectError` / `TimeoutException` / generic `Exception` around the synchronous `client.send(...)` call. Exceptions raised inside the `generate()` generator's `upstream.iter_bytes()` loop fire after `Response(...)` has already returned, so they bypass the handler, bubble up to waitress as an uncaught exception, and leave the downstream SSE stream truncated with no terminating event. The pool also hands out stale keepalive connections that can immediately RST on first read.

**Risks / edge cases**:
- Retry must only run while no byte has been yielded downstream — once the agent has received partial output, re-issuing the request would produce duplicate work (Anthropic has no resume tokens).
- Retries must be bounded (max 1 retry with short backoff) to avoid amplifying load during a real upstream outage.
- The `_SSEAccumulator`'s `finally`-block transcript flush must handle a partially-parsed stream without raising; verify current behavior.
- Must not touch non-streaming or `/v1/messages/count_tokens` paths — they already handle errors correctly.
- Synthetic SSE event format must match Anthropic's `event: error` convention so the SDK routes it through its normal error path instead of the connection-closed fatal path.

## Implementation

### Phase 1: Implement

Add (A) pre-stream retry and (B) mid-stream synthetic error envelope to the gateway's streaming `/v1/messages` proxy, plus regression tests.

**Tasks**:
1. **[task-1-1]** In `gateway/gateway.py:proxy_anthropic_messages()` (~line 5241), wrap the streaming branch's `client.send(http_request, stream=True)` + first-chunk peek in a bounded retry loop (max 1 retry) that catches `httpx.ReadError` and `httpx.RemoteProtocolError`. Pre-read the first chunk eagerly before returning the Flask `Response` so early resets surface inside the retry-safe window; re-prepend the peeked chunk onto the downstream stream. On retry, close the failed upstream and rebuild the request from the original headers + body. Log retries at INFO with a structured `upstream_reset_retry` event. Exhausted retries fall through to the existing 502 `api_error` handler. Acceptance: `ac-1`.
2. **[task-1-2]** In the `generate()` generator (~line 5270), wrap the `for chunk in upstream.iter_bytes():` loop in `try: … except (httpx.ReadError, httpx.RemoteProtocolError) as e:`. On error, yield a terminating SSE payload `event: error\ndata: {"type":"error","error":{"type":"api_error","message":"upstream connection reset"}}\n\n` and return. Keep the existing `finally` block flushing partial transcript capture via `_capture_streaming_response`. Log a WARN with `upstream_reset_midstream` plus bytes-transferred context. Acceptance: `ac-2`.
3. **[task-1-3]** Add `gateway/tests/test_proxy_anthropic_stream.py` covering: (a) upstream `ReadError` before any bytes → retried once → succeeds transparently (downstream sees only the retry's bytes, no error); (b) upstream `ReadError` persists across retries → returns 502 JSON error payload; (c) upstream `ReadError` after bytes have flowed → downstream stream ends with a well-formed SSE `event: error` payload, no uncaught exception reaches waitress; (d) transcript buffer's `_capture_streaming_response` still runs with partial accumulator data on mid-stream error. Use a mock `httpx.Client` injected via `get_anthropic_client()` with a transport that yields configurable bytes then raises. Acceptance: `ac-3` plus regression coverage for `ac-1` / `ac-2`.
