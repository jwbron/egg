# Plan: Improve the Generalized Reviewer (issue #1965)

> Pipeline `issue-1965` · Phase `plan` · Single-PR scope.

## Context

`reviewer_code` is currently confirming consensus on large diffs while
the GHA `egg-reviewer` finds blocking issues that the BRC reviewer
missed (PR #1964 shipped a broken `sandbox/scripts/jira` symlink and a
`^project$` info-disclosure bypass). The remediation is **A + B
(small)** from the issue body:

- **A** — let `reviewer_code` fan out into Claude Agent SDK `Task`
  subagents on large diffs so every changed file is read carefully,
  partitioned along the implement-phase task list.
- **B** — introduce two new **ADVISORY** specialised reviewers,
  `reviewer_security` and `reviewer_concurrency`, with their own
  dedicated criteria files. ADVISORY-by-default day 1 so they cannot
  deadlock consensus until severity-tagged NACKs land in #1997.

Everything else (Option D pre-PR gate, severity rubric, conditional-ACK
policy, `babysit_pr` fan-out, GHA reviewer code changes,
static-analyser integration, severity-tagged NACK signalling) is
**out of scope** and tracked elsewhere (#1997, #1998, #1999) — the
plan-phase reviewer should NACK any task that drifts there.

## Approach

The change ships in a single PR composed of five self-contained,
ordered phases. Each phase compiles, tests, and lints on its own so
the diff stays bisectable and `reviewer_code`'s own subagent fan-out
can match phases 1:1 to natural partitions during its review.

### Pre-resolved decisions baked into the plan

| Pitfall / question | Resolution |
|---|---|
| Pitfall 2 (threshold metrics path) | **Option 2B** — reviewer self-gates: prompt instructs it to run `git diff --numstat` and decide. No orchestrator-side numstat plumbing. |
| Pitfall 3 (implement-phase task list path) | **Option 3B** — reviewer calls `mcp__sdlc__show_contract` itself and self-extracts `phases.implement.tasks[]`. Empty list ⇒ skip fan-out. No `contract` parameter added to `_build_review_prompt()`. |
| Threshold composition | **OR** — fan out when files > 10 OR loc > 500. |
| Subagent diff scope | Subagent re-runs `git diff` itself and filters by path glob to its assigned partition. Parent passes only the partition spec. |
| New criteria-file inheritance | **Inherit** — each new file opens with an explicit "Inherits from `code-review-criteria.md`; only lens-specific rules below override or extend it" header. |
| Per-pipeline parallelism config site | `phase_configs.implement.reviewer_code.parallel` field on the contract; default `true`. |
| Replay-test execution mode | **Both** — CI-unconditional prompt-text asserts always run; live-LLM replay gated by `RUN_REVIEWER_REPLAY=1`. |

### Pitfall guards baked into the plan

The previous plan-attempt was NACKed for missing these. They are
now explicit verification tasks, not coding tasks:

1. **No redundant role mapping.** The single line at
   `orchestrator/routes/pipelines.py:8317` already transforms
   `reviewer_security` → `security` and `reviewer_concurrency` →
   `concurrency`. Phase 2 adds a unit test asserting this and forbids
   any new dict / if-elif chain.
2. **No attestation models for the new reviewers** unless day-1 ACKs
   carry attestation payloads. They will not — same shape as
   `reviewer_refine`, `reviewer_agent_design`, `reviewer_plan`, which
   ship modelless and work fine because `validate_attestation` is
   conditional on `review.attestation` being truthy. Phase 1 adds a
   test asserting `REVIEWER_ATTESTATION_MODELS` does *not* register
   either new role.

### Dependency ordering

```
Phase 1 ─┐
         ├─► Phase 2 ─┐
         │           ├─► Phase 4 ─► Phase 5
         └─ Phase 3 ─┘
```

Phases 2 and 3 can be developed in parallel after phase 1 lands, but
phase 4 depends on both being merged because it references both the
new criteria files (via the dispatcher) and the parallelism knob (via
the prompt builder). Phase 5 depends on phase 4 because it asserts
prompt-text introduced there.

Within each phase, the executor-role split is:
- **coder** owns Python production code (`shared/egg_contracts/`,
  `orchestrator/`).
- **documenter** owns markdown — new criteria files,
  `REVIEWER-SYNC.md` updates, and `docs/` pages.
- **tester** owns `integration_tests/` and any orchestrator/ unit
  tests that verify prompt text or graph wiring.

### Manual verification (reviewer's PR walk)

- Trigger an SDLC pipeline on a small (< 10 file) issue and confirm
  `reviewer_code` does *not* spawn subagents.
- Trigger an SDLC pipeline on a large (> 10 file) issue and confirm
  `reviewer_code` does spawn subagents partitioned along
  `phases.implement.tasks[]`.
- Override `phase_configs.implement.reviewer_code.parallel = false`
  on a contract and confirm the fan-out instructions switch from
  parallel to sequential in the resulting prompt.
- Pick any pipeline-produced PR and confirm `reviewer_security` /
  `reviewer_concurrency` show up in `egg-orch consensus status` as
  ADVISORY edges, NACKs from them are recorded but do not block
  CONSENSUS_CONFIRMED.

## Manual Steps

**Pre-merge**: none. The new ADVISORY reviewers cannot deadlock
existing pipelines, the new criteria files have inline fallbacks if
shared loading fails, and the parallelism knob is fully optional.

**Post-merge**: monitor the GHA blocking-issue trend on the next 5–10
pipeline-produced PRs. If the trend does not decline, file a
follow-up issue revisiting partition strategy / threshold tuning. No
config changes, migrations, or deployments required.

## Risks (cross-reference for risk_analyst)

The risk_analyst owns the full risk register; the plan calls out
three implementation-shape risks the task list must guard against:

1. **Reviewer subagent recursion.** A `reviewer_code` subagent could
   itself try to spawn subagents. Phase 4 prompt text must explicitly
   forbid recursion. Tested by the regression-replay's
   prompt-text asserts.
2. **Empty implement-phase tasks.** If the contract has no
   `phases.implement.tasks[]` (custom-phase invocation, contractless
   `babysit_pr`), reviewer_code must fall back to "review yourself
   without fan-out". Phase 4 prompt-text and phase 5 prompt-asserts
   must cover this.
3. **Schema drift on `phase_configs`.** Old contracts without the
   new field must continue to pipeline without error. Phase 3 unit
   tests assert this.
