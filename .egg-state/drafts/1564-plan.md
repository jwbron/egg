# Plan: Fix consensus race condition on container exit

## Summary

Fix the race condition where `_run_concurrent_phase` returns failure when all containers exit with non-zero codes, without rechecking consensus. The root cause is that step 5 ("all containers exited") returns `exit_code=1` immediately when `has_failures` is true, without a final consensus check. Additionally, the consensus wrapper's `check_agent_confirmed_with_fallback` only falls back to the message bus when the tracker is empty — after a withdrawal/re-proposal cascade, the tracker is populated but stale, so the fallback never triggers.

**Risks / edge cases**: The extra consensus check in the terminal path adds one API call but is negligible. The wrapper's expanded fallback is expensive (pulls all messages) but only runs once per agent exit. Must ensure genuine failures (no consensus messages) still propagate correctly.

## Implementation

### Phase 1: Implement

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py:4896-4900`, add a final `executor.check_consensus()` call before returning `exit_code=1` when all containers have exited with failures. If consensus is complete, call `_update_agents_complete()`, `_stop_running_containers()`, recover pipeline from FAILED status if needed (same logic as step 2), and return `0`. This closes the race window where consensus completes between step 2 and step 5. Acceptance: When all containers exit with non-zero codes but `check_consensus()` returns `is_complete: True`, `_run_concurrent_phase` returns exit code 0.

2. **[task-1-2]** In `orchestrator/consensus_wrapper.py:148-186`, modify `check_agent_confirmed_with_fallback` to also check the message bus when the tracker shows the agent as NOT confirmed (not just when the tracker agents map is empty). After the withdrawal/re-proposal cascade, the tracker is populated but stale — the current fallback never triggers. Add a second condition: if `confirmed` is `"False"` and the tracker is non-empty, still check the message bus for the agent's own `CONSENSUS_CONFIRMED` message. Acceptance: Wrapper exits cleanly (code 0) when tracker shows agent not confirmed but message bus has agent's CONSENSUS_CONFIRMED.

3. **[task-1-3]** Add test in `orchestrator/tests/test_consensus_complete_with_failures.py` for the race condition: all containers exit with code 1, but `check_consensus()` returns `is_complete: False` on the first call and `is_complete: True` on the second call (simulating consensus completing between the loop's step 2 and step 5). Verify `_run_concurrent_phase` returns exit code 0. Acceptance: Test passes and covers the race condition scenario.

4. **[task-1-4]** Add test for the improved wrapper fallback: tracker is non-empty but shows agent as not confirmed, message bus has a `CONSENSUS_CONFIRMED` from the agent — verify the function returns `"True"`. Acceptance: Test passes and covers the stale-tracker fallback scenario.
