# Plan: Add phase management MCP tools

## Summary

Add four MCP tools (`advance_phase`, `start_phase`, `complete_phase`, `populate_contract`) that wrap existing REST endpoints in `routes/phases.py`. Three endpoints already exist; `populate_contract` needs a new REST endpoint wrapping the internal `_populate_contract_from_plan()` function. The `advance_phase` handler also needs to stop running phase containers when `force=true` before advancing, addressing the cascading failure described in #1570. The MCP server auto-discovers tools from `PIPELINE_TOOLS`, so only `mcp_tools.py` and `routes/phases.py` need changes.

**Risks / edge cases**: The force-advance container stop must happen before the phase transition to avoid SIGTERM cascading into the new phase. The `populate_contract` endpoint needs worktree path resolution since contracts live in per-pipeline worktrees.

## Implementation

### Phase 1: Implement

Add 4 MCP tool definitions, their handler methods, a new REST endpoint for populate_contract, and tests.

**Tasks**:
1. **[task-1-1]** In `orchestrator/mcp_tools.py`, add 4 tool schema dicts to `PIPELINE_TOOLS` for `advance_phase` (params: `task_id`, `target_phase`, `force`), `start_phase` (params: `task_id`), `complete_phase` (params: `task_id`, optional `artifacts`), and `populate_contract` (params: `task_id`). Acceptance: all 4 tools appear in `PIPELINE_TOOLS` with correct input schemas.
2. **[task-1-2]** In `orchestrator/mcp_tools.py:PipelineToolHandler`, add `_handle_advance_phase`, `_handle_start_phase`, `_handle_complete_phase`, and `_handle_populate_contract` methods + register them in the `handlers` dict. `_handle_advance_phase` with `force=true` should first list running containers via `GET /api/v1/pipelines/{id}/containers`, then stop each running one via `POST /api/v1/pipelines/{id}/containers/{cid}/stop`, then call `POST /api/v1/pipelines/{id}/phase` with the target_phase and force params. `_handle_start_phase` calls `POST /api/v1/pipelines/{id}/phase/start`. `_handle_complete_phase` calls `POST /api/v1/pipelines/{id}/phase/complete` with optional artifacts. `_handle_populate_contract` calls the new `POST /api/v1/pipelines/{id}/phase/populate-contract` endpoint. Acceptance: each handler proxies correctly to its REST endpoint.
3. **[task-1-3]** In `orchestrator/routes/phases.py`, add a `POST /<pipeline_id>/phase/populate-contract` endpoint that loads the pipeline from the state store, resolves the worktree path via `resolve_worktree_path()`, and calls `_populate_contract_from_plan()` (imported from `routes.pipelines`) with the resolved path, pipeline_id, pipeline mode, and issue_number. Returns success with phase/task counts or appropriate error. Acceptance: endpoint exists, resolves worktree correctly, calls the populate function.
4. **[task-1-4]** In `orchestrator/tests/test_mcp_tools.py`, add test classes for all 4 new handlers: `TestAdvancePhase` (success, force with container stop, invalid phase), `TestStartPhase` (success, already running), `TestCompletePhase` (success, with artifacts), `TestPopulateContract` (success, not found). Acceptance: all tests pass.
