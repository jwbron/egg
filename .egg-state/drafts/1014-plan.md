# Implementation Plan: PR-based workflows — babysit-pr + PR-seeded coordinator

> Issue: #1014 | Phase: plan | Single PR

## Approach

This plan implements **Option B** from the analysis: a standalone `babysit-pr` loop module with future coordinator integration. The work ships the babysit-pr CLI command that monitors a PR through its review/fix lifecycle — resolving conflicts, fixing CI failures, running code reviews, and addressing feedback — looping until the PR merges or a timeout is reached.

The PR-seeded coordinator session (workflow 1 in the issue) is **deferred** since it depends on #1028 (coordinator, not yet implemented). This plan focuses on delivering the standalone babysit-pr loop, which can later be consumed by the coordinator as a sub-task.

### Key Architectural Decisions

1. **Module location**: `shared/egg_babysit/` — a new shared package alongside `egg_agent`, `egg_orchestrator`, etc.
2. **Agent sessions**: Short-lived per-cycle containers spawned via orchestrator's `ContainerSpawner`. Each fix/review step gets a fresh agent session to stay within context limits.
3. **Orchestrator registration**: The standalone CLI registers a pipeline (`pr-{N}`) with mode `babysit` for observability, checkpointing, and health monitoring.
4. **Gateway compatibility**: The gateway already allows pushing to PR branches with open PRs by the bot or trusted users — no gateway changes needed for core functionality.
5. **Prompt consumption**: Thin Python wrappers call existing bash prompt builders via subprocess (minimal change, single source of truth).
6. **State tracking**: Loop iteration state persisted via orchestrator pipeline state (StateStore), enabling crash recovery.

### Scope Boundaries

**In scope**: babysit-pr loop module, CLI command, orchestrator pipeline mode extension, PR state polling, CI check monitoring, fixer/reviewer agent spawning, HITL escalation, tests.

**Out of scope**: PR-seeded coordinator session (#1028 dependency), GitHub Actions changes, gateway policy changes for non-trusted-user PRs, rich terminal UX (v1 uses minimal status output).

## Phase 1: Core Loop Module and PR State Polling

Build the foundational `shared/egg_babysit/` package with PR state polling, CI check monitoring, and the main loop skeleton.

### Rationale

The loop module is the central abstraction. It must be designed as a standalone, testable module that both the CLI and future coordinator can consume. PR state polling and CI monitoring are prerequisites for every subsequent step.

### Tasks

1. **Create `shared/egg_babysit/` package structure** — `__init__.py`, `loop.py`, `pr_state.py`, `config.py`, `types.py`. Define the `BabysitConfig` dataclass (PR number, repo, timeout, max iterations, max retries per job, poll interval). Define `PRState` dataclass (merge status, mergeable state, CI check results, review status, head SHA).

2. **Implement PR state poller** (`pr_state.py`) — Uses `gh` CLI (via subprocess through gateway) to fetch PR metadata, CI check status, review state, and merge conflict status. Returns typed `PRState`. Handles GitHub API errors and rate limiting gracefully. Polls via `gh pr view` and `gh pr checks`.

3. **Implement main loop skeleton** (`loop.py`) — The core `babysit()` async function that drives the review/fix cycle: check conflicts → wait CI → fix failures → wait CI → review → address feedback → loop. Each step is a method that can be overridden (for coordinator integration later). Loop exits on: PR merged, timeout, max iterations, or HITL escalation. Emits progress via `egg-orch progress emit`.

4. **Implement CI check waiter** — Polls CI status at configurable intervals (default 30s). Streams status updates to stdout. Detects completion (all checks pass, any check fails, or checks stale). Returns structured result with failed job names and log URLs.

5. **Add unit tests** — Test PR state parsing, loop state transitions, CI waiter logic, timeout/exit conditions. Mock `gh` CLI calls. Target: `shared/tests/test_egg_babysit/`.

### Acceptance Criteria
- `shared/egg_babysit/` package exists with `loop.py`, `pr_state.py`, `config.py`, `types.py`
- `PRState` correctly parses `gh pr view --json` and `gh pr checks --json` output
- Main loop skeleton runs, detects PR merged → exits successfully
- CI waiter polls and detects pass/fail/pending states
- Unit tests pass for all state parsing and loop transitions

## Phase 2: Fixer and Reviewer Agent Integration

Wire up the fixer and reviewer agent sessions that the loop spawns for each cycle step.

### Rationale

The loop needs to spawn short-lived agent containers for conflict resolution, check fixing, code review, and feedback addressing. This phase builds the agent session management and prompt construction.

### Tasks

6. **Implement prompt builder wrappers** (`prompts.py`) — Python functions that call `action/build-check-fixer-prompt.sh` and `action/build-review-prompt.sh` via subprocess. Accept PR number, repo, failed jobs, and return constructed prompt strings. Load `shared/check-fixers.yml` for non-LLM fix commands and retry config.

7. **Implement fixer agent spawner** (`fixer.py`) — Spawns a short-lived fixer agent container via orchestrator's `ContainerSpawner`. Injects prompt (conflict resolution, check fix, or feedback addressing depending on cycle step). Configures read-write access to PR branch. Waits for agent completion and captures commit SHA from output. Handles agent failure (timeout, crash) with retry logic.

8. **Implement reviewer agent spawner** (`reviewer.py`) — Spawns a short-lived reviewer agent container. Injects review prompt built from PR diff and `shared/prompts/code-review-criteria.md`. Configures read-only mode (no push capability). Reviewer posts GitHub review via `gh pr review`. Captures review verdict (approve, request changes, comment).

9. **Implement conflict resolver step** — Detects `mergeable_state: dirty` from PR state. Spawns fixer with conflict resolution prompt. Verifies conflicts resolved after push. Handles unresolvable conflicts (escalate to HITL).

10. **Implement check fixer step** — Reads failed CI jobs from PR state. For each failed job: try non-LLM fix first (per `check-fixers.yml`), then spawn LLM fixer agent if non-LLM fails. Tracks retry count per job. Escalates after max retries. Uses `<!-- egg-autofix-state -->` markers for retry tracking (consistent with existing GitHub Actions behavior).

11. **Implement review and feedback steps** — After CI passes: spawn reviewer to post GitHub review. If reviewer requests changes: spawn fixer to address feedback. Cap feedback rounds (default 5, matching existing `on-review-feedback.yml` behavior). Use `<!-- egg-automated-review -->` markers for review tracking.

12. **Add integration tests** — Test fixer/reviewer spawning with mocked container spawner. Test prompt builder wrapper output. Test retry and escalation logic. Test marker-based state tracking.

### Acceptance Criteria
- Prompt builders successfully call bash scripts and return valid prompts
- Fixer agent spawns, receives prompt, and its commit SHA is captured
- Reviewer agent spawns in read-only mode and posts review
- Conflict resolution detects dirty state and spawns appropriate fixer
- Check fixer applies non-LLM fixes first, falls back to LLM agent
- Retry tracking works via markers; escalation triggers after max retries
- Feedback loop caps at configured max rounds
- Integration tests pass with mocked containers

## Phase 3: Orchestrator Pipeline Mode and CLI Command

Extend the orchestrator to support `babysit` pipeline mode and build the CLI entry point.

### Rationale

The CLI command is the user-facing interface. The orchestrator pipeline mode provides observability, state persistence, and health monitoring for the running loop.

### Tasks

13. **Extend orchestrator pipeline model** — Add `mode` field to `Pipeline` (default `"issue"`, new value `"babysit"`). Add `pr_number` field. Support pipeline ID format `pr-{N}`. Update `create_pipeline()` in routes to accept mode and pr_number. Update state store serialization.

14. **Add babysit pipeline lifecycle** — When a pipeline with `mode: "babysit"` is created and started, the orchestrator runs the babysit loop module instead of the standard phase progression. Pipeline state tracks loop iteration, current step (conflict/ci-wait/fix/review/feedback), and per-job retry counts. Health monitoring via OverseerMonitor detects stalled loops.

15. **Build CLI command** (`shared/egg_babysit/cli.py` + entry point) — `egg babysit-pr <PR> [--repo OWNER/REPO] [--timeout DURATION] [--max-iterations N]`. Creates orchestrator pipeline, starts babysit loop, streams status to terminal. Minimal v1 UX: periodic status line updates (current step, iteration count, elapsed time). Register as console_scripts entry point in `shared/pyproject.toml`.

16. **Implement HITL escalation** — When the loop hits an unrecoverable state (max retries exhausted, unresolvable conflict, repeated failures), create a HITL decision via orchestrator's `DecisionQueue`. Post a GitHub comment on the PR explaining the blocker. Optionally notify via Slack (`notifications.slack_notify`). Loop pauses until decision is resolved, then resumes or exits.

17. **Implement graceful shutdown** — Handle SIGTERM/SIGINT cleanly. Save loop state to pipeline. Log final status. Support resume from saved state on restart (crash recovery).

18. **Add end-to-end tests** — Test full CLI invocation with mocked GitHub API and container spawner. Test pipeline creation with babysit mode. Test HITL escalation flow. Test graceful shutdown and resume.

### Acceptance Criteria
- `egg babysit-pr <PR>` command runs and creates a `pr-{N}` pipeline
- Orchestrator pipeline model supports `mode: "babysit"` and `pr_number`
- Loop state persisted in pipeline state; crash recovery works
- HITL escalation creates decision and posts GitHub comment
- Graceful shutdown saves state; resume picks up from saved state
- Status output shows current step and iteration count
- End-to-end tests pass

## Phase 4: Gateway Validation, Documentation, and Polish

Validate gateway compatibility, add documentation, and polish edge cases.

### Rationale

Gateway branch enforcement must be validated end-to-end. Documentation ensures the feature is discoverable and usable. Edge case handling (concurrent pushes, rate limits, stale reviews) improves reliability.

### Tasks

19. **Validate gateway branch policy** — Write integration test confirming the gateway allows pushing to a PR branch when the bot has an open PR or the author is trusted. Document the trust requirements in the CLI help text. Verify `GATEWAY_TRUSTED_USERS` / `TRUSTED_BRANCH_OWNERS` configuration works for babysit scenarios.

20. **Handle concurrent push detection** — Detect when the PR head SHA changes unexpectedly (another user pushed). Re-fetch PR state and restart the current cycle step. Log a warning. Avoid force-pushing over human work.

21. **Implement rate limit handling** — Track GitHub API call frequency. Back off when approaching rate limits (X-RateLimit-Remaining header). Log rate limit warnings. Default poll interval (30s) should keep well under 5000/hr limit.

22. **Add inline documentation** — Module docstrings, function docstrings, and type hints throughout `shared/egg_babysit/`. Add `shared/egg_babysit/README.md` with usage examples, configuration reference, and architecture overview.

23. **Update shared/pyproject.toml** — Add `egg_babysit` package, console_scripts entry point, and any new dependencies.

### Acceptance Criteria
- Gateway integration test passes for bot-authored and trusted-user PRs
- Concurrent push detection re-fetches state without data loss
- Rate limit backoff prevents 403 errors under sustained polling
- All public functions have docstrings and type hints
- `egg babysit-pr --help` shows usage and options
- `shared/pyproject.toml` updated with new package and entry point

## Test Strategy

### Unit Tests (`shared/tests/test_egg_babysit/`)
- PR state parsing from `gh` CLI JSON output
- Loop state machine transitions (each step → next step, exit conditions)
- CI waiter polling logic (pass/fail/pending/timeout)
- Config validation (timeout, max iterations, poll interval)
- Prompt builder wrapper output validation
- Retry counting and escalation triggers

### Integration Tests (`integration_tests/test_babysit_pr/`)
- Full loop with mocked GitHub API (simulated PR lifecycle)
- Pipeline creation and state persistence (babysit mode)
- Container spawner integration (mocked Docker)
- HITL escalation flow (decision creation → resolution → resume)
- Graceful shutdown and resume from checkpoint

### Manual Testing
- Run `egg babysit-pr` against a real test PR in a sandbox repo
- Verify CI failure detection → fix → re-run cycle
- Verify review posting and feedback addressing
- Verify timeout and HITL escalation behavior

### Existing Test Compatibility
- Run `make test` to verify no regressions in existing test suite
- Run `make lint` to verify code quality

## Dependency Ordering

```
Phase 1 (core module, PR state, loop skeleton)
  └── Phase 2 (fixer/reviewer agents, prompt builders)
       └── Phase 3 (orchestrator mode, CLI, HITL escalation)
            └── Phase 4 (gateway validation, docs, polish)
```

Phases are strictly sequential — each builds on the previous. Within each phase, tasks can be worked in the listed order as they have logical dependencies (e.g., TASK-1-1 package structure before TASK-1-2 PR state poller).

## Risk Mitigations

| Risk | Mitigation |
|------|------------|
| #1028 coordinator not ready | babysit-pr ships standalone; module interface designed for future coordinator consumption |
| Context window exhaustion | Short-lived agent sessions per cycle step; no persistent Claude conversation |
| GitHub API rate limits | Configurable poll interval (default 30s); rate limit header monitoring; backoff |
| Gateway rejects push to PR branch | Validated in Phase 4; requires bot authorship or trusted user config |
| Infinite loop / runaway costs | Max iterations cap (default 10); per-job retry cap (from check-fixers.yml); timeout (default 4h) |
| Concurrent pushes by PR author | Head SHA change detection; re-fetch state; never force-push |
| Prompt injection via PR branch | Prompts built from trusted main branch checkout (existing pattern) |
