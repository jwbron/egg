## slice-C — PR C: Supervision hardening

*Live supervision behavior — highest-risk slice; heavy test coverage over classification +
loop-guard + landed-slice preservation. cq-1 is resolved (§ HITL).*

- **task-C-1** — Add a **transient rate-limit / cap-wall classification distinct from
  `abnormal`**. Detect the all-producers `agent-invocation-failure` streak signature whose
  underlying error carries the throttling wording `auth_errors.py` deliberately excludes
  (bare 429 / "rate limit" / "overloaded") and classify it as transient rate-limit, not into
  the `agent-invocation-fail-streak` halt. Reuse/extend the `auth_errors` throttling
  vocabulary rather than duplicating regexes; **do not widen `EX_AUTH_FATAL`**. *AC-C1, AC-C6 (partial).*
- **task-C-2** — On that classification, perform a **windowed paced retry** across the rolling
  cap window (hours-scale, **not** the 30s cap) without hammering: parse the reset time from
  the error when present to pace, else bounded backoff. Per resolved **cq-1**: **NO hard
  wall-clock ceiling** (retry until the cap lifts) **BUT emit an `OVERSEER_ALERT` once the
  wait crosses a threshold** so an attended operator is informed while auto-recovery
  continues. *AC-C2, AC-C5.*
- **task-C-3** — Use a **`restart_phase`-equivalent that preserves landed slices** —
  completed slice work is **not** discarded on recovery. Reuse existing restart_phase /
  slice-completion state rather than a cold restart. *AC-C3.*
- **task-C-4** — **Deterministic-loop guard**: if a restart reproduces the **identical failure
  signature at the same phase-progression point** (no state advance), **stop and escalate**
  (HITL/halt) instead of looping; if the restart advances state, continue the paced-retry
  policy. *AC-C4.*
- **task-C-5** — Tests: throttling-streak → rate-limit classification (NOT abnormal, no
  fail-streak halt); paced-retry pacing/window (reset-time-paced vs bounded backoff;
  `OVERSEER_ALERT` fires past threshold per cq-1); landed-slice preservation across a paced
  restart; loop-guard escalates on identical reproduction and continues when state advances;
  **regression**: `EX_AUTH_FATAL` (incl. weekly cap) and ordinary `abnormal` halts fire
  unchanged. `make lint` + `make test` green. *AC-C7, AC-C6.*

**Intra-slice order:** C-1 → C-2 → C-3 → C-4 → C-5 (each builds on the classification hook).

## Risks for reviewers

1. **PR C is highest-risk.** The rate-limit classification must key **only** off the
   throttling-streak signature; a too-broad match would swallow genuine `abnormal` halts
   (AC-C6). Confirm `EX_AUTH_FATAL` and `abnormal` paths are provably untouched.
2. **PR C loop-guard** needs a concrete "identical failure at the same point" signature (error
   class + phase-progression marker). Weak → loops forever or escalates prematurely. Heavy tests
   both directions (AC-C7).
3. **PR C cq-1**: no hard ceiling means an unattended pipeline can sit paused for days on a weekly
   cap; the threshold `OVERSEER_ALERT` is the **only** operator signal — it must actually fire.
   Do not silently add a ceiling.
4. **PR D task-D-1 is a genuine gate**, not a formality: four of five anomaly types map only to
   the LLM classifier `action:{action}` path. A classifier-only mapping is still an emitter the
   skill surfaces — but reviewers must confirm the skill's alert-surfacing renders it; where
   nothing maps, it **must** be a HITL, not a delete.
5. **PR D task-D-2 must not over-delete**: Stuck Pipeline Rescue Steps 1-3 and the two
   `AskUserQuestion` render-on-alert flows **stay** (AC-D3/AC-D4). Only host-side detection
   triggers go.
6. **PR B `slice.closed` payload** must be distinguishable success vs failure at emit time
   (single event type + outcome field) — no second lookup to tell a completion from a failure.

**cq-1 — PR C: how should the windowed paced-retry bound itself when a cap wall persists?**

`OVERSEER_ALERT` once the wait crosses a threshold, so an attended operator is informed while
auto-recovery continues.* This plan adopts that verbatim in task-C-2 / task-C-4.

No new plan-phase decision arises. The only contingent decision — PR D, a deleted detector block
found with **no** overseer emitter — is deliberately **not** pre-registered; it is raised as a
HITL at point of discovery (task-D-1) carrying the specific block + evidence.
