# Plan: Teach agents to use directed BRC messaging for cross-agent coordination

## Summary

The `egg-orch message send` CLI already supports directed peer-to-peer coordination, but agents don't know when to use it — the BRC preamble only covers consensus primitives. This plan adds prompt-level guidance in `_build_brc_preamble` telling producers and reviewers to use `HANDOFF`/`QUESTION`/`STATUS` messages for role-boundary handoffs, blocking questions, and peer-affecting status updates (instead of burying requests in proposal text). It also fixes the CLI `--type` help text to mention `HANDOFF` for discoverability, adds a worked example to the concurrent-execution guide using the coder→tester handoff from issue-1707, and adds a prompt test.

**Risks / edge cases**: Prompt bloat — the BRC preamble is already long, so the new section must be tight and role-gated (producer-specific guidance for HANDOFFs on role-boundary blockers; reviewer-specific guidance for QUESTIONs to ambiguous producers). No runtime behavior changes — agents ignoring the new guidance fail open to today's behavior. Without #1717, directed messages still won't persist to PR history; landing this alone still captures real-time coordination value.

**Note to reviewers**: Proposal #1 of issue #1718 ("Add `egg-orch message send`") is already implemented at `sandbox/egg_lib/orch_cli.py:978` (registered at line 1777). This PR addresses only the remaining gap: prompt guidance and documentation. PR description should call this out explicitly.

## Implementation

### Phase 1: Implement

Prompt + CLI help + docs + test.

**Tasks**:
1. **[task-1-1]** In `orchestrator/routes/pipelines.py`, extend `_build_brc_preamble` (~line 5251) with a role-gated "Directed Coordination" section. For producers: when blocked by a role boundary (e.g., can't push test files) send `egg-orch message send --to <role> --type HANDOFF --subject "..." --body "..."`; when another producer's proposal is ambiguous, send `--type QUESTION` to that producer. For reviewers: send `QUESTION` when a proposal is ambiguous. For both: explicitly state that coordination requests belong in directed messages, NOT in proposal-body footnotes. Keep additions tight (~8–12 lines per role). Acceptance: preamble output for a producer role in `implement` phase contains both `egg-orch message send` and `HANDOFF`.
2. **[task-1-2]** In `sandbox/egg_lib/orch_cli.py` around line 1782, update the `msg_send --type` help text from `"Message type (PROGRESS, QUESTION, STATUS)"` to include `HANDOFF` (e.g., `"Message type (HANDOFF, QUESTION, STATUS, PROGRESS)"`). Acceptance: `egg-orch message send --help` includes `HANDOFF` in the `--type` listed values.
3. **[task-1-3]** In `docs/guides/concurrent-execution.md`, add a "Directed Coordination" subsection under "Sending Messages" (near line 113) showing the CLI form, the three canonical use cases (role-boundary HANDOFF, blocking QUESTION, peer-affecting STATUS), and a worked example based on the issue-1707 coder→tester handoff. Explicitly note that coordination requests belong in directed messages, not proposal bodies. Acceptance: guide contains a "Directed Coordination" heading, a CLI `egg-orch message send` example, and the coder→tester worked example.
4. **[task-1-4]** In `orchestrator/tests/test_pipeline_prompts.py`, add a test that calls `_build_brc_preamble` for a producer role (e.g., `coder` in `implement` phase) and asserts the output contains both the literal string `egg-orch message send` and `HANDOFF`. Also verify the reviewer path gets `QUESTION` guidance. Acceptance: new test passes and fails if task-1-1 is reverted.
