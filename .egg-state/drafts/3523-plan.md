# Plan: Review-quality overhaul — structured findings, verification ladder, risk router, shared-evidence prefix (#3523)

## Approach

Issue #3523 is a prescriptive operator directive with five changes to egg's multi-agent
review machinery. The refine analysis (`.egg-state/drafts/3523-analysis.md`, HITL-approved)
grounded every item in the live codebase; the architect's recommended DAG
(`.egg-state/agent-outputs/3523-architect-slices.yaml`) fixed the seam structure. This plan is
the **final task-level DAG** — the architect explicitly delegates final DAG, ordering, and PR
packaging to the task_planner — and conforms to the architect's structure while making it
**forest-valid** (the platform requires every slice to have at most ONE dependency parent; the
architect's recommendation listed multi-parent deps on S4/S6/S7 as logical, not stackable,
edges).

**Conformance to the architect, with two owner-level refinements:**

- Adopted verbatim: two file-disjoint **parallel roots** — S1 (`shared/prompts/*-criteria.md`,
  prompt-only) and S2 (the finding schema in `shared/egg_contracts/`); the **serial
  consensus_wrapper.py spine** (verdict rendering → tool-call cap → effort threading → prefix
  assembly all touch that one file and must serialize); the **distinct tool-call-cap slice**;
  and a **single tail docs slice**.
- Refinement 1 (architect pre-authorized: "task_planner MAY split into serial sub-slices"):
  the architect's one-slice risk router (config + gating + effort + stance) is split into
  **router core** (pure module + config, fully unit-tested, unwired) and **router wiring**
  (graph gating + effort + stance behind the flag). The one-slice version bundles ~5
  file-categories and mixes new-module-introduction with wiring into `review_graph.py` — a
  chokepoint every consumer calls — which the slice-sizing rule (hard NACK, #2809) discourages.
- Refinement 2 (forest-validity): every multi-parent dep in the architect's recommendation is
  reduced to its single stackable parent along the serial spine (the other listed deps are
  transitive ancestors), so the DAG is a valid forest: one independent root (S1) plus the
  S2→S3→…→S8 spine.

**Two non-negotiable cross-cutting requirements**, applied to every behavior-shifting slice:

1. **Staged `off → log → on` flag**, modeled exactly on `orchestrator/slice_green_gate.py`
   `green_gate_mode()`: env-resolved, an unknown/typo value fails safe to `off`, and `log` mode
   records the would-have-been behavior into the existing BRC artifacts without changing any
   real ACK/NACK/graph outcome. Pure prompt-text additions (S1) are additive and need no flag.
2. **Mirror Claude Code's built-in `/review` skill** (operator directive). Before writing any
   reviewer-prompt text or the router tier taxonomy, the implementer MUST fetch the verbatim
   reference: `gh issue view 3523 --repo jwbron/egg --comments` — comment
   `issuecomment-4898679999` (all four effort-level prompt bodies) and `issuecomment-4898686738`
   (a fully-assembled example). The tier ladder (low/medium/high/xhigh, caps 4/8/10/15), finder
   angles (A–E), 3-state verify, and finding shape are the shared vocabulary; do not invent one.

**Cost is a first-class success criterion** (operator directive): the risk router (S5–S6) must
default low-risk slices to the cheaper tiers rather than always running the full graph, and the
evidence prefix (S7) must record measured cache-hit rate and per-wave token cost in `log` mode —
a measured net cost reduction gates the flip to `on`.

**Out of scope (binding):** no eval/benchmark harness, no human-feedback learning loop.

code-side conditional in `_criteria.py`, not as prose in the criteria files — no later slice
edits any `shared/prompts/*-criteria.md` file S1 touches.

## Slice detail

### S1 — Reviewer method-angle procedures & verification ladder (prompt-only ROOT)
Items 3 and the prompt-level rules of item 2. Entirely `shared/prompts/*-criteria.md` edits
(documenter-owned) plus a ratchet test (tester). Zero-regret: no orchestrator change, no flag.
Adds the four named *how-to-look* procedures (including the deletion audit, which the file says
nothing about today) and the CONFIRMED/PLAUSIBLE/REFUTED ladder with symmetric evidence duties,
mirroring the `/review` skill. Independent root — nothing else edits these files.

### S2 — Versioned finding schema (additive contract ROOT)
Item 1a. New versioned `Finding` schema next to the other verdict contracts in
`shared/egg_contracts/`, boundary-validated like `attestation_schemas.py`. File-disjoint from
every other slice; parallel-capable with S1. Purely additive — S3 consumes it; nothing does yet,
so no behavior shifts and no flag.

### S3 — Server-side computed verdict from findings + convergence
Item 1b. Moves verdict computation across the determinism boundary: reviewers emit findings,
orchestrator code computes the edge verdict (any blocking ⇒ NACK; advisory-only ⇒ ACK routed
through the existing conditional-ACK obligation fields; empty ⇒ ACK). Mechanism-level dedup
merges same-cause findings from different lenses into one carrying N producers
(convergence-as-signal). Renders the producer-facing NACK reason from findings via
`consensus_wrapper.py` (spine head). Behind `EGG_REVIEW_FINDINGS_MODE` (`off→log→on`); the legacy
prose-NACK path stays until `on`; `log` diffs computed-vs-legacy without acting.

### S4 — Per-finding tool-call cap (item 2's wrapper half)
Item 2's non-prompt half: a configurable per-finding tool-call cap enforced in
`consensus_wrapper.py` (not the prompt) to bound the scratch-check experiments S1 permits. Reads
the S2 schema; serialises after S3 on `consensus_wrapper.py`. Kept a distinct slice for
reviewability per the architect. Rides `EGG_REVIEW_FINDINGS_MODE`; `log` records would-be cap
hits without enforcing.

### S5 — Deterministic risk router core (pure, unwired)
Item 4a. The per-repo path/glob risk config (`.egg/review-risk.yaml`, mirroring the
`phase-permissions.json` / `repositories.yaml` conventions) plus the deterministic
(plain-code, non-model) router as a standalone, fully unit-tested pure module — no wiring into
the review graph yet, so no behavior shifts. Encodes the HARD floor rules and the
security-lens-un-gatable invariant as pure logic. Tier taxonomy mirrors the `/review` ladder
(low/medium/high/xhigh, caps 4/8/10/15).

### S6 — Risk router wiring: lens gating + effort tiers + stance
Item 4b. Wires the S5 router into `review_graph.py`'s single graph-resolution chokepoint (so all
consumers see the gated graph consistently — no per-caller forking), into the existing `--effort`
plumbing (`agent_model_resolution.py` → `consensus_wrapper.build_event_pump_wrapped_command`), and
adds the optional precision/recall stance as ONE code-side conditional in `_criteria.py`. Floor
rules are HARD: no-match ⇒ full graph + loud warning; a floor tier guarantees a misrouted risky
slice still gets a real review; the security lens is structurally un-gatable on
auth/session/input-boundary paths. Behind `EGG_RISK_ROUTER` (`off→log→on`), `log`-first: records
the would-be graph/tier and per-wave cost, changes nothing.

### S7 — Shared-evidence prompt prefix (the cost bet)
Item 5. A new unprivileged evidence-gatherer role (read-only, no GitHub access, casts no verdict,
posts nothing — capabilities structurally absent in the registry) assembles a mechanically
path-ordered per-slice evidence pack. Reviewer prompts become
`[system prefix][evidence pack][one lens instruction]`, fanned out same-turn/same-model so the
prompt cache stays warm, extending the `routes/event_prompt/` cacheable-prefix discipline across
sibling reviewers. Hard rule: evidence, never conclusions. Independence guardrails: the tester
and any finding-verifier stay cold-start; Delphi redaction is unchanged. Behind
`EGG_REVIEW_EVIDENCE_PREFIX`; `log` records cache-hit rate and per-wave cost, and a measured net
cost reduction is required before flipping to `on`.

### S8 — Documentation
Documents the whole overhaul: the finding schema and computed verdict + convergence, the
verification ladder + companion rules + scratch checks + tool-call cap, the four method-angle
procedures, the risk router + config + floor rules, and the evidence-prefix design +
independence guardrails + cost gate. Cross-references the `/review` skill as the reference design
and the `off→log→on` rollout. Tail slice; documenter-owned, disjoint from every feature slice.

## Test strategy

- **S1:** a ratchet test asserts each criteria file contains the named procedures, the three
  ladder states, and both companion rules — locks the prompt content against regression.
- **S2, S3, S5:** pure-function unit tests (schema validation, verdict computation, router
  routing) — the determinism boundary is exactly what must be nailed down.
- **S3, S4, S6, S7:** each behavior-shifting slice gets a `log`-mode parity test proving `log`
  changes no real ACK/NACK/graph outcome versus the legacy path, and a flag-typo-fails-to-`off`
  test. S7 additionally asserts a byte-identical prefix and cold-start tester/verifier.
- Every cumulative slice tip stays independently green (per-slice green gate).

## Risks & mitigations

- **Determinism-boundary regression (S3):** verdict is a pure, unit-tested function of findings;
  `log` mode diffs computed-vs-legacy without acting; the legacy path is retained until `on`.
- **Router silently under-reviewing (S6):** no-match ⇒ full graph + loud warning; floor tier;
  security lens structurally un-gatable on auth/input-boundary paths; `log`-first.
- **Anchoring via the shared pack (S7):** hard "evidence, never conclusions" rule, mechanical
  path ordering, cold-start tester/verifier, unchanged Delphi redaction.
- **Prompt-cache fragility (S7):** assemble the prefix deterministically byte-identically;
  measure real hit-rate in `log` before `on`.
- **Oversized-slice NACK:** item 1 split (schema S2 vs verdict S3), tool-call cap isolated (S4),
  and the router split (core S5 vs wiring S6) keep each slice within one reviewable concern.
