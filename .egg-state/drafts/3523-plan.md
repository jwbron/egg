# Plan: Review-quality overhaul — structured findings, verification ladder, risk router, shared-evidence prefix (#3523)

## Approach

Issue #3523 is a prescriptive operator directive with five changes to egg's multi-agent
review machinery. The refine analysis (`.egg-state/drafts/3523-analysis.md`, HITL-approved)
grounded every item in the live codebase and fixed the seams, sequencing, and acceptance
direction; this plan cuts that into a **linear slice chain** that honors the issue's binding
sequencing and the platform's hard slice rules (forest/overlap/test-co-location/staged-flag).

The chain is deliberately serial because the later slices edit orchestrator files the earlier
slices also touch (`consensus_wrapper.py`, `review_graph.py`, the reviewer-prompt assembly and
`shared/prompts/*-criteria.md`). Serializing along the dependency edges is the only way to
satisfy the HARD file-overlap rule (two slices touching the same file must sit on one
dependency chain) and matches the issue's own ordering: prompt-only rules first, then the
finding-schema structural investment, then the computed verdict, then the risk router, then the
cost-bet evidence prefix.

**Two non-negotiable cross-cutting requirements**, applied to every behavior-shifting slice:

1. **Staged `off → log → on` flag**, modeled exactly on `orchestrator/slice_green_gate.py`
   `green_gate_mode()`: env-resolved, an unknown/typo value fails safe to `off`, and `log` mode
   records the would-have-been behavior into the existing BRC artifacts without changing any
   real ACK/NACK outcome. Pure prompt-text additions (slice 1) are additive and need no flag.
2. **Mirror Claude Code's built-in `/review` skill** (operator directive). Before writing any
   reviewer-prompt text or router taxonomy, the implementer MUST fetch the verbatim reference
   posted on the issue:
   `gh issue view 3523 --repo jwbron/egg --comments` — comment `issuecomment-4898679999` (all
   four effort-level prompt bodies) and `issuecomment-4898686738` (a fully-assembled example).
   The tier ladder (low/medium/high/xhigh, caps 4/8/10/15), finder angles (A–E), 3-state verify,
   and finding shape are the shared vocabulary; do not invent a bespoke one.

**Cost is a first-class success criterion** (operator directive): the risk router (slices 4–5)
must default low-risk slices to the cheaper tiers rather than always running the full graph, and
the evidence prefix (slice 6) must record measured cache-hit rate and per-wave token cost in
`log` mode — a measured net cost reduction gates the flip to `on`.

**Out of scope (binding):** no eval/benchmark harness, no human-feedback learning loop.

## Slice detail

### Slice 1 — Reviewer method-angle procedures & verification ladder (prompt-only)
Items 3 and the prompt-level rules of item 2. Entirely `shared/prompts/*-criteria.md` edits
(documenter-owned) plus a ratchet test. Zero-regret: no orchestrator change, no flag. Adds the
named *how-to-look* search procedures and the CONFIRMED/PLAUSIBLE/REFUTED ladder with symmetric
evidence duties, mirroring the `/review` skill. Sequenced first per the issue.

### Slice 2 — Versioned finding schema (additive contract)
Item 1a. New versioned `Finding` schema next to the other verdict contracts in
`shared/egg_contracts/`, boundary-validated like `attestation_schemas.py`. Purely additive — no
consumer rewires the verdict path yet, so no behavior shifts and no flag. Splitting the schema
introduction (new API) away from the verdict-computation change (slice 3) honors the
"don't bundle new-API-introduction with behavior change" sizing rule.

### Slice 3 — Computed edge verdict from findings + convergence + tool-call cap
Item 1b plus item 2's wrapper-level per-finding tool-call cap (which the analysis places here
because it couples to the finding boundary). Moves verdict computation server-side: reviewers
emit findings, orchestrator code computes the edge verdict (any blocking ⇒ NACK; advisory-only ⇒
conditional-ACK; empty ⇒ ACK). Mechanism-level dedup merges same-cause findings from different
lenses into one carrying N producers (convergence-as-signal). Behavior-shifting ⇒ behind
`EGG_REVIEW_FINDINGS_MODE` (`off→log→on`); the legacy prose-NACK path stays until `on`; `log`
mode diffs computed-vs-legacy verdict without acting.

### Slice 4 — Deterministic risk router core (pure, unwired)
Item 4a. The per-repo path/glob risk config plus the deterministic (plain-code, non-model)
router as a standalone, fully unit-tested pure module — no wiring into the review graph yet, so
no behavior shifts. Isolating the pure core makes it trivially testable and keeps the
behavior-shifting wiring (slice 5) small.

### Slice 5 — Risk router wiring: lens gating + effort tiers + stance
Item 4b. Wires the slice-4 router into `review_graph.py` edge selection and the existing
`--effort` plumbing, and adds the optional precision/recall stance conditional. Floor rules are
HARD: a slice matching no config runs the full graph with a loud warning, a floor tier
guarantees a misrouted risky slice still gets a real review, and the security lens is
structurally un-gatable on auth/session/input-boundary paths. Behind `EGG_RISK_ROUTER`
(`off→log→on`), `log`-first: records the would-be graph/tier and per-wave cost, changes nothing.

### Slice 6 — Shared-evidence prompt prefix (the cost bet)
Item 5. A read-only, unprivileged evidence gatherer assembles a mechanically-ordered
(path-order) evidence pack; reviewer prompts are assembled as
`[system prefix][evidence pack][one lens instruction]` and fanned out same-turn/same-model so
the prompt cache stays warm. Hard rule: evidence, never conclusions. Independence guardrails:
the tester and any finding-verifier stay cold-start; Delphi redaction is unchanged. Behind
`EGG_REVIEW_EVIDENCE_PREFIX`; `log` mode records cache-hit rate and per-wave cost, and a
measured net cost reduction is required before flipping to `on`.

## Test strategy

- **Slice 1:** a ratchet test asserts each criteria file contains the named procedures, the
  three ladder states, and both companion rules — locks the prompt content against regression.
- **Slices 2, 3, 4:** pure-function unit tests (schema validation, verdict computation, router
  routing) — the determinism boundary is exactly what must be nailed down.
- **Slices 3, 5, 6:** each behavior-shifting slice gets a `log`-mode test proving `log` changes
  no real ACK/NACK/graph outcome versus the legacy path, and a flag-typo-fails-to-`off` test.
- Every cumulative slice tip stays independently green (per-slice green gate).

## Risks & mitigations

- **Determinism-boundary regression (slice 3):** verdict is a pure, unit-tested function of
  findings; `log` mode diffs computed-vs-legacy without acting; legacy path retained until `on`.
- **Router silently under-reviewing (slice 5):** no-match ⇒ full graph + loud warning; floor
  tier; security lens structurally un-gatable on auth/input-boundary paths; `log`-first.
- **Anchoring via the shared pack (slice 6):** hard "evidence, never conclusions" rule,
  mechanical path ordering, cold-start tester/verifier, unchanged Delphi redaction.
- **Prompt-cache fragility (slice 6):** assemble the prefix deterministically byte-identically;
  measure real hit-rate in `log` before `on`.
