# Plan: Orchestrator-driven on-demand agent spawning — lift the event pump out of the pod so idle agents don't exist

> Issue: #3023 | Phase: plan | Refine artifact: `.egg-state/drafts/3023-analysis.md`

## Goal

Invert today's lifecycle from "phase-start spawn-all + long-lived in-pod event-pump bash loop" to
"orchestrator-owned event loop + per-event one-shot pod spawn that exits when the agent finishes".

The analysis (cq-1..cq-6 resolutions, refine artifact §"Recommended Approach") settled on **Option A**:

- Orchestrator's existing per-phase run loop in `routes/pipelines.py` adds a per-role inner tick that
  calls `_derive_next_action(tracker, role)` in-process (no HTTP round-trip).
- On `action ∈ {propose, ack, nack, confirm}`, the orchestrator composes the per-event prompt by
  calling `compose_event_prompt` in-process, then spawns a one-shot k8s Job whose container command
  is `python3 -m egg_agent --model X --max-turns N` with the composed prompt on stdin.
- The per-`(pipeline_id, role)` worktree PVC is created at phase start and reused across every
  spawn; the gateway session is created once per `(pipeline_id, role)` at phase start and refreshed
  by an orchestrator-side keep-alive (cq-2).
- The idle-budget overseer alert moves from the wrapper to the orchestrator and becomes a
  phase-level "no spawns for X minutes" signal (cq-3) at the existing 30-minute threshold
  (feedback Q5: do not retune).
- `orchestrator/consensus_wrapper.py` is deleted entirely (cq-5).
- Rollout is big-bang, rollback-by-git-revert (cq-4).
- Overseer agents are out of scope for this PR; a follow-up issue is filed for the unification (cq-6).

The work decomposes into **three dependent slices**, all landing in a single PR (cq-4 big-bang):

1. **Slice 1 — Orchestrator-side phase-level idle-budget alert.** Move the
   `stuck-phase-transition` anomaly tag emitter from the in-pod wrapper to an orchestrator
   timer. Lands first so a real signal exists before pods stop existing. No behaviour change
   for the in-pod wrapper yet — both emitters can coexist during the slice's burn-in within the
   PR.
2. **Slice 2 — On-demand spawner + per-`(pipeline_id, role)` worktree-PVC and gateway-session reuse.**
   The new `orchestrator/on_demand_spawner.py` module + the per-phase tick that drives it via
   `_derive_next_action` + `compose_event_prompt` in-process. Worktree PVC and gateway session are
   created once per `(pipeline_id, role)` and reused across every spawn for that role.
3. **Slice 3 — `consensus_wrapper.py` retirement + entrypoint simplification.** Pod entrypoint
   becomes `python3 -m egg_agent --model X --max-turns N` with the composed prompt on stdin.
   `orchestrator/consensus_wrapper.py`, `build_consensus_wrapped_command`, and
   `build_event_pump_wrapped_command` are deleted; their call sites in
   `concurrent_executor.py` and `routes/pipelines.py` shift to the on-demand path.

## Slice 1 — Orchestrator-side phase-level idle-budget alert

**Goal**: Move the 30-min `stuck-phase-transition` OVERSEER_ALERT from
`consensus_wrapper.py:531-549` (per-role, in-pod) to an orchestrator-side per-phase timer
(cq-3), keeping the threshold (feedback Q5). This lands first so a signal exists before any
pods stop existing in slice 2.

**Dependencies**: none (in-process orchestrator change only).

### Tasks

- **[TASK-1-1]** Create `orchestrator/phase_idle_budget.py` with a `PhaseIdleBudgetTimer`
  class. It owns:
  - A `DEFAULT_PHASE_IDLE_BUDGET_MIN = 30` constant (parity with
    `consensus_wrapper.py:59`'s `EGG_BRC_IDLE_BUDGET_MIN`, feedback Q5).
  - State `(pipeline_id, phase, last_spawn_at, last_alert_at)`.
  - A `record_spawn(pipeline_id, phase)` API that resets `last_spawn_at`.
  - A `check(now)` API that emits `stuck-phase-transition` once at the 1× threshold and once
    at the 2× threshold (matching today's wrapper semantics at `consensus_wrapper.py:531-549`),
    via the `mcp__progress__overseer_alert`-equivalent direct orchestrator entry point used by
    `orchestrator/overseer/monitor.py`.
  - Idempotent re-fire (does not re-emit while still inside the same threshold bucket).
  - **Acceptance**: file exists; class exposes `record_spawn`, `check`, `reset`; constant equals 30;
    unit tests cover (a) 0 idle minutes → no emit, (b) 30 idle minutes → 1× emit once,
    (c) 60 idle minutes → 2× emit once (1× not re-emitted), (d) `record_spawn` resets, (e) idempotent
    across multiple `check(now)` calls inside the same bucket.
  - **Files affected**: `orchestrator/phase_idle_budget.py` (new),
    `orchestrator/tests/test_phase_idle_budget.py` (new).

- **[TASK-1-2]** Wire `PhaseIdleBudgetTimer.check(now)` into the orchestrator's existing
  per-phase tick in `orchestrator/routes/pipelines.py` (the run loop that already polls consensus
  for phase-completion). Each tick:
  1. Calls `PhaseIdleBudgetTimer.check(now=time.monotonic())` for the active phase.
  2. Surfaces a structured log line `phase_idle_budget_tick(pipeline_id, phase, idle_minutes)`
     once per emitted alert.
  - **Acceptance**: tick invokes `check` exactly once per loop iteration; test asserts that
    after the wall-clock fixture advances past 30 minutes with no `record_spawn` calls, the
    overseer alert handler is invoked exactly once with `anomaly="stuck-phase-transition"`.
  - **Files affected**: `orchestrator/routes/pipelines.py`,
    `orchestrator/tests/test_pipelines_phase_idle_budget.py` (new).

- **[TASK-1-3]** Coexistence guard: while the in-pod wrapper still exists (it does, until slice 3),
  the orchestrator-side timer is the authoritative emitter and the wrapper's
  `consensus_wrapper.py:531-549` emitter is **silenced** behind a code-path branch keyed on
  "an orchestrator-side timer is running" — detected by the wrapper at startup via a new
  `EGG_PHASE_IDLE_BUDGET_OWNER=orchestrator` env var injected by
  `concurrent_executor._spawn_agent`. In this slice we **inject the env var unconditionally**;
  slice 3 deletes the wrapper-side emitter outright.
  - **Acceptance**: `EGG_PHASE_IDLE_BUDGET_OWNER=orchestrator` appears in the spawn env emitted
    by `_spawn_agent` for every role; wrapper unit test confirms the alert subshell short-circuits
    when the var is set; the alert is emitted exactly once per phase per threshold (no double-emit).
  - **Files affected**: `orchestrator/concurrent_executor.py`,
    `orchestrator/consensus_wrapper.py:531-549` (gated short-circuit; full deletion deferred to
    task-3-1), `orchestrator/tests/test_consensus_wrapper.py`.

## Slice 2 — On-demand spawner + worktree-PVC and gateway-session reuse

**Goal**: Drive one pod spawn per actionable event (cq-1, feedback Q4). Reuse the per-role
worktree PVC and gateway session across every spawn for that role (cq-2).

**Dependencies**: slice 1 (so an idle-budget alert exists during burn-in).

### Tasks

- **[TASK-2-1]** Expose `_derive_next_action` from `orchestrator/routes/consensus.py:280-406` as a
  module-level callable that the orchestrator run loop can call in-process. Today it is a
  module-private function reached via the HTTP route. Add a thin public `derive_next_action(...)`
  alias that takes a `tracker` + `role` and returns the same `(action, event_payload, reason)`
  tuple. Keep the route handler calling the alias so behaviour stays byte-identical for external
  callers (the in-pod wrapper today + any future caller during burn-in).
  - **Acceptance**: function is importable as `from orchestrator.routes.consensus import
    derive_next_action`; existing route tests pass without change; new unit test asserts in-process
    + HTTP route return identical results for the same tracker snapshot.
  - **Files affected**: `orchestrator/routes/consensus.py`,
    `orchestrator/tests/test_consensus_next_action.py`.

- **[TASK-2-2]** Create `orchestrator/on_demand_spawner.py` with an `OnDemandSpawner` class. It owns:
  - A reference to the `KubernetesSpawner`, the `PhaseIdleBudgetTimer` (slice 1), and the
    `OrchestratorSessionKeepAlive` (task-2-6).
  - A `tick(pipeline_id, phase, roles)` API that, for each role in `roles`, calls
    `derive_next_action(tracker, role)`:
    - `wait` → no spawn; do nothing.
    - `complete` → no spawn; the orchestrator's phase-completion check (already exists) handles
      transition.
    - `confirm` → spawn one pod with the same composed prompt path as `propose/ack/nack` (the
      agent calls `mcp__brc__confirm` inside). No special-case path.
    - `propose | ack | nack` → call `compose_event_prompt(role, event_payload, ...)` in-process,
      then call `OnDemandSpawner.spawn_event(role, prompt, model_decision)` (task-2-4).
  - A `record_phase_start(pipeline_id, phase, roles, slice_id?)` API that pre-warms the per-role
    worktree PVC + gateway session for every role in `roles`. Called once per phase before the
    first tick.
  - A `record_phase_end(pipeline_id, phase)` API that tears down the per-role worktree PVC
    cleanup pointers + the gateway session keep-alive registration. PVC garbage collection still
    uses the existing kubernetes_spawner lifecycle (not touched here).
  - **Acceptance**: class exists with the listed APIs; unit tests cover (a) wait → no spawn,
    (b) propose → spawn called with role + composed prompt + correct model decision, (c) confirm
    → spawn called with same path, (d) record_phase_start pre-warms PVC + session, (e) re-entry
    of tick after a spawn does not double-spawn while a spawn is in flight, (f) `record_phase_end`
    drops the keep-alive entry.
  - **Files affected**: `orchestrator/on_demand_spawner.py` (new),
    `orchestrator/tests/test_on_demand_spawner.py` (new).

- **[TASK-2-3]** Adapt `compose_event_prompt` for in-process orchestrator use. Today the wrapper
  reaches it through `orchestrator/routes/event_prompt.py` via a subprocess shell hop
  (`consensus_wrapper.py:400-449`). The function is already pure (`event_prompt.py:337-447`) — the
  task is to add a small adapter that resolves its disk-side inputs (`memory_excerpt`,
  `git_log_delta`) from the orchestrator's view of the worktree PVC instead of the in-pod path.
  Inputs unchanged; signature unchanged; only the call site that resolves `repo_path`,
  `worktree_path`, and `base_branch` moves into the spawner.
  - **Acceptance**: `compose_event_prompt(role, event_payload, ..., repo_path=worktree_pvc_path)`
    returns the same string the in-pod wrapper would have rendered for the same event; existing
    `test_compose_event_prompt.py` tests pass unchanged; new integration test asserts byte-identity
    against a wrapper-rendered fixture for one `(role, event_payload)` pair.
  - **Files affected**: `orchestrator/routes/event_prompt.py` (adapter docstring + parameter
    plumbing only; no logic change), `orchestrator/on_demand_spawner.py` (consumer),
    `orchestrator/tests/test_compose_event_prompt.py`.

- **[TASK-2-4]** Refactor `ConcurrentExecutor._spawn_agent` so it can be called from the
  `OnDemandSpawner` per-event path with a precomposed prompt. Today it composes the prompt + the
  wrapper command in one shot (`concurrent_executor.py:445-524`); we want the on-demand path to
  hand it the prompt directly and skip the wrapper command builder. Add a new public
  `spawn_event(role, prompt_text, model_decision)` entry that:
  1. Receives an already-composed prompt and a `resolve_agent_model` decision.
  2. Builds the one-shot command `python3 -m egg_agent --model {alias} --max-turns {N}` (no
     wrapper; the prompt is piped on stdin via the `command` arg already supported by
     `spawn_agent_job`).
  3. Calls `self.spawn_fn` (factory returned by `KubernetesSpawner.create_concurrent_spawn_fn()`
     today; task-2-5 adds a sibling factory).
  4. Does NOT touch the consensus tracker (matches `spawn_specific_roles` semantics from #1879 —
     the tracker has already registered the role at `spawn_all` time during phase-start pre-warm).
  - **Acceptance**: new entry exists; unit test asserts it builds the `python3 -m egg_agent`
    command (no `bash -c "..."` wrapper bytes), forwards the model decision into the spawn
    env, and does not call `build_consensus_wrapped_command`.
  - **Files affected**: `orchestrator/concurrent_executor.py`,
    `orchestrator/tests/test_concurrent_executor.py`.

- **[TASK-2-5]** Extend `KubernetesSpawner` to support per-event spawns that reuse a pre-existing
  worktree PVC. Today `spawn_agent_job` already mounts the per-role PVC via the per-role mount
  pattern (`kubernetes_spawner.py`, feedback Q3). The task is:
  1. Add a sibling factory `create_on_demand_spawn_fn()` (mirror of
     `create_concurrent_spawn_fn` at `kubernetes_spawner.py:1772-1846`) that returns a callable
     suitable for `OnDemandSpawner.spawn_event`. The difference vs. the concurrent factory is
     that the per-event factory does NOT call `_register_worktree_lifecycle` (PVC already exists
     from phase-start pre-warm) and does NOT serialize spawns through the per-role pool — the
     orchestrator drives serialization at the tick level.
  2. Extend the spawn env composition so that on every per-event spawn, the env contains:
     - `EGG_SESSION_TOKEN` from the orchestrator-held session (task-2-6).
     - `EGG_PHASE_IDLE_BUDGET_OWNER=orchestrator` (task-1-3 already injects unconditionally).
     - `EGG_ON_DEMAND_SPAWN=1` (informational, surfaced in agent-side logs).
     - All existing `_PROTECTED_ENV_KEYS` values intact.
  3. Capture per-spawn stdout/stderr (task-2-7).
  - **Acceptance**: new factory exists; unit test asserts the returned callable spawns a Job with
    `command=["python3","-m","egg_agent","--model","<alias>","--max-turns","<N>"]` (no
    `bash -c`), the per-role PVC mount is present, and the env contains every protected key
    + the new three.
  - **Files affected**: `orchestrator/kubernetes_spawner.py`,
    `orchestrator/tests/test_kubernetes_spawner.py`.

- **[TASK-2-6]** Create `orchestrator/session_keepalive.py` with an
  `OrchestratorSessionKeepAlive` class (cq-2). It owns:
  - A `{(pipeline_id, role): SessionRecord}` map where `SessionRecord` = `(token, created_at,
    last_validated_at, idle_timeout_minutes)`.
  - A `register(pipeline_id, role, token, idle_timeout_minutes)` API that adds a record.
  - A `refresh_all(now)` API that calls the gateway's `validate_session(token)` (the same call
    the wrapper's heartbeat made — see `consensus_wrapper.py:188-234`) for any record whose
    `(now - last_validated_at)` exceeds `idle_timeout_minutes - 5` (5-minute headroom).
  - An `unregister(pipeline_id, role)` API called by `OnDemandSpawner.record_phase_end`.
  - The orchestrator's per-phase tick calls `refresh_all(now)` once per iteration alongside the
    idle-budget timer check (task-1-2 is the parallel hook).
  - **Acceptance**: class exists with the listed APIs; unit tests cover (a) refresh emits a
    validate call for stale records only, (b) unregister drops the entry, (c) the validate call
    targets the gateway's `validate_session` endpoint with the recorded token.
  - **Files affected**: `orchestrator/session_keepalive.py` (new),
    `orchestrator/tests/test_session_keepalive.py` (new),
    `orchestrator/routes/pipelines.py` (tick hook).

- **[TASK-2-7]** Per-spawn pod-log capture (feedback Q2). Every per-event spawn writes its
  stdout/stderr to `.egg-state/agent-outputs/<role>/spawn-<event_index>.log` on the per-role
  worktree PVC. Implementation reuses today's per-container log capture mounted by
  `kubernetes_spawner.py`; the on-demand spawner increments a per-role `event_index` counter and

  - **Acceptance**: a successful per-event spawn produces a `spawn-<N>.log` file in the per-role
    output dir; index increments across consecutive spawns; the file survives pod exit (PVC,
    not pod ephemeral).
  - **Files affected**: `orchestrator/on_demand_spawner.py`,
    `orchestrator/kubernetes_spawner.py`,
    `orchestrator/tests/test_on_demand_spawn_logs.py` (new).

- **[TASK-2-8]** Wire the orchestrator's per-phase tick to drive `OnDemandSpawner.tick(...)`.
  Today the tick polls consensus state for phase-completion; the task adds a sibling call to the
  on-demand spawner ahead of the completion check. Once this task lands, the orchestrator is
  actively spawning per-event pods alongside the long-lived wrapper pods (the wrapper still spawns

  and are made mutually exclusive in slice 3.
  - **Acceptance**: the tick calls `OnDemandSpawner.tick(pipeline_id, phase, roles)` exactly once

  - **Files affected**: `orchestrator/routes/pipelines.py`,

## Risk recap

The risk_analyst's artifact (parallel to this plan) is the authoritative risk register; the
items below are the high-level callouts this task breakdown anticipates:

- **R1 — orchestrator hot path regression.** Slice 2 touches the per-phase tick in
  `orchestrator/routes/pipelines.py`. A bug here affects every pipeline. Mitigated by:
  (a) the new spawner is a separate module, (b) coexistence with the long-lived wrapper inside
  slice 2 until slice 3 deletes the wrapper, (c) the cq-4 revert path is git-clean.
- **R2 — gateway-session lifecycle move.** The session keep-alive moves from a 30-second in-pod
  heartbeat to an orchestrator-driven validate call. Mitigated by: (a) the 60-minute idle timeout
  is unchanged, (b) the keep-alive cadence is configured to validate at `idle_timeout_minutes - 5`
  (matching the wrapper's effective 30-second cadence in safety margin), (c) the gateway-side
  `validate_session` endpoint is unchanged.
- **R3 — prefix cache hit-rate regression.** A wrong-shaped composed prompt would cold-cache every
  spawn. Mitigated by: (a) `compose_event_prompt` is unchanged (task-2-3 is plumbing-only),
  (b) the byte-identity integration test in task-2-3 asserts cache-key-stable output.
- **R4 — silent loss of the idle-budget alert during burn-in.** Slice 1 deliberately makes the
  orchestrator the authoritative emitter and short-circuits the wrapper emitter — but a bug in
  the short-circuit gate (task-1-3) could double-emit or silence both. Mitigated by: explicit
  unit + integration assertions on exactly-once emit per threshold per phase.
