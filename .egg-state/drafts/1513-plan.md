# Plan: Add worktree path mapping to gateway contract API

## Summary

Add worktree path mapping to the gateway's contract API endpoints, following the established pattern used by git endpoints. The contract CLI also needs to send `container_id` so the gateway knows which worktree to resolve. Interactive sessions (no `container_id`) continue to work unchanged since `map_container_path_to_worktree` returns the original path when no container ID is provided.

**Risks / edge cases**: None identified — the `map_container_path_to_worktree` function already handles the no-container-id case (interactive sessions) and non-standard paths gracefully. The git endpoints have been using this pattern successfully.

## Implementation

### Phase 1: Implement

Add worktree path mapping to contract API endpoints and update the CLI to send container_id.

**Tasks**:
1. **[task-1-1]** In `gateway/contract_api.py`, modify `get_repo_path_from_request()` to also extract `container_id` from the request (query param for GET via `request.args.get("container_id")`, body for POST via `data.get("container_id")`) or fall back to `g.session.container_id` if available. Return it as part of the tuple alongside the path. Acceptance: function returns `(path, error, container_id)` tuple.
2. **[task-1-2]** In `gateway/contract_api.py`, update `get_contract()`, `mutate_contract()`, and `check_contract_exists()` to call `map_container_path_to_worktree(str(repo_path), container_id, "contract")` (imported from `gateway.gateway`) on the resolved path before passing it to contract loader functions. Handle `None` returns with `make_worktree_not_found_error(container_id)` (imported from `gateway.gateway`). Acceptance: contract operations use the worktree-mapped path when container_id is present.
3. **[task-1-3]** In `sandbox/egg_lib/contract_cli.py`, add a `get_container_id()` helper that returns `os.environ.get("CONTAINER_ID", "")`, matching the pattern in `sandbox/scripts/git:329`. Update GET requests to append `container_id` as a query parameter. Update POST request data dicts to include `container_id`. Acceptance: all gateway requests from egg-contract include container_id when the env var is set.
4. **[task-1-4]** Add tests in `gateway/tests/test_contract_api.py` covering: (a) contract GET with `container_id` query param maps repo_path to worktree path, (b) contract POST (mutate) with `container_id` in body maps path, (c) contract exists check with `container_id` maps path, (d) requests without `container_id` use original path unchanged, (e) when `container_id` is provided but worktree doesn't exist, returns appropriate error. Acceptance: all new tests pass.
