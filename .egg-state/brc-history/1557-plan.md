The architect's ad-9 explicitly flagged this ("Single disjunctive JQL of the form `parent = <K> OR \"Epic Link\" = <K>` returns HTTP 400 when one custom field is missing on the searched project. The result of shipping single-OR: reassess detection silently downgrades to fresh-path on any team-managed project (every pre-existing child becomes a candidate for re-creation → duplicate child tickets), and the existing-children sweep returns an empty list (in-flight gate never fires; Won't-Do batch is empty). **Fix**: in both TASK-1-3 and TASK-1-12, replace the single-OR query with two separate JQL queries — query 1: `parent = "<KEY>"`; query 2 (skipped as a tautology if `JiraPolicy.epic_link_field == "parent"` per the existing per-site config at gateway/jira_policy.py:163-170): `"Epic Link" = "<KEY>"` (or `"<configured field>" = "<KEY>"` to match the per-project hierarchy config from TASK-1-4) — and merge the results, tolerating per-query HTTP 400. Update the acceptance criteria on both tasks to assert both query shapes are issued and 400 on either query alone does not fail the whole sweep. This is the architect's ad-9 verbatim.
